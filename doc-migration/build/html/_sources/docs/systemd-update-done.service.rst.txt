systemd-update-done.service(8)
==============================

Name
####

systemd-update-done.service, systemd-update-done — Mark

Synopsis
########

:code:`systemd-update-done.service`

:code:`/usr/lib/systemd/systemd-update-done`

Description
###########

:code:`systemd-update-done.service` is a service that is invoked as part of the first boot after the vendor operating system resources in :code:`/usr/` have been updated. This is useful to implement offline updates of :code:`/usr/` which might require updates to :code:`/etc/` or :code:`/var/` on the following boot.

:code:`systemd-update-done.service` updates the file modification time (mtime) stored in and "on" the files :code:`/etc/.updated` and :code:`/var/.updated` to the modification time of the :code:`/usr/` directory, unless the stamp files are already newer. (The timestamp is stored as the mtime field on the file, but also *in* the file to support filesystems that do not store full timestamp precision.) the file to support filesystems that do not store full timestamp precision.)

Services that shall run after offline upgrades of :code:`/usr/` should order themselves before :code:`systemd-update-done.service`, and use the :code:`ConditionNeedsUpdate=` (see :ref:`systemd.unit(5)`) condition to make sure to run when :code:`/etc/` or :code:`/var/` are older than :code:`/usr/` according to the modification times of the files described above. This requires that updates to :code:`/usr/` are always followed by an update of the modification time of :code:`/usr/`, for example by invoking :man-pages:`touch(1)` on it.

Note that if the :code:`systemd.condition_needs_update=` kernel command line option is used it overrides the :code:`ConditionNeedsUpdate=` unit condition checks. In that case :code:`systemd-update-done.service` will not reset the condition state until a follow-up reboot where the kernel switch is not specified anymore.

Options
#######

The following options are understood:

.. systemd:option:: --root=root

   Takes a directory path as an argument. The program will operate on paths below the specified root directory.
