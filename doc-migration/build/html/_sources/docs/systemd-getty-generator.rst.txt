systemd-getty-generator(8)
==========================

Name
####

systemd-getty-generator — Generator for enabling getty instances on the console

Synopsis
########

:code:`/usr/lib/systemd/system-generators/systemd-getty-generator`

Description
###########

:code:`systemd-getty-generator` is a generator that automatically instantiates :code:`serial-getty@.service` on the kernel consoles, if they can function as ttys and are not provided by the virtual console subsystem. It will also instantiate :code:`serial-getty@.service` instances for virtualizer consoles, if execution in a virtualized environment is detected. If execution in a container environment is detected, it will instead enable :code:`console-getty.service` for :code:`/dev/console`, and :code:`container-getty@.service` instances for additional container pseudo TTYs as requested by the container manager (see `:code:`Container Interface` <https://systemd.io/CONTAINER_INTERFACE>`_). This should ensure that the user is shown a login prompt at the right place, regardless of which environment the system is started in. For example, it is sufficient to redirect the kernel console with a kernel command line argument such as :code:`console=` to get both kernel messages and a getty prompt on a serial TTY. See `The kernel's command-line parameters <https://docs.kernel.org/admin-guide/kernel-parameters.html>`_ for more information on the :code:`console=` kernel parameter.

:code:`systemd-getty-generator` implements :ref:`systemd.generator(7)`.

Further information about configuration of gettys can be found in `systemd for Administrators, Part XVI: Gettys on Serial Consoles (and Elsewhere) <https://0pointer.de/blog/projects/serial-console.html>`_.

Kernel Command Line
###################

:code:`systemd-getty-generator` understands the following :man-pages:`kernel-command-line(7)` parameters:

.. systemd:option:: systemd.getty_auto=
   :group: kernel-commandline-options

   This kernel command line option may be used to control the execution mode of the generator. Takes an optional boolean argument. Since v258, this also takes comma-separated list of special values: "credential", "container", "console", and "builtin".

   When "credential" is specified, the two credentials :systemd:var:`getty.ttys.serial` and :systemd:var:`getty.ttys.container` will be parsed. See System Credentials section below for more details.

   When "container" is specified, :code:`console-getty.service` and :code:`container-getty@.service` will be enabled when the system is running in a container. This option will be ignored when the system is not in a container.

   When "console" is specified, :code:`serial-getty@.service` for active kernel consoles will be enabled. This option will be ignored when the system is running in a container.

   When "builtins" is specified, :code:`serial-getty@.service` for available virtualizer consoles will be enabled. This option will be ignored when the system is running in a container.

   When yes, the above four options will be enabled. When no, all options are disabled and no service will be enabled. When the kernel command line option is specified without an argument, defaults to yes. The generator is enabled by default, and a false value may be used to disable it.

   .. versionadded:: 250

Environment
###########

.. systemd:var:: $SYSTEMD_GETTY_AUTO
   :group: environment-variables

   This environment variable may be used to control the execution mode of the generator. Takes the same value as :systemd:var:`systemd.getty_auto=` kernel command line option.

   .. versionadded:: 250

System Credentials
##################

.. systemd:option:: getty.auto
   :group: system-credentials

   The system credential may be used to control the execution mode of the generator. Takes the same value as :systemd:var:`systemd.getty_auto=` kernel command line option.

   .. versionadded:: 258

.. systemd:option:: getty.ttys.serial, getty.ttys.container
   :group: system-credentials

   These system credentials may be used to spawn additional login prompts on selected TTYs. The two credentials should contain a newline-separated list of TTY names to spawn instances of :code:`serial-getty@.service` (in case of :systemd:var:`getty.ttys.serial`) and :code:`container-getty@.service` (in case of :systemd:var:`getty.ttys.container`) on. Any lines starting with a "#" will be ignored.

   .. versionadded:: 254
