============
updatectl(1)
============

Name
####

updatectl — Control the system update service

Synopsis
########

:code:`updatectl [OPTIONS...] {COMMAND} [TARGET...]`

Description
###########

:code:`updatectl` may be used to check for and install system updates managed by :ref:`systemd-sysupdated.service(8)`.

Commands
########

The following commands are understood:

.. systemd:option:: list [TARGET[@VERSION]]

   Show information about targets and their versions.

   When no :emphasis:`TARGET` is specified, this command lists all available targets. When a :emphasis:`TARGET` is specified without a :emphasis:`VERSION`, this command lists all known versions of the specified target. If a :emphasis:`VERSION` is specified, this command lists all known information about the specific version.

   See the example below for details of the output.

   .. versionadded:: 257

.. systemd:option:: check [TARGET…]

   Check if any updates are available for the specified targets. If no targets are specified, all available targets will be checked for updates.

   See the example below for details of the output.

   .. versionadded:: 257

.. systemd:option:: update [TARGET[@VERSION]…]

   Update the specified targets to the specified versions. If a target is specified without a version, then it will be updated to the latest version. If no targets are specified, then all available targets will be updated to the latest version.

   .. versionadded:: 257

.. systemd:option:: vacuum [TARGET…]

   Clean up old versions of the specified targets. If no targets are specified, all available targets will be vacuumed.

   .. versionadded:: 257

.. systemd:option:: features [FEATURE]

   When no :emphasis:`FEATURE` is specified, this command lists all optional features. When a :emphasis:`FEATURE` is specified, this command lists all known information about that feature.

   .. versionadded:: 257

.. systemd:option:: enable FEATURE…, disable FEATURE…

   These commands enable or disable optional features. See :man-pages:`sysupdate.features(5)`. These commands always operate on the host system.

   By default, these commands will only change the system's configuration by creating or deleting drop-in files; they will not immediately download the enabled features, or clean up after the disabled ones. Enabled features will be downloaded and installed the next time the target is updated, and disabled transfers will be cleaned up the next time the target is updated or vacuumed. Pass :code:`--now` to immediately apply these changes.

   .. versionadded:: 257

Options
#######

The following commands are understood:

.. systemd:option:: --reboot

   When used with the :code:`update` command, reboots the system after updates finish applying. If any update fails, the system will not reboot.

   When used with the :code:`enable` or :code:`disable` commands and the :code:`--now` flag, reboots the system after download or clean-up finish applying.

   .. versionadded:: 257

.. systemd:option:: --offline

   When used with the :code:`list` command, disables fetching metadata from the network. This makes the :code:`list` command only return information that is available locally (i.e. about versions already installed on the system).

   .. versionadded:: 257

.. systemd:option:: --now

   When used with the :code:`enable` command, downloads and installs the enabled features. When used with the :code:`disable` command, deletes all resources downloaded by the disabled features.

   .. versionadded:: 257

Exit status
###########

On success, 0 is returned, a non-zero failure code otherwise.

Checking for and installing updates
-----------------------------------

.. code-block:: sh

   $ updatectl check
   TARGET         UPDATE
   host           48 → 50
   machine:fedora 38 → 40
   $ updatectl update host machine:fedora@39
   [...]
   ✓ host@50
   ✓ machine:fedora@39
