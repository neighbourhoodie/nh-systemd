kernel-command-line(7)
======================

Name
####

kernel-command-line — Kernel command line parameters

Synopsis
########

:code:`/proc/cmdline`

Description
###########

The kernel, the programs running in the initrd and in the host system may be configured at boot via kernel command line arguments.

For command line parameters understood by the kernel, please see `:code:`kernel-parameters.html` <https://docs.kernel.org/admin-guide/kernel-parameters.html>`_ and :man-pages:`bootparam(7)`.

For command line parameters understood by the initrd, see the documentation of the specific initrd implementation of your installation.

.. systemd:option:: systemd.volatile=
   :group: kernel-commandline-options

   This parameter controls whether the system shall boot up in volatile mode. Takes a boolean argument, or the special values "state" or "overlay". If false (the default), normal boot mode is selected, the root directory and :code:`/var/` are mounted as specified on the kernel command line or :code:`/etc/fstab`, or otherwise configured. If true, full state-less boot mode is selected. In this case, the root directory is mounted as volatile memory file system ("tmpfs"), and only :code:`/usr/` is mounted from the file system configured as root device, in read-only mode. This enables fully state-less boots where the vendor-supplied OS is used as shipped, with only default configuration and no stored state in effect, as :code:`/etc/` and :code:`/var/` (as well as all other resources shipped in the root file system) are reset at boot and lost on shutdown. If this setting is set to "state" the root file system is mounted read-only, however :code:`/var/` is mounted as a volatile memory file system ("tmpfs"), so that the system boots up with the normal configuration applied, but all state reset at boot and lost at shutdown. If this setting is set to "overlay" the root file system is set up as "overlayfs" mount combining the read-only root directory with a writable "tmpfs", so that no modifications are made to disk, but the file system may be modified nonetheless with all changes being lost at reboot. For details, see :ref:`systemd-volatile-root.service(8)` and :ref:`systemd-fstab-generator(8)`.

   .. versionadded:: 233

.. systemd:option:: systemd.firstboot=
   :group: kernel-commandline-options

   Takes a boolean argument, defaults to on. If off, :ref:`systemd-firstboot.service(8)` and :ref:`systemd-homed-firstboot.service(1)` will not query the user for basic system settings, even if the system boots up for the first time and the relevant settings are not initialized yet. Not to be confused with :systemd:var:`systemd.condition_first_boot=` (see below), which overrides the result of the :systemd:var:`ConditionFirstBoot=` unit file condition, and thus controls more than just :code:`systemd-firstboot.service` behaviour.

   .. versionadded:: 233

.. systemd:option:: systemd.condition_needs_update=
   :group: kernel-commandline-options

   .. versionadded:: 246

.. systemd:option:: systemd.condition_first_boot=
   :group: kernel-commandline-options

   Takes a boolean argument. If specified, overrides the result of :systemd:var:`ConditionFirstBoot=` unit condition checks. See :ref:`systemd.unit(5)` for details. Not to be confused with :systemd:var:`systemd.firstboot=` which only controls behaviour of the :code:`systemd-firstboot.service` system service but has no effect on the condition check (see above).

   .. versionadded:: 246

.. systemd:option:: systemd.clock_usec=
   :group: kernel-commandline-options

   Takes a decimal, numeric timestamp in μs since January 1st 1970, 00:00am, to set the system clock to. The system time is set to the specified timestamp early during boot. It is not propagated to the hardware clock (RTC).

   .. versionadded:: 246

.. systemd:option:: systemd.random_seed=
   :group: kernel-commandline-options

   Takes a base64 encoded random seed value to credit with full entropy to the kernel's random pool during early service manager initialization. This option is useful in testing environments where delays due to random pool initialization in entropy starved virtual machines shall be avoided.

   Note that if this option is used the seed is accessible to unprivileged programs from :code:`/proc/cmdline`. This option is hence a security risk when used outside of test systems, since the (possibly) only seed used for initialization of the kernel's entropy pool might be easily acquired by unprivileged programs.

   It is recommended to pass 512 bytes of randomized data (as that matches the Linux kernel pool size), which may be generated with a command like the following:

     .. code-block:: sh

        dd if=/dev/urandom bs=512 count=1 status=none | base64 -w 0

   Again: do not use this option outside of testing environments, it is a security risk elsewhere, as secret key material derived from the entropy pool can possibly be reconstructed by unprivileged programs.

   .. versionadded:: 246

.. systemd:option:: systemd.allow_userspace_verity=
   :group: kernel-commandline-options

   Takes a boolean argument. Controls whether disk images that are Verity protected may be authenticated in userspace signature checks via :code:`/etc/verity.d/` (and related directories) public key drop-ins, or whether in-kernel signature checking only. Defaults to on.

   .. versionadded:: 256

.. systemd:option:: systemd.hostname=
   :group: kernel-commandline-options

   Accepts a hostname to set during early boot. If specified takes precedence over what is set in :code:`/etc/hostname`. Note that this does not bar later runtime changes to the hostname, it simply controls the initial hostname set during early boot.

   .. versionadded:: 246

.. systemd:option:: systemd.tty.term.tty=, systemd.tty.rows.tty=, systemd.tty.columns.tty=
   :group: kernel-commandline-options

   These arguments allow configuring default values for :systemd:var:`$TERM`, :systemd:var:`TTYRows=`, and :systemd:var:`TTYColumns=` for tty :emphasis:`tty`. Additionally, :systemd:var:`systemd.tty.term.console` will configure the :systemd:var:`$TERM` value used by :code:`systemd` if not set explicitly using :systemd:var:`TERM` on the kernel command line. The tty name should be specified without the :code:`/dev/` prefix (e.g. "systemd.tty.rows.ttyS0=80").

   .. versionadded:: 254

.. systemd:option:: systemd.battery_check=
   :group: kernel-commandline-options
