Description
###########

:code:`sd_bus_message_new()` creates a new bus message object attached to the bus :code:`bus` and returns it in the output parameter :code:`m`. This object is reference-counted, and will be destroyed when all references are gone. Initially, the caller of this function owns the sole reference to the message object. Note that the message object holds a reference to the bus object, so the bus object will not be destroyed as long as the message exists.

Note: this is a low-level call. In most cases functions like :man-pages:`sd_bus_message_new_method_call(3)`, :man-pages:`sd_bus_message_new_method_error(3)`, :man-pages:`sd_bus_message_new_method_return(3)`, and :man-pages:`sd_bus_message_new_signal(3)` that create a message of a certain type and initialize various fields are easier to use.

The :code:`type` parameter specifies the type of the message. It must be one of :code:`SD_BUS_MESSAGE_METHOD_CALL` — a method call, :code:`SD_BUS_MESSAGE_METHOD_RETURN` — a method call reply, :code:`SD_BUS_MESSAGE_METHOD_ERROR` — an error reply to a method call, :code:`SD_BUS_MESSAGE_SIGNAL` — a broadcast message with no reply.

The flag to allow interactive authorization is initialized based on the current value set in the bus object, see :man-pages:`sd_bus_set_allow_interactive_authorization(3)`. This may be changed using :man-pages:`sd_bus_message_set_allow_interactive_authorization(3)`.

:code:`sd_bus_message_ref()` increases the internal reference counter of :code:`m` by one.

:code:`sd_bus_message_unref()` decreases the internal reference counter of :code:`m` by one. Once the reference count has dropped to zero, message object is destroyed and cannot be used anymore, so further calls to :code:`sd_bus_message_ref()` or :code:`sd_bus_message_unref()` are illegal.

:code:`sd_bus_message_unrefp()` is similar to :code:`sd_bus_message_unref()` but takes a pointer to a pointer to an sd_bus_message object. This call is useful in conjunction with GCC's and LLVM's `Clean-up Variable Attribute <https://gcc.gnu.org/onlinedocs/gcc/Common-Variable-Attributes.html>`_. See :man-pages:`sd_bus_new(3)` for an example how to use the cleanup attribute.

:code:`sd_bus_message_ref()` and :code:`sd_bus_message_unref()` execute no operation if the passed in bus message object address is :code:`NULL`. :code:`sd_bus_message_unrefp()` will first dereference its argument, which must not be :code:`NULL`, and will execute no operation if *that* is is :code:`NULL`.

:code:`sd_bus_message_get_bus()` returns the bus object that message :code:`m` is attached to.

Return Value
############

On success, :code:`sd_bus_message_new()` returns 0 or a positive integer. On failure, it returns a negative errno-style error code.

:code:`sd_bus_message_ref()` always returns the argument.

:code:`sd_bus_message_unref()` always returns :code:`NULL`.

:code:`sd_bus_message_get_bus()` always returns the bus object.

Errors
######

Returned errors may indicate the following problems:

.. systemd:option:: -EINVAL

   Specified :code:`type` is invalid.

.. systemd:option:: -ENOTCONN

   The bus parameter :code:`bus` is :code:`NULL` or the bus is not connected.

.. systemd:option:: -ENOMEM

   Memory allocation failed.
