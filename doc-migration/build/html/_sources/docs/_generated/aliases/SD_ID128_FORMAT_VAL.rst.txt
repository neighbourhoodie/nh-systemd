Description
###########

:code:`sd-id128.h` is part of :man-pages:`libsystemd(3)` and provides APIs to generate, convert, and compare 128-bit ID values. The 128-bit ID values processed and generated by these APIs are a generalization of OSF UUIDs as defined by `RFC 4122 <https://tools.ietf.org/html/rfc4122>`_ but use a simpler string format. These functions impose no structure on the used IDs, much unlike OSF UUIDs or Microsoft GUIDs, but are mostly compatible with those types of IDs.

A 128-bit ID is implemented as the following union type:

.. code-block:: sh

   typedef union sd_id128 {
     uint8_t bytes[16];
     uint64_t qwords[2];
   } sd_id128_t;

This union type allows accessing the 128-bit ID as 16 separate bytes or two 64-bit words. It is generally safer to access the ID components by their 8-bit array to avoid endianness issues. This union is intended to be passed by value (as opposed to pass-by-reference) and may be directly manipulated by clients.

A couple of macros are defined to denote and decode 128-bit IDs:

:code:`SD_ID128_MAKE()` is used to write a constant ID in source code. A commonly used idiom is to assign a name to an ID using this macro:

.. code-block:: sh

   #define SD_MESSAGE_COREDUMP SD_ID128_MAKE(fc,2e,22,bc,6e,e6,47,b6,b9,07,29,ab,34,a2,50,b1)

:code:`SD_ID128_NULL` defines an ID consisting of only :code:`NUL` bytes (i.e. all bits off).

:code:`SD_ID128_ALLF` defines an ID consisting of only :code:`0xFF` bytes (i.e. all bits on).

:code:`SD_ID128_MAKE_STR()` is similar to :code:`SD_ID128_MAKE()`, but creates a const char* expression that can be conveniently used in message formats and such:

.. code-block:: sh

   #include <stdio.h>
   #define SD_MESSAGE_COREDUMP_STR SD_ID128_MAKE_STR(fc,2e,22,bc,6e,e6,47,b6,b9,07,29,ab,34,a2,50,b1)
   int main(int argc, char **argv) {
     puts("Match for coredumps: MESSAGE_ID=" SD_MESSAGE_COREDUMP_STR);
   }

:code:`SD_ID128_CONST_STR()` converts constant IDs into constant strings for output. The following example code will output the string "fc2e22bc6ee647b6b90729ab34a250b1":

.. code-block:: sh

   int main(int argc, char *argv[]) {
     puts("Match for coredumps: %s", SD_ID128_CONST_STR(SD_MESSAGE_COREDUMP));
   }

:code:`SD_ID128_FORMAT_STR` and :code:`SD_ID128_FORMAT_VAL()` is used to format an ID in a :man-pages:`printf(3)` format string, as shown in the following example:

.. code-block:: sh

   int main(int argc, char *argv[]) {
     sd_id128_t id;
     id = SD_ID128_MAKE(ee,89,be,71,bd,6e,43,d6,91,e6,c5,5d,eb,03,02,07);
     printf("The ID encoded in this C file is " SD_ID128_FORMAT_STR ".\n", SD_ID128_FORMAT_VAL(id));
     return 0;
   }

:code:`SD_ID128_UUID_FORMAT_STR` and :code:`SD_ID128_MAKE_UUID_STR()` are similar to :code:`SD_ID128_FORMAT_STR` and :code:`SD_ID128_MAKE_STR()`, but include separating hyphens to conform to the "`UUID canonical representation <https://en.wikipedia.org/wiki/Universally_unique_identifier#Format>`_". They format the string based on `RFC4122 <https://tools.ietf.org/html/rfc4122>`_ Variant 1 rules, i.e. converting from Big Endian byte order. This matches behaviour of most other Linux userspace infrastructure. It's probably best to avoid UUIDs of other variants, in order to avoid unnecessary ambiguities. All 128-bit IDs generated by the sd-id128 APIs strictly conform to Variant 1 Version 4 UUIDs, as per RFC 4122.

:code:`sd_id128_equal()` compares two 128-bit IDs:

.. code-block:: sh

   int main(int argc, char *argv[]) {
     sd_id128_t a, b, c;
     a = SD_ID128_MAKE(ee,89,be,71,bd,6e,43,d6,91,e6,c5,5d,eb,03,02,07);
     b = SD_ID128_MAKE(f2,28,88,9c,5f,09,44,15,9d,d7,04,77,58,cb,e7,3e);
     c = a;
     assert(sd_id128_equal(a, c));
     assert(!sd_id128_equal(a, b));
     return 0;
   }

:code:`sd_id128_string_equal()` is similar to :code:`sd_id128_equal()`, but the first ID is formatted as const char*. The same restrictions apply as to the first argument of :code:`sd_id128_from_string()`.

:code:`sd_id128_is_null()` checks if an ID consists of only :code:`NUL` bytes:

.. code-block:: sh

   assert(sd_id128_is_null(SD_ID128_NULL));

Similarly, :code:`sd_id128_is_allf()` checks if an ID consists of only :code:`0xFF` bytes (all bits on):

.. code-block:: sh

   assert(sd_id128_is_allf(SD_ID128_ALLF));

:code:`sd_id128_in_set_sentinel()` takes a list of IDs and returns true if the first argument is equal to any of the subsequent arguments. The argument list is terminated by an :code:`SD_ID128_NULL` sentinel, which must be present.

:code:`sd_id128_in_set()` is a convenience function that takes a list of IDs and returns true if the first argument is equal to any of the subsequent arguments:

.. code-block:: sh

   int main(int argc, char *argv[]) {
     sd_id12_t a = SD_ID128_MAKE(ee,89,be,71,bd,6e,43,d6,91,e6,c5,5d,eb,03,02,07);
     assert(sd_id128_in_set(a, a));
     assert(sd_id128_in_set(a, a, a));
     assert(!sd_id128_in_set(a));
     assert(!sd_id128_in_set(a,
                             SD_ID128_MAKE(f2,28,88,9c,5f,09,44,15,9d,d7,04,77,58,cb,e7,3e)
                             SD_ID128_MAKE(2f,88,28,5f,9c,44,09,9d,d7,15,77,04,bc,85,7e,e3)
                             SD_ID128_ALLF));
     return 0;
   }

:code:`sd_id128_in_set()` is defined as a macro over :code:`sd_id128_in_set_sentinel()`, adding the :code:`SD_ID128_NULL` sentinel automatically. Since :code:`sd_id128_in_set_sentinel()` uses :code:`SD_ID128_NULL` as the sentinel, :code:`SD_ID128_NULL` cannot be otherwise placed in the argument list.

:code:`sd_id128_in_setv()` is similar to :code:`sd_id128_in_set_sentinel()`, but takes a struct varargs argument.

New randomized IDs may be generated with :man-pages:`systemd-id128(1)`'s :code:`new` command.

See :man-pages:`sd_id128_to_string(3)`, :man-pages:`sd_id128_randomize(3)` and :man-pages:`sd_id128_get_machine(3)` for information about other implemented functions.
