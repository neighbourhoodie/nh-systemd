Description
###########

The :code:`sd_bus_reply_method_error()` function sends an error reply to the :code:`call` message. The error structure :code:`e` specifies the error to send, and is used as described in :ref:`sd_bus_message_new_method_error(3)`. If no reply is expected to :code:`call`, this function succeeds without sending a reply.

The :code:`sd_bus_reply_method_errorf()` is to :code:`sd_bus_reply_method_error()` what :code:`sd_bus_message_new_method_errorf()` is to :code:`sd_bus_message_new_method_error()`.

The :code:`sd_bus_reply_method_errno()` is to :code:`sd_bus_reply_method_error()` what :code:`sd_bus_message_new_method_errno()` is to :code:`sd_bus_message_new_method_error()`.

The :code:`sd_bus_reply_method_errnof()` is to :code:`sd_bus_reply_method_error()` what :code:`sd_bus_message_new_method_errnof()` is to :code:`sd_bus_message_new_method_error()`.

Return Value
############

This function returns a non-negative integer if the error reply was successfully sent or if :code:`call` does not expect a reply. On failure, it returns a negative errno-style error code.

Errors
######

Returned errors may indicate the following problems:

.. systemd:option:: -EINVAL

   The input parameter :code:`call` is :code:`NULL`.

   Message :code:`call` is not a method call message.

   Message :code:`call` is not attached to a bus.

   The error parameter :code:`e` to :code:`sd_bus_reply_method_error()` is not set, see :ref:`sd_bus_error_is_set(3)`.

.. systemd:option:: -EPERM

   Message :code:`call` has been sealed.

.. systemd:option:: -ENOTCONN

   The bus to which message :code:`call` is attached is not connected.

.. systemd:option:: -ENOMEM

   Memory allocation failed.

In addition, any error returned by :ref:`sd_bus_send(3)` may be returned.
