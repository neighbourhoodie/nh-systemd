==============
coredumpctl(1)
==============

Name
####

coredumpctl — Retrieve and process saved core dumps and metadata

Synopsis
########

:code:`coredumpctl [OPTIONS...] {COMMAND} [PID|COMM|EXE|MATCH...]`

Description
###########

:code:`coredumpctl` is a tool that can be used to retrieve and process core dumps and metadata which were saved by :ref:`systemd-coredump(8)`.

Commands
########

The following commands are understood:

.. systemd:option:: list

   List core dumps captured in the journal matching specified characteristics. If no command is specified, this is the implied default.

   The output is designed to be human-readable and contains a table with the following columns:

   .. systemd:constant:: TIME

         The timestamp of the crash, as reported by the kernel.

         .. versionadded:: 233

   .. systemd:constant:: PID

         The identifier of the process that crashed.

         .. versionadded:: 233

   .. systemd:constant:: UID, GID

         The user and group identifiers of the process that crashed.

         .. versionadded:: 233

   .. systemd:constant:: SIGNAL

         The signal that caused the process to crash, when applicable.

         .. versionadded:: 233

   .. systemd:constant:: COREFILE

         Information whether the coredump was stored, and whether it is still accessible: "none" means the core was not stored, "-" means that it was not available (for example because the process was not terminated by a signal), "present" means that the core file is accessible by the current user, "journal" means that the core was stored in the "journal", "truncated" is the same as one of the previous two, but the core was too large and was not stored in its entirety, "error" means that the core file cannot be accessed, most likely because of insufficient permissions, and "missing" means that the core was stored in a file, but this file has since been removed.

         .. versionadded:: 233

   .. systemd:constant:: EXE

         The full path to the executable. For backtraces of scripts this is the name of the interpreter.

         .. versionadded:: 233

   It's worth noting that different restrictions apply to data saved in the journal and core dump files saved in :code:`/var/lib/systemd/coredump`, see overview in :ref:`systemd-coredump(8)`. Thus it may very well happen that a particular core dump is still listed in the journal while its corresponding core dump file has already been removed.

   .. versionadded:: 215

.. systemd:option:: info

   Show detailed information about the last core dump or core dumps matching specified characteristics captured in the journal.

   .. versionadded:: 215

.. systemd:option:: dump

   Extract the last core dump matching specified characteristics. The core dump will be written on standard output, unless an output file is specified with :code:`--output=`.

   .. versionadded:: 215

.. systemd:option:: debug

   Invoke a debugger on the last core dump matching specified characteristics. By default, :man-pages:`gdb(1)` will be used. This may be changed using the :code:`--debugger=` option or the :code:`$SYSTEMD_DEBUGGER` environment variable. Use the :code:`--debugger-arguments=` option to pass extra command line arguments to the debugger.

   .. versionadded:: 239

.. systemd:option:: -1

   Show information of the most recent core dump only, instead of listing all known core dumps. Equivalent to :code:`--reverse -n 1`.

   .. versionadded:: 215

.. systemd:option:: -n INT

   Show at most the specified number of entries. The specified parameter must be an integer greater or equal to 1.

   .. versionadded:: 248

.. systemd:option:: -S, --since

   Only print entries which are since the specified date.

   .. versionadded:: 233

.. systemd:option:: -U, --until

   Only print entries which are until the specified date.

   .. versionadded:: 233

.. systemd:option:: -r, --reverse

   Reverse output so that the newest entries are displayed first.

   .. versionadded:: 233

.. systemd:option:: -F FIELD, --field=FIELD

   Print all possible data values the specified field takes in matching core dump entries of the journal.

   .. versionadded:: 215

.. systemd:option:: -o FILE, --output=FILE

   Write the core to :code:`FILE`.

   .. versionadded:: 215

.. systemd:option:: --debugger=DEBUGGER

   Use the given debugger for the :code:`debug` command. If not given and :code:`$SYSTEMD_DEBUGGER` is unset, then :man-pages:`gdb(1)` will be used.

   .. versionadded:: 239

.. systemd:option:: -A ARGS, --debugger-arguments=ARGS

   Pass the given :emphasis:`ARGS` as extra command line arguments to the debugger. Quote as appropriate when :emphasis:`ARGS` contain whitespace. (See Examples.)

   .. versionadded:: 248

.. systemd:option:: --file=GLOB

   Takes a file glob as an argument. If specified, coredumpctl will operate on the specified journal files matching :emphasis:`GLOB` instead of the default runtime and system journal paths. May be specified multiple times, in which case files will be suitably interleaved.

   .. versionadded:: 246

.. systemd:option:: -D DIR, --directory=DIR

   Use the journal files in the specified :code:`DIR`.

   .. versionadded:: 225

.. systemd:option:: --root=ROOT

   Use root directory :code:`ROOT` when searching for coredumps.

   .. versionadded:: 252

.. systemd:option:: --image=image

   Takes a path to a disk image file or block device node. If specified, all operations are applied to file system in the indicated disk image. This option is similar to :code:`--root=`, but operates on file systems stored in disk images or block devices. The disk image should either contain just a file system or a set of file systems within a GPT partition table, following the `Discoverable Partitions Specification <https://uapi-group.org/specifications/specs/discoverable_partitions_specification>`_. For further information on supported disk images, see :ref:`systemd-nspawn(1)`'s switch of the same name.

Matching
########

A match can be:

.. systemd:constant:: PID

   Process ID of the process that dumped core. An integer.

   .. versionadded:: 215

.. systemd:constant:: COMM

   Name of the executable (matches :code:`COREDUMP_COMM=`). Must not contain slashes.

   .. versionadded:: 215

.. systemd:constant:: EXE

   Path to the executable (matches :code:`COREDUMP_EXE=`). Must contain at least one slash.

   .. versionadded:: 215

.. systemd:constant:: MATCH

   General journalctl match filter, must contain an equals sign ("="). See :man-pages:`journalctl(1)`.

   .. versionadded:: 215

Exit status
###########

On success, 0 is returned; otherwise, a non-zero failure code is returned. Not finding any matching core dumps is treated as failure.

Environment
###########

.. systemd:var:: $SYSTEMD_DEBUGGER
   :group: environment-variables

   Use the given debugger for the :code:`debug` command. See the :systemd:option:`--debugger=` option.

   .. versionadded:: 239

Examples
########

List all the core dumps of a program
------------------------------------

.. code-block:: sh

   $ coredumpctl list /usr/lib64/firefox/firefox
   TIME       PID  UID  GID SIG     COREFILE EXE                         SIZE
   Tue …   8018 1000 1000 SIGSEGV missing  /usr/lib64/firefox/firefox     -
   Wed … 251609 1000 1000 SIGTRAP missing  /usr/lib64/firefox/firefox     -
   Fri … 552351 1000 1000 SIGSEGV present  /usr/lib64/firefox/firefox 28.7M

The journal has three entries pertaining to :code:`/usr/lib64/firefox/firefox`, and only the last entry still has an available core file (in external storage on disk).

Note that :code:`coredumpctl` needs access to the journal files to retrieve the relevant entries from the journal. Thus, an unprivileged user will normally only see information about crashing programs of this user.

Invoke :code:`gdb` on the last core dump
----------------------------------------

.. code-block:: sh

   $ coredumpctl debug

Use :code:`gdb` to display full register info from the last core dump
---------------------------------------------------------------------

.. code-block:: sh

   $ coredumpctl debug --debugger-arguments="-batch -ex 'info all-registers'"

   $ coredumpctl -o bar.coredump dump /usr/bin/bar
