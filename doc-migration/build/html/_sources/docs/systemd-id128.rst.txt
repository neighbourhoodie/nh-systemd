================
systemd-id128(1)
================

Name
####

systemd-id128 — Generate and print sd-128 identifiers

Synopsis
########

:code:`systemd-id128 [OPTIONS...] new`

:code:`systemd-id128 [OPTIONS...] machine-id`

:code:`systemd-id128 [OPTIONS...] boot-id`

:code:`systemd-id128 [OPTIONS...] invocation-id`

:code:`systemd-id128 [OPTIONS...] var-partition-uuid`

:code:`systemd-id128 [OPTIONS...] show [NAME|UUID...]`

Description
###########

:code:`id128` may be used to conveniently print :ref:`sd-id128(3)` UUIDs. What identifier is printed depends on the specific verb.

With :code:`new`, a new random identifier will be generated.

With :code:`machine-id`, the identifier of the current machine will be printed. See :man-pages:`machine-id(5)`.

With :code:`boot-id`, the identifier of the current boot will be printed.

With :code:`invocation-id`, the identifier of the current service invocation will be printed. This is available in systemd services. See :ref:`systemd.exec(5)`.

With :code:`show`, well-known IDs are printed (for now, only GPT partition type UUIDs), along with brief identifier strings. When no arguments are specified, all known IDs are shown. When arguments are specified, they may be the identifiers or ID values of one or more known IDs, which are then printed with their name, or arbitrary IDs, which are then printed with a placeholder name. Combine with :code:`--uuid` to list the IDs in UUID style, i.e. the way GPT partition type UUIDs are usually shown.

:code:`machine-id`, :code:`boot-id`, and :code:`show` may be combined with the :code:`--app-specific=:emphasis:`app-id`` switch to generate application-specific IDs. See :ref:`sd_id128_get_machine(3)` for the discussion when this is useful. Support for :code:`show --app-specific=` was added in version 255.

:code:`var-partition-uuid` prints a UUID which, following the `Discoverable Partitions Specification <https://uapi-group.org/specifications/specs/discoverable_partitions_specification>`_, should be used as the GPT partition UUID for :code:`/var/`, being derived from the GPT partition type, keyed by the local :code:`/etc/machine-id`. Added in version 257.

Options
#######

The following options are understood:

.. systemd:option:: -p, --pretty

   Generate output as programming language snippets.

   .. versionadded:: 240

.. systemd:option:: -P, --value

   Only print the value. May be combined with :code:`-u`/:code:`--uuid`.

   .. versionadded:: 255

.. systemd:option:: -a app-id, --app-specific=app-id

   With this option, identifiers will be printed that are the result of hashing the application identifier :emphasis:`app-id` and another ID. The :emphasis:`app-id` argument must be a valid sd-id128 string identifying the application. When used with :code:`machine-id`, the other ID will be the machine ID as described in :man-pages:`machine-id(5)`, when used with :code:`boot-id`, the other ID will be the boot ID, and when used with :code:`show`, the other ID or IDs should be specified via the positional arguments.

   .. versionadded:: 240

.. systemd:option:: -u, --uuid

   Generate output as a UUID formatted in the "canonical representation", with five groups of digits separated by hyphens. See the Wikipedia entry for `Universally Unique Identifiers <https://en.wikipedia.org/wiki/Universally_unique_identifier#Format>`_ for more discussion.

   .. versionadded:: 244

Exit status
###########

On success 0 is returned, and a non-zero failure code otherwise.

Examples
########

Show a well-known UUID
----------------------

.. code-block:: sh

   $ systemd-id128 show --value user-home
   773f91ef66d449b5bd83d683bf40ad16
   $ systemd-id128 show --value --uuid user-home
   773f91ef-66d4-49b5-bd83-d683bf40ad16
   $ systemd-id128 show 773f91ef-66d4-49b5-bd83-d683bf40ad16
   NAME      ID
   user-home 773f91ef66d449b5bd83d683bf40ad16

Generate an application-specific UUID
-------------------------------------

.. code-block:: sh

   $ systemd-id128 machine-id -u
   3a9d668b-4db7-4939-8a4a-5e78a03bffb7
   $ systemd-id128 new -u
   1fb8f24b-02df-458d-9659-cc8ace68e28a
   $ systemd-id128 machine-id -u -a 1fb8f24b-02df-458d-9659-cc8ace68e28a
   47b82cb1-5339-43da-b2a6-1c350aef1bd1
   $ systemd-id128 -Pu show 3a9d668b-4db7-4939-8a4a-5e78a03bffb7 \
       -a 1fb8f24b-02df-458d-9659-cc8ace68e28a
   47b82cb1-5339-43da-b2a6-1c350aef1bd1

On a given machine with the ID 3a9d668b-4db7-4939-8a4a-5e78a03bffb7, for the application 1fb8f24b-02df-458d-9659-cc8ace68e28a, we generate an application-specific machine ID (47b82cb1-5339-43da-b2a6-1c350aef1bd1). If we want to later recreate the same calculation on a different machine, we need to specify both IDs explicitly as parameters to :code:`show`.
