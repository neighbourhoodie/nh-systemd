Name
####

systemd.system-credentials — System Credentials

Description
###########

`System and Service Credentials <https://systemd.io/CREDENTIALS>`_ are data objects that may be passed into booted systems or system services as they are invoked. They can be acquired from various external sources, and propagated into the system and from there into system services. Credentials may optionally be encrypted with a machine-specific key and/or locked to the local TPM2 device, and are only decrypted when the consuming service is invoked.

System credentials may be used to provision and configure various aspects of the system. Depending on the consuming component credentials are only used on initial invocations or are needed for all invocations.

Credentials may be used for any kind of data, binary or text, and may carry passwords, secrets, certificates, cryptographic key material, identity information, configuration, and more.

Well known system credentials
#############################

.. systemd:option:: firstboot.keymap
   :group: system-credentials

   The console key mapping to set (e.g. "de"). Read by :ref:`systemd-firstboot(1)`, and only honoured if no console keymap has been configured before.

   .. versionadded:: 252

.. systemd:option:: firstboot.locale, firstboot.locale-messages
   :group: system-credentials

   The system locale to set (e.g. "de_DE.UTF-8"). Read by :ref:`systemd-firstboot(1)`, and only honoured if no locale has been configured before. :systemd:var:`firstboot.locale` sets "LANG", while :systemd:var:`firstboot.locale-message` sets "LC_MESSAGES".

   .. versionadded:: 252

.. systemd:option:: firstboot.timezone
   :group: system-credentials

   The system timezone to set (e.g. "Europe/Berlin"). Read by :ref:`systemd-firstboot(1)`, and only honoured if no system timezone has been configured before.

   .. versionadded:: 252

.. systemd:option:: login.issue
   :group: system-credentials

   The data of this credential is written to :code:`/etc/issue.d/50-provision.conf`, if the file does not exist yet. :man-pages:`agetty(8)` reads this file and shows its contents at the login prompt of terminal logins. See :man-pages:`issue(5)` for details.

   Consumed by :code:`/usr/lib/tmpfiles.d/provision.conf`, see :man-pages:`tmpfiles.d(5)`.

   .. versionadded:: 252

.. systemd:option:: login.motd
   :group: system-credentials

   The data of this credential is written to :code:`/etc/motd.d/50-provision.conf`, if the file does not exist yet. :man-pages:`pam_motd(8)` reads this file and shows its contents as "message of the day" during terminal logins. See :man-pages:`motd(5)` for details.

   Consumed by :code:`/usr/lib/tmpfiles.d/provision.conf`, see :man-pages:`tmpfiles.d(5)`.

   .. versionadded:: 252

.. systemd:option:: network.hosts
   :group: system-credentials

   The data of this credential is written to :code:`/etc/hosts`, if the file does not exist yet. See :man-pages:`hosts(5)` for details.

   Consumed by :code:`/usr/lib/tmpfiles.d/provision.conf`, see :man-pages:`tmpfiles.d(5)`.

   .. versionadded:: 252

.. systemd:option:: network.dns, network.search_domains
   :group: system-credentials

   DNS server information and search domains. Read by :ref:`systemd-resolved.service(8)`.

   .. versionadded:: 253

.. systemd:option:: network.conf.*, network.link.*, network.netdev.*, network.network.*
   :group: system-credentials

   Configures network devices. Read by :ref:`systemd-network-generator.service(8)`. These credentials should contain valid :man-pages:`networkd.conf(5)`, :ref:`systemd.link(5)`, :ref:`systemd.netdev(5)`, :ref:`systemd.network(5)` configuration data. From each matching credential a separate file is created. Example: the contents of a credential :code:`network.link.50-foobar` will be copied into a file :code:`50-foobar.link`.

   Note that the resulting files are created world-readable, it is hence recommended to not include secrets in these credentials, but supply them via separate credentials directly to :code:`systemd-networkd.service`, e.g. :systemd:var:`network.wireguard.*` as described below.

   .. versionadded:: 256

.. systemd:option:: network.wireguard.*
   :group: system-credentials

   Configures secrets for WireGuard netdevs. Read by :ref:`systemd-networkd.service(8)`. For more information, refer to the :systemd:option:`[WireGuard]` section of :ref:`systemd.netdev(5)`.

   .. versionadded:: 256

.. systemd:option:: passwd.hashed-password.root, passwd.plaintext-password.root
   :group: system-credentials

   May contain the password (either in UNIX hashed format, or in plaintext) for the root users. Read by both :ref:`systemd-firstboot(1)` and :ref:`systemd-sysusers(8)`, and only honoured if no root password has been configured before.

   .. versionadded:: 252

.. systemd:option:: passwd.shell.root
   :group: system-credentials

   The path to the shell program (e.g. "/bin/bash") for the root user. Read by both :ref:`systemd-firstboot(1)` and :ref:`systemd-sysusers(8)`, and only honoured if no root shell has been configured before.

   .. versionadded:: 252

.. systemd:option:: ssh.ephemeral-authorized_keys-all
   :group: system-credentials

   Provides additional public keys, given in the customary :code:`authorized_keys` format, for all users, for incoming connections via the generated :systemd:constant:`AF_VSOCK` and :systemd:constant:`AF_UNIX` socket units.

   The intended use of this is for a host system (in either VM or container configurations) to generate a keypair and inject the public key into the guest, using the private key to connect to any user account on the guest via ssh, without further authentication.

   Consumed by :ref:`systemd-ssh-generator(8)`.

   .. versionadded:: 256

.. systemd:option:: ssh.authorized_keys.root
   :group: system-credentials

   The data of this credential is written to :code:`/root/.ssh/authorized_keys`, if the file does not exist yet. This allows provisioning SSH access for the system's root user.

   Consumed by :code:`/usr/lib/tmpfiles.d/provision.conf`, see :man-pages:`tmpfiles.d(5)`.

   .. versionadded:: 252

.. systemd:option:: ssh.listen
   :group: system-credentials

   May be used to configure SSH sockets the system shall be reachable on. See :ref:`systemd-ssh-generator(8)` for details.

   .. versionadded:: 256

.. systemd:option:: sysusers.extra
   :group: system-credentials

   Additional :man-pages:`sysusers.d(5)` lines to process during boot.

   .. versionadded:: 252

.. systemd:option:: sysctl.extra
   :group: system-credentials

   Additional :man-pages:`sysctl.d(5)` lines to process during boot.

   .. versionadded:: 252

.. systemd:option:: tmpfiles.extra
   :group: system-credentials

   Additional :man-pages:`tmpfiles.d(5)` lines to process during boot.

   .. versionadded:: 252

.. systemd:option:: fstab.extra
   :group: system-credentials

   Additional mounts to establish at boot. For details, see :ref:`systemd-fstab-generator(8)`.

   .. versionadded:: 254

.. systemd:option:: vconsole.keymap, vconsole.keymap_toggle, vconsole.font, vconsole.font_map, vconsole.font_unimap
   :group: system-credentials

   Console settings to apply, see :ref:`systemd-vconsole-setup.service(8)` for details.

   .. versionadded:: 253

.. systemd:option:: getty.auto
   :group: system-credentials

   Used for controlling the execution mode of :code:`systemd-getty-generator`. See :ref:`systemd-getty-generator(8)` for details.

   .. versionadded:: 258

.. systemd:option:: getty.ttys.serial, getty.ttys.container
   :group: system-credentials

   Used for spawning additional login prompts, see :ref:`systemd-getty-generator(8)` for details.

   .. versionadded:: 254

.. systemd:option:: journal.forward_to_socket
   :group: system-credentials

   Used by :ref:`systemd-journald(8)` to determine where to forward log messages for socket forwarding, see :man-pages:`journald.conf(5)` for details.

   .. versionadded:: 256

.. systemd:option:: journal.storage
   :group: system-credentials

   Used by :ref:`systemd-journald(8)` to determine where to store journal files, see :man-pages:`journald.conf(5)` for details.

   .. versionadded:: 256

.. systemd:option:: vmm.notify_socket
   :group: system-credentials

   Configures an :ref:`sd_notify(3)` compatible :systemd:constant:`AF_VSOCK` socket the service manager will report status information, ready notification and exit status on. For details see :ref:`systemd(1)`.

   .. versionadded:: 253

.. systemd:option:: shell.prompt.prefix, shell.prompt.suffix
   :group: system-credentials

   Defines strings to prefix and suffix any interactive UNIX shell prompt with. For details see :man-pages:`pam_systemd(8)`.

   .. versionadded:: 257

.. systemd:option:: shell.welcome
   :group: system-credentials

   Define a string to print when an interactive UNIX shell initializes. For details see :man-pages:`pam_systemd(8)`.

   .. versionadded:: 257

.. systemd:option:: system.machine_id
   :group: system-credentials

   Takes a 128bit ID to initialize the machine ID from (if it is not set yet). Interpreted by the service manager (PID 1). For details see :ref:`systemd(1)`.

   .. versionadded:: 254

.. systemd:option:: system.hostname
   :group: system-credentials

   Accepts a (transient) hostname to configure during early boot. The static hostname specified in :code:`/etc/hostname`, if configured, takes precedence over this setting. Interpreted by the service manager (PID 1). For details see :ref:`systemd(1)`.

   .. versionadded:: 254

.. systemd:option:: home.add-signing-key.*
   :group: system-credentials

   Adds a new signing key for user records to the system. The credential contents should contain a user signing key, for example as reported by :code:`homectl get-signing-key`. Multiple keys may be specified, and they will be put in place under the name of the credential name suffix (which must itself carry the :code:`.public` suffix). For details see :man-pages:`homectl(1)`.

   .. versionadded:: 258

.. systemd:option:: home.create.*
   :group: system-credentials

   Creates a new home area for the specified user with the user record data passed in. For details see :man-pages:`homectl(1)`.

   .. versionadded:: 256

.. systemd:option:: home.register.*
   :group: system-credentials

   Registers an existing home area for the specified user with the user record data passed in. For details see :man-pages:`homectl(1)`.

   .. versionadded:: 258

.. systemd:option:: cryptsetup.passphrase, cryptsetup.tpm2-pin, cryptsetup.fido2-pin, cryptsetup.pkcs11-pin, cryptsetup.luks2-pin
   :group: system-credentials

   Specifies the passphrase/PINs to use for unlock encrypted storage volumes. For details see :ref:`systemd-cryptsetup(8)`.

   .. versionadded:: 256

.. systemd:option:: systemd.extra-unit.*, systemd.unit-dropin.*
   :group: system-credentials

   These credentials specify extra units and drop-ins to add to the system. For details see :ref:`systemd-debug-generator(8)`.

   .. versionadded:: 256

.. systemd:option:: udev.conf.*, udev.rules.*
   :group: system-credentials

   Configures udev configuration file and udev rules. Read by :code:`systemd-udev-load-credentials.service`, which invokes :code:`udevadm control --load-credentials`. These credentials directly translate to a matching :man-pages:`udev.conf(5)` or :man-pages:`udev(7)` rules file. Example: the contents of a credential :code:`udev.conf.50-foobar` will be copied into a file :code:`/run/udev/udev.conf.d/50-foobar.conf`, and :code:`udev.rules.50-foobar` will be copied into a file :code:`/run/udev/rules.d/50-foobar.rules`. See :man-pages:`udev(7)`, :man-pages:`udev.conf(5)`, and :man-pages:`udevadm(8)` for details.

   .. versionadded:: 256

.. systemd:option:: import.pull
   :group: system-credentials

   Specified disk images (tarballs and DDIs) to automatically download and install at boot. For details see :ref:`systemd-import-generator(8)`.

   .. versionadded:: 257

.. systemd:option:: userdb.user.*, userdb.group.*, userdb.transient.user.*, userdb.transient.group.*
   :group: system-credentials

   Configure JSON user and group records. Read by :code:`systemd-userdb-load-credentials.service`, which invokes :code:`userdbctl load-credentials`. These credentials directly translate to matching `JSON User <https://systemd.io/USER_RECORD>`_ and `JSON Group <https://systemd.io/GROUP_RECORD>`_ records. Example: the contents of a credential :code:`userdb.user.foobar` will be copied into a file :code:`/etc/userdb/foobar.user`, and :code:`userdb.group.foobar` will be copied into a file :code:`/etc/userdb/foobar.group`. Symlinks for the uid/gid will also be created in :code:`/etc/userdb/`, as well as the corresponding:code:`.membership` files. See :ref:`systemd-userdbd.service(7)`, :man-pages:`nss-systemd(8)`, and :man-pages:`userdbctl(1)` for details.

   Any passed user records must contain uid and gid fields. Any passed group records must contain a gid field. For both user and group records, the credential suffix (for "userdb.user.foobar" the suffix is "foobar") must match the user or group name field from the user or group record.

   Note that the records created for :systemd:var:`userdb.user.*` and :systemd:var:`userdb.group.*` credentials are created in :code:`/etc/userdb/` and the records created for :systemd:var:`userdb.transient.user.*` and :systemd:var:`userdb.transient.group.*` are created in :code:`/run/userdb/` (:code:`/etc/passwd` and :code:`/etc/group` are not modified).

   .. versionadded:: 258

.. systemd:option:: fsck.*
   :group: system-credentials

   Read by :code:`systemd-fsck@.service`, :code:`systemd-fsck-root.service`, and :code:`systemd-fsck-usr.service`. See :ref:`systemd-fsck@.service(8)` for more details.

   .. versionadded:: 258

.. systemd:option:: quotacheck.*
   :group: system-credentials

   Read by :code:`systemd-quotacheck@.service` and :code:`systemd-quotacheck-root.service`. See :ref:`systemd-quotacheck(8)` for more details.

   .. versionadded:: 258
