udev(7)
=======

Name
####

udev — Dynamic device management

Description
###########

udev supplies the system software with device events, manages permissions of device nodes and may create additional symlinks in the :code:`/dev/` directory, or renames network interfaces. The kernel usually just assigns unpredictable device names based on the order of discovery. Meaningful symlinks or network device names provide a way to reliably identify devices based on their properties or current configuration.

The udev daemon, :ref:`systemd-udevd.service(8)`, receives device uevents directly from the kernel whenever a device is added or removed from the system, or it changes its state. When udev receives a device event, it matches its configured set of rules against various device attributes to identify the device. Rules that match may provide additional device information to be stored in the udev database or to be used to create meaningful symlink names.

All device information udev processes is stored in the udev database and sent out to possible event subscribers. Access to all stored data and the event sources is provided by the library libudev.

Rules Files
###########

The udev rules are read from the files located in the system rules directories :code:`/usr/lib/udev/rules.d` and :code:`/usr/local/lib/udev/rules.d`, the volatile runtime directory :code:`/run/udev/rules.d` and the local administration directory :code:`/etc/udev/rules.d`. All rules files are collectively sorted and processed in lexicographic order, regardless of the directories in which they live. However, files with identical filenames replace each other. Files in :code:`/etc/` have the highest priority, files in :code:`/run/` take precedence over files with the same name under :code:`/usr/`. This can be used to override a system-supplied rules file with a local file if needed; a symlink in :code:`/etc/` with the same name as a rules file in :code:`/usr/lib/`, pointing to :code:`/dev/null`, disables the rules file entirely. Rule files must have the extension :code:`.rules`; other extensions are ignored.

Every line in the rules file contains at least one key-value pair. Except for empty lines or lines beginning with "#", which are ignored. There are two kinds of keys: match and assignment. If all match keys match against their values, the rule gets applied and the assignment keys get the specified values assigned.

A matching rule may rename a network interface, add symlinks pointing to the device node, or run a specified program as part of the event handling.

A rule consists of a comma-separated list of one or more key-operator-value expressions. Each expression has a distinct effect, depending on the key and operator used.

Operators
#########

.. systemd:option:: "=="

   Compare for equality. (The specified key has the specified value.)

.. systemd:option:: "!="

   Compare for inequality. (The specified key does not have the specified value, or the specified key is not present at all.)

.. systemd:option:: "="

   Assign a value to a key. Keys that represent a list are reset and only this single value is assigned.

.. systemd:option:: "+="

   Add the value to a key that holds a list of entries.

.. systemd:option:: "-="

   Remove the value from a key that holds a list of entries.

   .. versionadded:: 217

.. systemd:option:: ":="

   Assign a value to a key finally; disallow any later changes.

   .. versionadded:: 247

Values
######

Values are written as double quoted strings, such as ("string"). To include a quotation mark (") in the value, precede it by a backslash (\\"). Any other occurrences of a backslash followed by a character are not unescaped. That is, "\\t\\n" is treated as four characters: backslash, lowercase t, backslash, lowercase n.

The string can be prefixed with a lowercase e (e"string\\n") to mark the string as C-style escaped, see `Escape sequences in C <https://en.wikipedia.org/wiki/Escape_sequences_in_C#Table_of_escape_sequences>`_. For example, e"string\\n" is parsed as 7 characters: 6 lowercase letters and a newline. This can be useful for writing special characters when a kernel driver requires them.

The string can be prefixed with a lowercase i (i"string") to mark that the string or pattern will match case-insensitively. For example, i"foo" will match "foo", "FOO", "FoO" and so on. The prefix can be used only for match ("==") or unmatch ("!=") rules, e.g. :code:`ATTR{foo}==i"abcd"`.

Please note that :code:`NUL` is not allowed in either string variant.

Keys
####

The following key names can be used to match against device properties. Some of the keys also match against properties of the parent devices in sysfs, not only the device that has generated the event. If multiple keys that match a parent device are specified in a single rule, all these keys must match at one and the same parent device.

.. systemd:constant:: ACTION
   :group: udev-directives

   Match the name of the event action.

.. systemd:constant:: DEVPATH
   :group: udev-directives

   Match the devpath of the event device.

.. systemd:constant:: KERNEL
   :group: udev-directives

   Match the name of the event device.

.. systemd:constant:: KERNELS
   :group: udev-directives

   Search the devpath upwards for a matching device name.

.. systemd:constant:: NAME
   :group: udev-directives

   Match the name of a network interface. It can be used once the NAME key has been set in one of the preceding rules.

.. systemd:constant:: SYMLINK
   :group: udev-directives

   Match the name of a symlink targeting the node. It can be used once a SYMLINK key has been set in one of the preceding rules. There may be multiple symlinks; only one needs to match. If the operator is "!=", the token returns true only if there is no symlink matched.

.. systemd:constant:: SUBSYSTEM
   :group: udev-directives

   Match the subsystem of the event device.

.. systemd:constant:: SUBSYSTEMS
   :group: udev-directives

   Search the devpath upwards for a matching device subsystem name.

.. systemd:constant:: DRIVER
   :group: udev-directives

   Match the driver name of the event device. Only set this key for devices which are bound to a driver at the time the event is generated.

.. systemd:constant:: DRIVERS
   :group: udev-directives

   Search the devpath upwards for a matching device driver name.

.. systemd:option:: ATTR{filename}
   :group: udev-directives

   Match sysfs attribute value of the event device.

   Trailing whitespace in the attribute values is ignored unless the specified match value itself contains trailing whitespace.

.. systemd:option:: ATTRS{filename}
   :group: udev-directives

   Search the devpath upwards for a device with matching sysfs attribute values. If multiple :systemd:var:`ATTRS` matches are specified, all of them must match on the same device.

   Trailing whitespace in the attribute values is ignored unless the specified match value itself contains trailing whitespace.

.. systemd:option:: SYSCTL{kernel parameter}
   :group: udev-directives

   Match a kernel parameter value.

   .. versionadded:: 240

.. systemd:option:: ENV{key}
   :group: udev-directives

   Match against a device property value.

.. systemd:option:: CONST{key}
   :group: udev-directives

   Match against a system-wide constant. Supported keys are:

   .. systemd:option:: "arch"
      :group: udev-directives

         System's architecture. See :systemd:option:`ConditionArchitecture=` in :ref:`systemd.unit(5)` for possible values.

         .. versionadded:: 244

   .. systemd:option:: "virt"
      :group: udev-directives

         System's virtualization environment. See :ref:`systemd-detect-virt(1)` for possible values.

         .. versionadded:: 244

   .. systemd:option:: "cvm"
      :group: udev-directives

         System's confidential virtualization technology. See :ref:`systemd-detect-virt(1)` for possible values.

         .. versionadded:: 254

   Unknown keys will never match.

   .. versionadded:: 244

.. systemd:constant:: TAG
   :group: udev-directives

   Match against one of device tags. It can be used once a TAG key has been set in one of the preceding rules. There may be multiple tags; only one needs to match. If the operator is "!=", the token returns true only if there is no tag matched.

.. systemd:constant:: TAGS
   :group: udev-directives

   Search the devpath upwards for a device with matching tag. If the operator is "!=", the token returns true only if there is no tag matched.

.. systemd:option:: TEST{octal mode mask}
   :group: udev-directives

   Test the existence of a file. An octal mode mask can be specified if needed.

.. systemd:constant:: PROGRAM
   :group: udev-directives

   Execute a program to determine whether there is a match; the key is true if the program returns successfully. The device properties are made available to the executed program in the environment. The program's standard output is available in the :systemd:var:`RESULT` key.

   This can only be used for very short-running foreground tasks. For details, see :systemd:var:`RUN`.

   Note that multiple :systemd:var:`PROGRAM` keys may be specified in one rule, and "=", ":=", and "+=" have the same effect as "==".

.. systemd:constant:: RESULT
   :group: udev-directives

   Match the returned string of the last :systemd:var:`PROGRAM` call. This key can be used in the same or in any later rule after a :systemd:var:`PROGRAM` call.

Most of the fields support shell glob pattern matching and alternate patterns. The following special characters are supported:

.. systemd:option:: "*"

   Matches zero or more characters.

.. systemd:option:: "?"

   Matches any single character.

.. systemd:option:: "[]"

   Matches any single character specified within the brackets. For example, the pattern string "tty[SR]" would match either "ttyS" or "ttyR". Ranges are also supported via the "-" character. For example, to match on the range of all digits, the pattern "[0-9]" could be used. If the first character following the "[" is a "!", any characters not enclosed are matched.

.. systemd:option:: "|"

   Separates alternative patterns. For example, the pattern string "abc|x*" would match either "abc" or "x*".

   .. versionadded:: 217

The following keys can get values assigned:

.. systemd:constant:: NAME
   :group: udev-directives

   The name to use for a network interface. See :ref:`systemd.link(5)` for a higher-level mechanism for setting the interface name. The name of a device node cannot be changed by udev, only additional symlinks can be created.

.. systemd:constant:: SYMLINK
   :group: udev-directives

   The name of a symlink targeting the node. Every matching rule adds this value to the list of symlinks to be created.

   The set of characters to name a symlink is limited. Allowed characters are "0-9A-Za-z#+-.:=@_/", valid UTF-8 character sequences, and "\\x00" hex encoding. All other characters are replaced by a "_" character.

   Multiple symlinks may be specified by separating the names by the space character. In case multiple devices claim the same name, the link always points to the device with the highest link_priority. If the current device goes away, the links are re-evaluated and the device with the next highest link_priority becomes the owner of the link. If no link_priority is specified, the order of the devices (and which one of them owns the link) is undefined.

   Symlink names must never conflict with the kernel's default device node names, as that would result in unpredictable behavior.

.. systemd:constant:: OWNER, GROUP, MODE
   :group: udev-directives

   The permissions for the device node. Every specified value overrides the compiled-in default value.

.. systemd:option:: SECLABEL{module}
   :group: udev-directives

   Applies the specified Linux Security Module label to the device node.

   .. versionadded:: 209

.. systemd:option:: ATTR{key}
   :group: udev-directives

   The value that should be written to a sysfs attribute of the event device.

.. systemd:option:: SYSCTL{kernel parameter}
   :group: udev-directives

   The value that should be written to kernel parameter.

   .. versionadded:: 220

.. systemd:option:: ENV{key}
   :group: udev-directives

   Set a device property value. Property names with a leading "." are neither stored in the database nor exported to events or external tools (run by, for example, the :systemd:var:`PROGRAM` match key).

.. systemd:constant:: TAG
   :group: udev-directives

   Attach a tag to a device. This is used to filter events for users of libudev's monitor functionality, or to enumerate a group of tagged devices. The implementation can only work efficiently if only a few tags are attached to a device. It is only meant to be used in contexts with specific device filter requirements, and not as a general-purpose flag. Excessive use might result in inefficient event handling.

.. systemd:option:: RUN{type}
   :group: udev-directives

   Specify a program to be executed after processing of all the rules for the event. With "+=", this invocation is added to the list, and with "=" or ":=", it replaces any previous contents of the list. Please note that both "program" and "builtin" types described below share a common list, so clearing the list with ":=" and "=" affects both types.

   :emphasis:`type` may be:

   .. systemd:option:: "program"
      :group: udev-directives

         Execute an external program specified as the assigned value. If no absolute path is given, the program is expected to live in :code:`/usr/lib/udev`; otherwise, the absolute path must be specified.

         This is the default if no :emphasis:`type` is specified.

   .. systemd:option:: "builtin"
      :group: udev-directives

         As :systemd:var:`program`, but use one of the built-in programs rather than an external one.

         .. versionadded:: 199

   The program name and following arguments are separated by spaces. Single quotes can be used to specify arguments with spaces.

   This can only be used for very short-running foreground tasks. Running an event process for a long period of time may block all further events for this or a dependent device.

   Note that running programs that access the network or mount/unmount filesystems is not allowed inside of udev rules, due to the default sandbox that is enforced on :code:`systemd-udevd.service`.

   Starting daemons or other long-running processes is not allowed; the forked processes, detached or not, will be unconditionally killed after the event handling has finished. In order to activate long-running processes from udev rules, provide a service unit and pull it in from a udev device using the :systemd:var:`SYSTEMD_WANTS` device property. See :ref:`systemd.device(5)` for details.

.. systemd:constant:: LABEL
   :group: udev-directives

   A named label to which a :systemd:var:`GOTO` may jump.

.. systemd:constant:: GOTO
   :group: udev-directives

   Jumps to the next :systemd:var:`LABEL` with a matching name.

.. systemd:option:: IMPORT{type}
   :group: udev-directives

   Import a set of variables as device properties, depending on :emphasis:`type`:

   .. systemd:option:: "program"
      :group: udev-directives

         Execute an external program specified as the assigned value and, if it returns successfully, import its output, which must be in environment key format. Path specification, command/argument separation, and quoting work like in :systemd:var:`RUN`.

         .. versionadded:: 199

   .. systemd:option:: "builtin"
      :group: udev-directives

         Similar to "program", but use one of the built-in programs rather than an external one.

         .. versionadded:: 199

   .. systemd:option:: "file"
      :group: udev-directives

         Import a text file specified as the assigned value, the content of which must be in environment key format.

   .. systemd:option:: "db"
      :group: udev-directives

         Import a single property specified as the assigned value from the current device database. This works only if the database is already populated by an earlier event.

   .. systemd:option:: "cmdline"
      :group: udev-directives

         Import a single property from the kernel command line. For simple flags the value of the property is set to "1".

   .. systemd:option:: "parent"
      :group: udev-directives

         Import the stored keys from the parent device by reading the database entry of the parent device. The value assigned to :systemd:option:`IMPORT{parent}` is used as a filter of key names to import (with the same shell glob pattern matching used for comparisons).

   This can only be used for very short-running foreground tasks. For details see :systemd:option:`RUN`.

   Note that multiple :systemd:var:`IMPORT{}` keys may be specified in one rule, and "=", ":=", and "+=" have the same effect as "==". The key is true if the import is successful, unless "!=" is used as the operator which causes the key to be true if the import failed.

.. systemd:constant:: OPTIONS
   :group: udev-directives

   Rule and device options:

   .. systemd:option:: link_priority=value
      :group: udev-directives

         Specify the priority of the created symlinks. Devices with higher priorities overwrite existing symlinks of other devices. The default is 0.

   .. systemd:option:: string_escape=none|replace
      :group: udev-directives

         When "replace", possibly unsafe characters in strings assigned to :systemd:var:`NAME`, :systemd:var:`SYMLINK`, and :systemd:var:`ENV{:emphasis:`key`}` are replaced. When "none", no replacement is performed. When unset, the replacement is performed for :systemd:var:`NAME`, :systemd:var:`SYMLINK`, but not for :systemd:var:`ENV{:emphasis:`key`}`. Defaults to unset.

   .. systemd:option:: static_node=
      :group: udev-directives

         Apply the permissions specified in this rule to the static device node with the specified name. Also, for every tag specified in this rule, create a symlink in the directory :code:`/run/udev/static_node-tags/tag` pointing at the static device node with the specified name. Static device node creation is performed by systemd-tmpfiles before systemd-udevd is started. The static nodes might not have a corresponding kernel device; they are used to trigger automatic kernel module loading when they are accessed.

   .. systemd:option:: watch
      :group: udev-directives

         Watch the device node with inotify; when the node is closed after being opened for writing, a change uevent is synthesized.

   .. systemd:option:: nowatch
      :group: udev-directives

         Disable the watching of a device node with inotify.

   .. systemd:option:: db_persist
      :group: udev-directives

         Set the flag (sticky bit) on the udev database entry of the event device. Device properties are then kept in the database even when :code:`udevadm info --cleanup-db` is called. This option can be useful in certain cases (e.g. Device Mapper devices) for persisting device state on the transition from initrd.

         .. versionadded:: 241

   .. systemd:option:: log_level=level
      :group: udev-directives

         Takes a log level name like "debug" or "info", or a special value "reset". When a log level name is specified, the maximum log level is changed to that level. When "reset" is set, then the previously specified log level is revoked. Defaults to the log level of the main process of :code:`systemd-udevd`.

         This may be useful when debugging events for certain devices. Note that the log level is applied when the line including this rule is processed. So, for debugging, it is recommended that this is specified at earlier place, e.g., the first line of :code:`00-debug.rules`.

         Example for debugging uevent processing for network interfaces:

             .. code-block:: sh

                # /etc/udev/rules.d/00-debug-net.rules
                SUBSYSTEM=="net", OPTIONS="log_level=debug"

         .. versionadded:: 248

   .. systemd:option:: dump
      :group: udev-directives

         Dump the status of the event currently processing. It may be useful for debugging udev rules by inserting this option.

         .. versionadded:: 258

   .. systemd:option:: dump-json
      :group: udev-directives

         Similar to :systemd:option:`dump`, but dump the status of the event in JSON format.

         .. versionadded:: 259

The :code:`ENV`, :code:`GROUP`, :code:`MODE`, :code:`NAME`, :code:`OWNER`, :code:`PROGRAM`, :code:`RUN`, :code:`SECLABEL`, and :code:`SYMLINK` fields support simple string substitutions. The :code:`RUN` substitutions are performed after all rules have been processed, right before the program is executed, allowing for the use of device properties set by earlier matching rules. For all other fields, substitutions are performed while the individual rule is being processed. The available substitutions are:

.. systemd:var:: $kernel, %k
   :group: udev-directives

   The kernel name for this device.

.. systemd:var:: $number, %n
   :group: udev-directives

   The kernel number for this device. For example, "sda3" has kernel number 3.

.. systemd:var:: $devpath, %p
   :group: udev-directives

   The devpath of the device.

.. systemd:var:: $id, %b
   :group: udev-directives

   The name of the device matched while searching the devpath upwards for :systemd:option:`SUBSYSTEMS`, :systemd:option:`KERNELS`, :systemd:option:`DRIVERS`, and :systemd:option:`ATTRS`.

.. systemd:var:: $driver
   :group: udev-directives

   The driver name of the device matched while searching the devpath upwards for :systemd:option:`SUBSYSTEMS`, :systemd:option:`KERNELS`, :systemd:option:`DRIVERS`, and :systemd:option:`ATTRS`.

.. systemd:var:: $attr{file}, %s{file}
   :group: udev-directives

   The value of a sysfs attribute found at the device where all keys of the rule have matched. If the matching device does not have such an attribute, and a previous :systemd:option:`KERNELS`, :systemd:option:`SUBSYSTEMS`, :systemd:option:`DRIVERS`, or :systemd:option:`ATTRS` test selected a parent device, then the attribute from that parent device is used.

   If the attribute is a symlink, the last element of the symlink target is returned as the value.

.. systemd:var:: $env{key}, %E{key}
   :group: udev-directives

   A device property value.

.. systemd:var:: $major, %M
   :group: udev-directives

   The kernel major number for the device.

.. systemd:var:: $minor, %m
   :group: udev-directives

   The kernel minor number for the device.

.. systemd:var:: $result, %c
   :group: udev-directives

   The string returned by the external program requested with :systemd:var:`PROGRAM`. A single part of the string, separated by a space character, may be selected by specifying the part number as an attribute: "%c{N}". If the number is followed by the "+" character, this part plus all remaining parts of the result string are substituted: "%c{N+}".

.. systemd:var:: $parent, %P
   :group: udev-directives

   The node name of the parent device.

.. systemd:var:: $name
   :group: udev-directives

   The current name of the device. If not changed by a rule, it is the name of the kernel device.

.. systemd:var:: $links
   :group: udev-directives

   A space-separated list of the current symlinks. The value is only set during a remove event or if an earlier rule assigned a value.

.. systemd:var:: $root, %r
   :group: udev-directives

   The udev_root value.

.. systemd:var:: $sys, %S
   :group: udev-directives

   The sysfs mount point.

.. systemd:var:: $devnode, %N
   :group: udev-directives

   The name of the device node.

.. systemd:option:: %%
   :group: udev-directives

   The "%" character itself.

.. systemd:var:: $$
   :group: udev-directives

   The "$" character itself.
