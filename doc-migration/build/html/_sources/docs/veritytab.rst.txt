============
veritytab(5)
============

Name
####

veritytab — Configuration for verity block devices

Synopsis
########

:code:`/etc/veritytab`

Description
###########

The :code:`/etc/veritytab` file describes verity protected block devices that are set up during system boot.

Empty lines and lines starting with the "#" character are ignored. Each of the remaining lines describes one verity protected block device. Fields are delimited by white space.

Each line is in the form

.. code-block:: sh

   volume-name  data-device  hash-device  roothash  [options]

The first four fields are mandatory, the remaining one is optional.

The first field contains the name of the resulting verity volume; its block device is set up below :code:`/dev/mapper/`.

The second field contains a path to the underlying block data device, or a specification of a block device via :code:`UUID=` followed by the :emphasis:`UUID`.

The third field contains a path to the underlying block hash device, or a specification of a block device via :code:`UUID=` followed by the :emphasis:`UUID`.

The fourth field is the :emphasis:`roothash` in hexadecimal. If this field is specified as dash, it is attempted to read the root hash from the udev property "ID_DISSECT_PART_ROOTHASH=" (encoded in hexadecimal) of the data device.

The fifth field, if present, is a comma-delimited list of options. The following options are recognized:

.. systemd:option:: superblock=BOOL
   :group: fstab-options

   Use dm-verity with or without permanent on-disk superblock.

   .. versionadded:: 254

.. systemd:option:: format=NUMBER
   :group: fstab-options

   Specifies the hash version type. Format type "0" is original Chrome OS version. Format type "1" is modern version.

   .. versionadded:: 254

.. systemd:option:: data-block-size=BYTES
   :group: fstab-options

   Used block size for the data device. (Note kernel supports only page-size as maximum here; Multiples of 512 bytes.)

   .. versionadded:: 254

.. systemd:option:: hash-block-size=BYTES
   :group: fstab-options

   Used block size for the hash device. (Note kernel supports only page-size as maximum here; Multiples of 512 bytes.)

   .. versionadded:: 254

.. systemd:option:: data-blocks=BLOCKS
   :group: fstab-options

   Number of blocks of data device used in verification. If not specified, the whole device is used.

   .. versionadded:: 254

.. systemd:option:: hash-offset=BYTES
   :group: fstab-options

   Offset of hash area/superblock on "hash-device". (Multiples of 512 bytes.)

   .. versionadded:: 254

.. systemd:option:: salt=HEX
   :group: fstab-options

   Salt used for format or verification. Format is a hexadecimal string; 256 bytes long maximum; "-" is the special value for empty.

   .. versionadded:: 254

.. systemd:option:: uuid=UUID
   :group: fstab-options

   Use the provided :emphasis:`UUID` instead of generating new one. The :emphasis:`UUID` must be provided in standard UUID format, e.g. "12345678-1234-1234-1234-123456789abc".

   .. versionadded:: 254

.. systemd:option:: ignore-corruption, restart-on-corruption, panic-on-corruption
   :group: fstab-options

   Defines what to do if a data verity problem is detected (data corruption). Without these options kernel fails the IO operation with I/O error. With :systemd:option:`--ignore-corruption` option the corruption is only logged. With :systemd:option:`--restart-on-corruption` or :systemd:option:`--panic-on-corruption` the kernel is restarted (panicked) immediately. (You have to provide way how to avoid restart loops.)

   .. versionadded:: 248

.. systemd:option:: ignore-zero-blocks
   :group: fstab-options

   Instruct kernel to not verify blocks that are expected to contain zeroes and always directly return zeroes instead.

   .. warning::

       Use this option only in very specific cases. This option is available since Linux kernel version 4.5.

   .. versionadded:: 248

.. systemd:option:: check-at-most-once
   :group: fstab-options

   Instruct kernel to verify blocks only the first time they are read from the data device, rather than every time.

   .. warning::

       It provides a reduced level of security because only offline tampering of the data device's content will be detected, not online tampering. This option is available since Linux kernel version 4.17.

   .. versionadded:: 248

.. systemd:option:: hash=HASH
   :group: fstab-options

   Hash algorithm for dm-verity. This should be the name of the algorithm, like "sha1". For default see :code:`veritysetup --help`.

   .. versionadded:: 254

.. systemd:option:: fec-device=PATH
   :group: fstab-options

   Use forward error correction (FEC) to recover from corruption if hash verification fails. Use encoding data from the specified device. The fec device argument can be block device or file image. If fec device path does not exist, it will be created as file. Note: block sizes for data and hash devices must match. Also, if the verity data_device is encrypted the fec_device should be too.

   .. versionadded:: 254

.. systemd:option:: fec-offset=BYTES
   :group: fstab-options

   This is the offset, in bytes, from the start of the FEC device to the beginning of the encoding data. (Aligned on 512 bytes.)

   .. versionadded:: 254

.. systemd:option:: fec-roots=NUM
   :group: fstab-options

   Number of generator roots. This equals to the number of parity bytes in the encoding data. In RS(M, N) encoding, the number of roots is M-N. M is 255 and M-N is between 2 and 24 (including).

   .. versionadded:: 254

.. systemd:option:: root-hash-signature=PATH|base64:BASE64|auto
   :group: fstab-options

   A Base64 string encoding the root hash signature prefixed by "base64:", or an absolute path to a root hash signature file used to verify the root hash (in kernel). If the special string "auto" is specified, the root hash signature is attempted to be read from the udev property "ID_DISSECT_PART_ROOTHASH_SIG=" (in Base64 format) of the data device. This feature requires Linux kernel version 5.4 or more recent.

   .. versionadded:: 248

.. systemd:option:: _netdev
   :group: fstab-options

   Marks this veritysetup device as requiring network. It will be started after the network is available, similarly to :ref:`systemd.mount(5)` units marked with :systemd:option:`_netdev`. The service unit to set up this device will be ordered between :code:`remote-fs-pre.target` and :code:`remote-veritysetup.target`, instead of :code:`veritysetup-pre.target` and :code:`veritysetup.target`.

   Hint: if this device is used for a mount point that is specified in :man-pages:`fstab(5)`, the :systemd:option:`_netdev` option should also be used for the mount point. Otherwise, a dependency loop might be created where the mount point will be pulled in by :code:`local-fs.target`, while the service to configure the network is usually only started *after* the local file system has been mounted. the local file system has been mounted.

   .. versionadded:: 248

.. systemd:option:: noauto
   :group: fstab-options

   This device will not be added to :code:`veritysetup.target`. This means that it will not be automatically enabled on boot, unless something else pulls it in. In particular, if the device is used for a mount point, it'll be enabled automatically during boot, unless the mount point itself is also disabled with :systemd:option:`noauto`.

   .. versionadded:: 248

.. systemd:option:: nofail
   :group: fstab-options

   This device will not be a hard dependency of :code:`veritysetup.target`. It'll still be pulled in and started, but the system will not wait for the device to show up and be enabled, and boot will not fail if this is unsuccessful. Note that other units that depend on the enabled device may still fail. In particular, if the device is used for a mount point, the mount point itself also needs to have the :systemd:option:`nofail` option, or the boot will fail if the device is not enabled successfully.

   .. versionadded:: 248

.. systemd:option:: x-initrd.attach
   :group: fstab-options

   Setup this verity protected block device in the initrd, similarly to :ref:`systemd.mount(5)` units marked with :systemd:option:`x-initrd.mount`.

   Although it is not necessary to mark the mount entry for the root file system with :systemd:option:`x-initrd.mount`, :systemd:option:`x-initrd.attach` is still recommended with the verity protected block device containing the root file system as otherwise systemd will attempt to detach the device during the regular system shutdown while it is still in use. With this option the device will still be detached but later after the root file system is unmounted.

   All other verity protected block devices that contain file systems mounted in the initrd should use this option.

   .. versionadded:: 248

At early boot and when the system manager configuration is reloaded, this file is translated into native systemd units by :ref:`systemd-veritysetup-generator(8)`.

Examples
########

/etc/veritytab example
----------------------

Set up two verity protected block devices. One using device blocks, another using files.

.. code-block:: sh

   usr  PARTUUID=783e45ae-7aa3-484a-beef-a80ff9c19cbb PARTUUID=21dc1dfe-4c33-8b48-98a9-918a22eb3e37 36e3f740ad502e2c25e2a23d9c7c17bf0fdad2300b7580842d4b7ec1fb0fa263 auto
   data /etc/data /etc/hash a5ee4b42f70ae1f46a08a7c92c2e0a20672ad2f514792730f5d49d7606ab8fdf auto
