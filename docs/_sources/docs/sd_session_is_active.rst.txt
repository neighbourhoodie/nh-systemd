Description
###########

:code:`sd_session_is_active()` may be used to determine whether the session identified by the specified session identifier is currently active (i.e. currently in the foreground and available for user input) or not.

:code:`sd_session_is_remote()` may be used to determine whether the session identified by the specified session identifier is a remote session (i.e. its remote host is known) or not.

:code:`sd_session_get_state()` may be used to determine the state of the session identified by the specified session identifier. The following states are currently known: "online" (session logged in, but session not active, i.e. not in the foreground), "active" (session logged in and active, i.e. in the foreground), "closing" (session nominally logged out, but some processes belonging to it are still around). In the future additional states might be defined, client code should be written to be robust in regards to additional state strings being returned. This function is a more generic version of :code:`sd_session_is_active()`. The returned string needs to be freed with the libc :man-pages:`free(3)` call after use.

:code:`sd_session_get_uid()` may be used to determine the user identifier of the Unix user the session identified by the specified session identifier belongs to.

:code:`sd_session_get_username()` may be used to determine the name of the Unix user the session identified by the specified session identifier belongs to. The returned string needs to be freed with the libc :man-pages:`free(3)` call after use.

:code:`sd_session_get_seat()` may be used to determine the seat identifier of the seat the session identified by the specified session identifier belongs to. Note that not all sessions are attached to a seat, this call will fail (returning :code:`-ENODATA`) for them. The returned string needs to be freed with the libc :man-pages:`free(3)` call after use.

:code:`sd_session_get_start_time()` may be used to determine the start time of the session identified by the specified session identifier belongs to. The :code:`usec` is in microseconds since the epoch (:code:`CLOCK_REALTIME`).

:code:`sd_session_get_service()` may be used to determine the name of the service (as passed during PAM session setup) that registered the session identified by the specified session identifier. The returned string needs to be freed with the libc :man-pages:`free(3)` call after use.

:code:`sd_session_get_type()` may be used to determine the type of the session identified by the specified session identifier. The returned string is one of "x11", "wayland", "tty", "mir" or "unspecified" and needs to be freed with the libc :man-pages:`free(3)` call after use.

:code:`sd_session_get_class()` may be used to determine the class of the session identified by the specified session identifier. The returned string is one of "user", "user-early", "user-light", "user-early-light", "user-incomplete", "greeter", "lock-screen", "background", "background-light", "manager" or "manager-early" and needs to be freed with the libc :man-pages:`free(3)` call after use.

:code:`sd_session_get_desktop()` may be used to determine the brand of the desktop running on the session identified by the specified session identifier. This field can be set freely by desktop environments and does not follow any special formatting. However, desktops are strongly recommended to use the same identifiers and capitalization as for :code:`$XDG_CURRENT_DESKTOP`, as defined by the `Desktop Entry Specification <https://standards.freedesktop.org/desktop-entry-spec/latest/>`_. The returned string needs to be freed with the libc :man-pages:`free(3)` call after use.

:code:`sd_session_get_display()` may be used to determine the X11 display of the session identified by the specified session identifier. The returned string needs to be freed with the libc :man-pages:`free(3)` call after use.

:code:`sd_session_get_leader()` may be used to determine the PID of the leader of the session identified by the specified session identifier.

:code:`sd_session_get_remote_host()` may be used to determine the remote hostname of the session identified by the specified session identifier. The returned string needs to be freed with the libc :man-pages:`free(3)` call after use.

:code:`sd_session_get_remote_user()` may be used to determine the remote username of the session identified by the specified session identifier. The returned string needs to be freed with the libc :man-pages:`free(3)` call after use. Note that this value is rarely known to the system, and even then should not be relied on.

:code:`sd_session_get_tty()` may be used to determine the TTY device of the session identified by the specified session identifier. The returned string needs to be freed with the libc :man-pages:`free(3)` call after use.

:code:`sd_session_get_vt()` may be used to determine the VT number of the session identified by the specified session identifier. This function will return an error if the seat does not support VTs.

If the :code:`session` parameter of any of these functions is passed as :code:`NULL`, the operation is executed for the session the calling process is a member of, if there is any.

Return Value
############

If the test succeeds, :code:`sd_session_is_active()` and :code:`sd_session_is_remote()` return a positive integer; if it fails, 0. On success, :code:`sd_session_get_state()`, :code:`sd_session_get_uid()`, :code:`sd_session_get_username()`, :code:`sd_session_get_seat()`, :code:`sd_session_get_service()`, :code:`sd_session_get_type()`, :code:`sd_session_get_class()`, :code:`sd_session_get_display()`, :code:`sd_session_get_leader()`, :code:`sd_session_get_remote_user()`, :code:`sd_session_get_remote_host()` and :code:`sd_session_get_tty()` return 0 or a positive integer. On failure, these calls return a negative errno-style error code.

Errors
######

Returned errors may indicate the following problems:

.. systemd:option:: -ENXIO

   The specified session does not exist.

.. systemd:option:: -ENODATA

   The given field is not specified for the described session.

.. systemd:option:: -EINVAL

   An input parameter was invalid (out of range, or :code:`NULL`, where that is not accepted).

.. systemd:option:: -ENOMEM

   Memory allocation failed.
