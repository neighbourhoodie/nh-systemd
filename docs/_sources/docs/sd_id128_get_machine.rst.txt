Description
###########

:code:`sd_id128_get_machine()` returns the machine ID of the executing host. This reads and parses the :man-pages:`machine-id(5)` file. This function caches the machine ID internally to make retrieving the machine ID a cheap operation. This ID may be used wherever a unique identifier for the local system is needed. However, it is recommended to use this ID as-is only in trusted environments. In untrusted environments it is recommended to derive an application specific ID from this machine ID, in an irreversible (cryptographically secure) way. To make this easy :code:`sd_id128_get_machine_app_specific()` is provided, see below.

:code:`sd_id128_get_app_specific()` returns a machine ID that is a combination of the :code:`base` and :code:`app_id` parameters. Internally, this function calculates HMAC-SHA256 of the :code:`app_id` parameter keyed by the :code:`base` parameter, and truncates this result to fit in sd_id128_t and turns it into a valid Variant 1 Version 4 UUID, in accordance with `RFC 4122 <https://tools.ietf.org/html/rfc4122>`_. Neither of the two input parameters can be calculated from the output parameter :code:`ret`.

:code:`sd_id128_get_machine_app_specific()` is similar to :code:`sd_id128_get_machine()`, but retrieves a machine ID that is specific to the application that is identified by the indicated application ID. It is recommended to use this function instead of :code:`sd_id128_get_machine()` when passing an ID to untrusted environments, in order to make sure that the original machine ID may not be determined externally. This way, the ID used by the application remains stable on a given machine, but cannot be easily correlated with IDs used in other applications on the same machine. The application-specific ID should be generated via a tool like :code:`systemd-id128 new`, and may be compiled into the application. This function will return the same application-specific ID for each combination of machine ID and application ID. Internally, this function calls :code:`sd_id128_get_app_specific()` with the result from :code:`sd_id128_get_machine()` and the :code:`app_id` parameter.

:code:`sd_id128_get_boot()` returns the boot ID of the executing kernel. This reads and parses the :code:`/proc/sys/kernel/random/boot_id` file exposed by the kernel. It is randomly generated early at boot and is unique for every running kernel instance. See :man-pages:`random(4)` for more information. This function also internally caches the returned ID to make this call a cheap operation. It is recommended to use this ID as-is only in trusted environments. In untrusted environments it is recommended to derive an application specific ID using :code:`sd_id128_get_boot_app_specific()`, see below.

:code:`sd_id128_get_boot_app_specific()` is analogous to :code:`sd_id128_get_machine_app_specific()`, but returns an ID that changes between boots. Some machines may be used for a long time without rebooting, hence the boot ID may remain constant for a long time, and has properties similar to the machine ID during that time.

:code:`sd_id128_get_invocation()` returns the invocation ID of the currently executed service. In its current implementation, this tries to read and parse the following: *    The :code:`$INVOCATION_ID` environment variable that the service manager sets when activating a service.

*    An entry in the kernel keyring that the system service manager sets when activating a service.

See :ref:`systemd.exec(5)` for details. The ID is cached internally. In future a different mechanism to determine the invocation ID may be added.

:code:`sd_id128_get_invocation_app_specific()` derives an application-specific ID from the invocation ID.

Note that :code:`sd_id128_get_machine_app_specific()`, :code:`sd_id128_get_boot()`, :code:`sd_id128_get_boot_app_specific()`, :code:`sd_id128_get_invocation()` and :code:`sd_id128_get_invocation_app_specific` always return UUID Variant 1 Version 4 compatible IDs. :code:`sd_id128_get_machine()` will also return a UUID Variant 1 Version 4 compatible ID on new installations but might not on older. It is possible to convert the machine ID non-reversibly into a UUID Variant 1 Version 4 compatible one. For more information, see :man-pages:`machine-id(5)`. It is hence guaranteed that these functions will never return the ID consisting of all zero or all one bits (:code:`SD_ID128_NULL`, :code:`SD_ID128_ALLF`) — with the possible exception of :code:`sd_id128_get_machine()`, as mentioned.

For more information about the "sd_id128_t" type see :ref:`sd-id128(3)`.

Return Value
############

Those calls return 0 on success (in which case :code:`ret` is filled in), or a negative errno-style error code.

Errors
######

Returned errors may indicate the following problems:

.. systemd:option:: -ENOENT

   Returned by :code:`sd_id128_get_machine()` and :code:`sd_id128_get_machine_app_specific()` when :code:`/etc/machine-id` is missing.

   .. versionadded:: 242

.. systemd:option:: -ENOMEDIUM

   Returned by :code:`sd_id128_get_machine()` and :code:`sd_id128_get_machine_app_specific()` when :code:`/etc/machine-id` is empty or all zeros. Also returned by :code:`sd_id128_get_invocation()` when the invocation ID is all zeros.

   .. versionadded:: 242

.. systemd:option:: -ENOPKG

   Returned by :code:`sd_id128_get_machine()` and :code:`sd_id128_get_machine_app_specific()` when the content of :code:`/etc/machine-id` is "uninitialized".

   .. versionadded:: 253

.. systemd:option:: -ENOSYS

   Returned by :code:`sd_id128_get_boot()` and :code:`sd_id128_get_boot_app_specific()` when :code:`/proc/` is not mounted.

   .. versionadded:: 253

.. systemd:option:: -ENXIO

   Returned by :code:`sd_id128_get_invocation()` if no invocation ID is set. Also returned by :code:`sd_id128_get_app_specific()`, :code:`sd_id128_get_machine_app_specific()`, and :code:`sd_id128_get_boot_app_specific()` when the :code:`app_id` parameter is all zeros.

   .. versionadded:: 242

.. systemd:option:: -EUCLEAN

   Returned by any of the functions described here when the configured value has invalid format.

   .. versionadded:: 253

.. systemd:option:: -EPERM

   Requested information could not be retrieved because of insufficient permissions.

   .. versionadded:: 242

Examples
########

Application-specific machine ID
-------------------------------

First, generate the application ID:

.. code-block:: sh

   $ systemd-id128 -p new
   As string:
   c273277323db454ea63bb96e79b53e97
   As UUID:
   c2732773-23db-454e-a63b-b96e79b53e97
   As man:sd-id128(3) macro:
   #define MESSAGE_XYZ SD_ID128_MAKE(c2,73,27,73,23,db,45,4e,a6,3b,b9,6e,79,b5,3e,97)
   ...
