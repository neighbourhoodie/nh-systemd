=========================
systemd-sysctl.service(8)
=========================

Name
####

systemd-sysctl.service, systemd-sysctl — Configure kernel parameters at boot

Synopsis
########

:code:`/usr/lib/systemd/systemd-sysctl [OPTIONS...] [<CONFIGFILE>...]`

:code:`systemd-sysctl.service`

Description
###########

:code:`systemd-sysctl.service` is an early boot service that configures :man-pages:`sysctl(8)` kernel parameters by invoking :code:`/usr/lib/systemd/systemd-sysctl`.

When invoked with no arguments, :code:`/usr/lib/systemd/systemd-sysctl` applies all directives from configuration files listed in :man-pages:`sysctl.d(5)`. When invoked with positional arguments, the configuration specified by the command line arguments is executed. If the string "-" is specified instead of a filename, the configuration is read from standard input. If the argument is a file name (without any slashes), all configuration directories are searched for a matching file and the file found that has the highest priority is executed. If the argument is a path, that file is used directly without searching the configuration directories for any other matching file.

In addition, :code:`--prefix=` option may be used to limit which sysctl settings are applied.

See :man-pages:`sysctl.d(5)` for information about the configuration of sysctl settings. After sysctl configuration is changed on disk, it must be written to the files in :code:`/proc/sys/` before it takes effect. It is possible to update specific settings, or simply to reload all configuration, see Examples below.

Credentials
###########

:code:`systemd-sysctl` supports the service credentials logic as implemented by :code:`ImportCredential=`/:code:`LoadCredential=`/:code:`SetCredential=` (see :ref:`systemd.exec(5)` for details). The following credentials are used when passed in:

.. systemd:option:: sysctl.extra
   :group: system-credentials

   The contents of this credential may contain additional lines to operate on. The credential contents should follow the same format as any other :code:`sysctl.d/` drop-in configuration file. If this credential is passed it is processed after all of the drop-in files read from the file system. The settings configured in the credential hence take precedence over those in the file system.

   .. versionadded:: 252

Note that by default the :code:`systemd-sysctl.service` unit file is set up to inherit the "sysctl.extra" credential from the service manager.

Examples
########

Reset all sysctl settings
-------------------------

.. code-block:: sh

   systemctl restart systemd-sysctl

View coredump handler configuration
-----------------------------------

.. code-block:: sh

   # sysctl kernel.core_pattern
   kernel.core_pattern = |/usr/libexec/abrt-hook-ccpp %s %c %p %u %g %t %P %I

Update coredump handler configuration
-------------------------------------

.. code-block:: sh

   # /usr/lib/systemd/systemd-sysctl --prefix kernel.core_pattern

This searches all the directories listed in :man-pages:`sysctl.d(5)` for configuration files and writes :code:`/proc/sys/kernel/core_pattern`.

Update coredump handler configuration according to a specific file
------------------------------------------------------------------

.. code-block:: sh

   # /usr/lib/systemd/systemd-sysctl 50-coredump.conf

This applies all the settings found in :code:`50-coredump.conf`. Either :code:`/etc/sysctl.d/50-coredump.conf`, or :code:`/run/sysctl.d/50-coredump.conf`, or :code:`/usr/lib/sysctl.d/50-coredump.conf` will be used, in the order of preference.

See :man-pages:`sysctl(8)` for various ways to directly apply sysctl settings.
