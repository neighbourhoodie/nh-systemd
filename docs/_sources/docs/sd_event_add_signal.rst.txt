sd_event_add_signal(3)
======================

Name
####

sd_event_add_signal, sd_event_source_get_signal, sd_event_signal_handler_t, SD_EVENT_SIGNAL_PROCMASK — Add a UNIX process signal event source to an event loop

Synopsis
########

:code:`#include <systemd/sd-event.h>` :code:`:code:`typedef` struct sd_event_source sd_event_source;` :code:`:code:`SD_EVENT_SIGNAL_PROCMASK`` .. code-block::

   typedef int (*sd_event_signal_handler_t)(sd_event_source *s,
	const struct signalfd_siginfo *si,
	void *userdata); .. code-block::

   int sd_event_add_signal(sd_event *event,
	sd_event_source **source,
	int signal,
	sd_event_signal_handler_t handler,
	void *userdata); .. code-block::

   int sd_event_source_get_signal(sd_event_source *source);

Description
###########

:code:`sd_event_add_signal()` adds a new UNIX process signal event source to an event loop. The event loop object is specified in the :code:`event` parameter, and the event source object is returned in the :code:`source` parameter. The :code:`signal` parameter specifies the numeric signal to be handled (see :man-pages:`signal(7)`).

The :code:`handler` parameter is a function to call when the signal is received or :code:`NULL`. The handler function will be passed the :code:`userdata` pointer, which may be chosen freely by the caller. The handler also receives a pointer to a signalfd_siginfo structure containing information about the received signal. See :man-pages:`signalfd(2)` for further information. The handler may return negative to signal an error (see below), other return values are ignored. If :code:`handler` is :code:`NULL`, a default handler that calls :ref:`sd_event_exit(3)` will be used.

Only a single handler may be installed for a specific signal. The signal must be blocked in all threads before this function is called (using :man-pages:`sigprocmask(2)` or :man-pages:`pthread_sigmask(3)`). For convenience, if the special flag :code:`SD_EVENT_SIGNAL_PROCMASK` is ORed into the specified signal the signal will be automatically masked as necessary, for the calling thread. Note that this only works reliably if the signal is already masked in all other threads of the process, or if there are no other threads at the moment of invocation.

By default, the event source is enabled permanently (:code:`SD_EVENT_ON`), but this may be changed with :ref:`sd_event_source_set_enabled(3)`. If the handler function returns a negative error code, it will either be disabled after the invocation, even if the :code:`SD_EVENT_ON` mode was requested before, or it will cause the loop to terminate, see :ref:`sd_event_source_set_exit_on_failure(3)`.

To destroy an event source object use :ref:`sd_event_source_unref(3)`, but note that the event source is only removed from the event loop when all references to the event source are dropped. To make sure an event source does not fire anymore, even if it is still referenced, disable the event source using :ref:`sd_event_source_set_enabled(3)` with :code:`SD_EVENT_OFF`.

If the second parameter of :code:`sd_event_add_signal()` is :code:`NULL` no reference to the event source object is returned. In this case, the event source is considered "floating", and will be destroyed implicitly when the event loop itself is destroyed.

If the :code:`handler` parameter to :code:`sd_event_add_signal()` is :code:`NULL`, and the event source fires, this will be considered a request to exit the event loop. In this case, the :code:`userdata` parameter, cast to an integer, is passed as the exit code parameter to :ref:`sd_event_exit(3)`.

:code:`sd_event_source_get_signal()` returns the configured signal number of an event source created previously with :code:`sd_event_add_signal()`. It takes the event source object as the :code:`source` parameter.

Return Value
############

On success, these functions return 0 or a positive integer. On failure, they return a negative errno-style error code.

Errors
######

Returned errors may indicate the following problems:

.. systemd:option:: -ENOMEM

   Not enough memory to allocate an object.

.. systemd:option:: -EINVAL

   An invalid argument has been passed.

.. systemd:option:: -EBUSY

   A handler is already installed for this signal or the signal was not blocked previously.

.. systemd:option:: -ESTALE

   The event loop is already terminated.

.. systemd:option:: -ECHILD

   The event loop has been created in a different process, library or module instance.

.. systemd:option:: -EDOM

   The passed event source is not a signal event source.
