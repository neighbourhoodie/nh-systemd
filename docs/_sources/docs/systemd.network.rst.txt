==================
systemd.network(5)
==================

Name
####

systemd.network — Network configuration

Synopsis
########

:code:`network.network`

Description
###########

A plain ini-style text file that encodes network configuration for matching network interfaces, used by :ref:`systemd-networkd(8)`. See :ref:`systemd.syntax(7)` for a general description of the syntax.

The main network file must have the extension :code:`.network`; other extensions are ignored. Networks are applied to links whenever the links appear.

Note that not all settings and configurations can be made with :code:`.network` files, and that it may be necessary to use :ref:`systemd.link(5)`) or :ref:`systemd.netdev(5)`) files in conjunction with :code:`.network` files when working with physical and virtual network devices respectively.

The :code:`.network` files are read from the files located in the system network directories :code:`/usr/lib/systemd/network` and :code:`/usr/local/lib/systemd/network` [#usrlocalfootnote]_, the volatile runtime network directory :code:`/run/systemd/network` and the local administration network directory :code:`/etc/systemd/network`. All configuration files are collectively sorted and processed in alphanumeric order, regardless of the directories in which they live. However, files with identical filenames replace each other. It is recommended that each filename is prefixed with a number smaller than "70" (e.g. :code:`10-eth0.network`). Otherwise, the default :code:`.network` files or those generated by :ref:`systemd-network-generator.service(8)` may take precedence over user configured files. Files in :code:`/etc/` have the highest priority, files in :code:`/run/` take precedence over files with the same name under :code:`/usr/`. This can be used to override a system-supplied configuration file with a local file if needed. As a special case, an empty file (file size 0) or symlink with the same name pointing to :code:`/dev/null` disables the configuration file entirely (it is "masked").

Along with the network file :code:`foo.network`, a "drop-in" directory :code:`foo.network.d/` may exist. All files with the suffix ".conf" from this directory will be merged in the alphanumeric order and parsed after the main file itself has been parsed. This is useful to alter or add configuration settings, without having to modify the main configuration file. Each drop-in file must have appropriate section headers.

In addition to :code:`/etc/systemd/network`, drop-in ".d" directories can be placed in :code:`/usr/lib/systemd/network` or :code:`/run/systemd/network` directories. Drop-in files in :code:`/etc/` take precedence over those in :code:`/run/` which in turn take precedence over those in :code:`/usr/lib/`. Drop-in files under any of these directories take precedence over the main network file wherever located.

[Match] Section Options
#######################

The network file contains a \[Match] section, which determines if a given network file may be applied to a given interface; and a \[Network] section specifying how the interface should be configured. The first (in alphanumeric order) of the network files that matches a given interface is applied, all later files are ignored, even if they match as well.

Note that any network interfaces that have the :code:`ID_NET_MANAGED_BY=` udev property set will never be matched by any .network files – unless the property's value is the string "io.systemd.Network" – even if the \[Match] section would otherwise match. This may be used to exclude specific network interfaces from :ref:`systemd-networkd(8)`'s management, while keeping the \[Match] section generic. The :code:`ID_NET_MANAGED_BY=` property thus declares intended *ownership* of the device, and permits ensuring that concurrent network management implementations do not compete for management of specific devices. of the device, and permits ensuring that concurrent network management implementations do not compete for management of specific devices.

A network file is said to match a network interface if all matches specified by the \[Match] section are satisfied. When a network file does not contain valid settings in \[Match] section, then the file will match all interfaces and :code:`systemd-networkd` warns about that. Hint: to avoid the warning and to make it clear that all interfaces shall be matched, add the following:

.. code-block:: sh

   Name=*

[Link] Section Options
######################

The \[Link] section accepts the following keys:

.. systemd:option:: MACAddress=
   :group: network-directives

   The hardware address to set for the device.

   .. versionadded:: 218

.. systemd:option:: MTUBytes=
   :group: network-directives

   The maximum transmission unit in bytes to set for the device. The usual suffixes K, M, G, are supported and are understood to the base of 1024.

   Note that if IPv6 is enabled on the interface, and the MTU is chosen below 1280 (the minimum MTU for IPv6) it will automatically be increased to this value.

   .. versionadded:: 218

.. systemd:option:: ARP=
   :group: network-directives

   Takes a boolean. If set to true, the IPv4 ARP (low-level Address Resolution Protocol) and IPv6 NDP (Neighbor Discovery Protocol) for this interface are enabled. For example, disabling ARP is useful when creating multiple MACVLAN or VLAN virtual interfaces atop a single lower-level physical interface, which will then only serve as a link/"bridge" device aggregating traffic to the same physical link and not participate in the network otherwise. Defaults to unset, and enabled when the IPv4 link-local addressing is enabled in :systemd:var:`LinkLocalAddressing=` or an IPv4 address with :systemd:var:`DuplicateAddressDetection=` enabled is requested. Otherwise, the kernel's default will be used.

   .. versionadded:: 232

.. systemd:option:: Multicast=
   :group: network-directives

   Takes a boolean. If set to true, the multicast flag on the device is enabled. Defaults to unset and the flag is unchanged. When disabled, :systemd:var:`IPv6AcceptRA=` and :systemd:var:`IPv6SendRA=` cannot be enabled.

   .. versionadded:: 239

.. systemd:option:: AllMulticast=
   :group: network-directives

   Takes a boolean. If set to true, the driver retrieves all multicast packets from the network. This happens when multicast routing is enabled. Defaults to unset.

   .. versionadded:: 239

.. systemd:option:: Promiscuous=
   :group: network-directives

   Takes a boolean. If set to true, promiscuous mode of the interface is enabled. Defaults to unset.

   If this is set to false for the underlying link of a "passthru" mode MACVLAN/MACVTAP, the virtual interface will be created with the "nopromisc" flag set.

   .. versionadded:: 248

.. systemd:option:: Unmanaged=
   :group: network-directives

   Takes a boolean. When "yes", no attempts are made to bring up or configure matching links, equivalent to when there are no matching network files. Defaults to "no".

   This is useful for preventing later matching network files from interfering with certain interfaces that are fully controlled by other applications.

   .. versionadded:: 233

.. systemd:option:: Group=
   :group: network-directives

   Link groups are similar to port ranges found in managed switches. When network interfaces are added to a numbered group, operations on all the interfaces from that group can be performed at once. Takes an unsigned integer in the range 0…2147483647. Defaults to unset.

   .. versionadded:: 246

.. systemd:option:: RequiredForOnline=
   :group: network-directives

   Takes a boolean, a minimum operational state (e.g., "carrier"), or a range of operational state separated with a colon (e.g., "degraded:routable"). Please see :man-pages:`networkctl(1)` for possible operational states. When "yes", the network is deemed required when determining whether the system is online (including when running :code:`systemd-networkd-wait-online`). When "no", the network is ignored when determining the online state. When a minimum operational state and an optional maximum operational state are set, :code:`systemd-networkd-wait-online` deems that the interface is online when the operational state is in the specified range.

   Defaults to "yes" when :systemd:var:`ActivationPolicy=` is not set, or set to "up", "always-up", or "bound". Defaults to "no" when :systemd:var:`ActivationPolicy=` is set to "manual" or "down". This is forced to "no" when :systemd:var:`ActivationPolicy=` is set to "always-down".

   The network will be brought up normally (as configured by :systemd:var:`ActivationPolicy=`), but in the event that there is no address being assigned by DHCP or the cable is not plugged in, the link will simply remain offline and be skipped automatically by :code:`systemd-networkd-wait-online` if "RequiredForOnline=no".

   The boolean value "yes" is translated as follows; .. systemd:option:: CAN devices
      :group: network-directives

         "carrier",

         .. versionadded:: 256

   .. systemd:option:: Master devices, e.g. bond or bridge
      :group: network-directives

         "degraded-carrier" with :systemd:var:`RequiredFamilyForOnline=any`,

         .. versionadded:: 256

   .. systemd:option:: Bonding port interfaces
      :group: network-directives

         "enslaved",

         .. versionadded:: 256

   .. systemd:option:: Other interfaces
      :group: network-directives

         "degraded".

         .. versionadded:: 236

   This setting can be overridden by the command line option for :code:`systemd-networkd-wait-online`. See :ref:`systemd-networkd-wait-online.service(8)` for more details.

   .. versionadded:: 236

.. systemd:option:: RequiredFamilyForOnline=
   :group: network-directives

   Takes an address family. When specified, an IP address in the given family is deemed required when determining whether the link is online (including when running :code:`systemd-networkd-wait-online`). Takes one of "ipv4", "ipv6", "both", or "any". Defaults to "no". Note that this option has no effect if "RequiredForOnline=no".

   .. versionadded:: 249

.. systemd:option:: ActivationPolicy=
   :group: network-directives

   Specifies the policy for :code:`systemd-networkd` managing the link administrative state. Specifically, this controls how :code:`systemd-networkd` changes the network device's "IFF_UP" flag, which is sometimes controlled by system administrators by running e.g., :code:`ip link set dev eth0 up` or :code:`ip link set dev eth0 down`, and can also be changed with :code:`networkctl up eth0` or :code:`networkctl down eth0`.

   Takes one of "up", "always-up", "manual", "always-down", "down", or "bound". When "manual", :code:`systemd-networkd` will not change the link's admin state automatically; the system administrator must bring the interface up or down manually, as desired. When "up" (the default) or "always-up", or "down" or "always-down", :code:`systemd-networkd` will set the link up or down, respectively, when the interface is (re)configured. When "always-up" or "always-down", :code:`systemd-networkd` will set the link up or down, respectively, any time :code:`systemd-networkd` detects a change in the administrative state. When :systemd:var:`BindCarrier=` is also set, this is automatically set to "bound" and any other value is ignored.

   When the policy is set to "down" or "manual", the default value of :systemd:var:`RequiredForOnline=` is "no". When the policy is set to "always-down", the value of :systemd:var:`RequiredForOnline=` forced to "no".

   The administrative state is not the same as the carrier state, so using "always-up" does not mean the link will never lose carrier. The link carrier depends on both the administrative state as well as the network device's physical connection. However, to avoid reconfiguration failures, when using "always-up", :systemd:var:`IgnoreCarrierLoss=` is forced to true.

   .. versionadded:: 248

[Network] Section Options
#########################

The \[Network] section accepts the following keys:

.. systemd:option:: Description=
   :group: network-directives

   A description of the device. This is only used for presentation purposes.

   .. versionadded:: 211

.. systemd:option:: DHCP=
   :group: network-directives

   Enables DHCPv4 and/or DHCPv6 client support. Accepts "yes", "no", "ipv4", or "ipv6". Defaults to "no".

   Note that DHCPv6 will by default be triggered by Router Advertisements, if reception is enabled, regardless of this parameter. By explicitly enabling DHCPv6 support here, the DHCPv6 client will be started in the mode specified by the :systemd:var:`WithoutRA=` setting in the \[DHCPv6] section, regardless of the presence of routers on the link, or what flags the routers pass. See :systemd:var:`IPv6AcceptRA=`.

   Furthermore, note that by default the domain name specified through DHCP is not used for name resolution. See option :systemd:option:`UseDomains=` below.

   See the \[DHCPv4] or \[DHCPv6] sections below for further configuration options for the DHCP client support.

   .. versionadded:: 211

.. systemd:option:: DHCPServer=
   :group: network-directives

   Takes a boolean. If set to "yes", DHCPv4 server will be started. Defaults to "no". Further settings for the DHCP server may be set in the \[DHCPServer] section described below.

   Even if this is enabled, the DHCP server will not be started automatically and wait for the persistent storage being ready to load/save leases in the storage, unless :systemd:var:`RelayTarget=` or :systemd:var:`PersistLeases=no/runtime` are specified in the \[DHCPServer] section. It will be started after :code:`systemd-networkd-persistent-storage.service` is started, which calls :code:`networkctl persistent-storage yes`. See :man-pages:`networkctl(1)` for more details.

   .. versionadded:: 215

.. systemd:option:: LinkLocalAddressing=
   :group: network-directives

   Enables link-local address autoconfiguration. Accepts a boolean, :systemd:option:`ipv4`, and :systemd:option:`ipv6`. An IPv6 link-local address is configured when :systemd:option:`yes` or :systemd:option:`ipv6`. An IPv4 link-local address is configured when :systemd:option:`yes` or :systemd:option:`ipv4` and when DHCPv4 autoconfiguration has been unsuccessful for some time. (IPv4 link-local address autoconfiguration will usually happen in parallel with repeated attempts to acquire a DHCPv4 lease).

   Defaults to :systemd:option:`no` when :systemd:var:`KeepMaster=` or :systemd:var:`Bridge=` is set or when the specified :systemd:var:`MACVLAN=`/:systemd:var:`MACVTAP=` has :systemd:var:`Mode=passthru`, or :systemd:option:`ipv6` otherwise.

   When IPv4 link-local addressing is enabled, :systemd:var:`ARP=` is enabled unless if it is explicitly configured.

   .. versionadded:: 219

.. systemd:option:: IPv6LinkLocalAddressGenerationMode=
   :group: network-directives

   Specifies how IPv6 link-local address is generated. Takes one of "eui64", "none", "stable-privacy" and "random". When unset, "stable-privacy" is used if :systemd:var:`IPv6StableSecretAddress=` is specified, and if not, "eui64" is used. Note that if :systemd:var:`LinkLocalAddressing=` is "no" or "ipv4", then :systemd:var:`IPv6LinkLocalAddressGenerationMode=` will be ignored. Also, even if :systemd:var:`LinkLocalAddressing=` is "yes" or "ipv6", setting :systemd:var:`IPv6LinkLocalAddressGenerationMode=none` disables to configure an IPv6 link-local address.

   .. versionadded:: 246

.. systemd:option:: IPv6StableSecretAddress=
   :group: network-directives

   Takes an IPv6 address. The specified address will be used as a stable secret for generating IPv6 link-local address. If this setting is specified, and :systemd:var:`IPv6LinkLocalAddressGenerationMode=` is unset, then :systemd:var:`IPv6LinkLocalAddressGenerationMode=stable-privacy` is implied. If this setting is not specified, and "stable-privacy" is set to :systemd:var:`IPv6LinkLocalAddressGenerationMode=`, then a stable secret address will be generated from the local machine ID and the interface name.

   .. versionadded:: 249

.. systemd:option:: IPv4LLStartAddress=
   :group: network-directives

   Specifies the first IPv4 link-local address to try. Takes an IPv4 address for example 169.254.1.2, from the link-local address range: 169.254.0.0/16 except for 169.254.0.0/24 and 169.254.255.0/24. This setting may be useful if the device should always have the same address as long as there is no address conflict. When unset, a random address will be automatically selected. Defaults to unset.

   .. versionadded:: 252

.. systemd:option:: IPv4LLRoute=
   :group: network-directives

   Takes a boolean. If set to true, sets up the route needed for non-IPv4LL hosts to communicate with IPv4LL-only hosts. Defaults to false.

   .. versionadded:: 216

.. systemd:option:: DefaultRouteOnDevice=
   :group: network-directives

   Takes a boolean. If set to true, sets up the IPv4 default route bound to the interface. Defaults to false. This is useful when creating routes on point-to-point interfaces. This is equivalent to e.g. the following,

     .. code-block:: sh

        ip route add default dev veth99

   or,

     .. code-block:: sh

        [Route]
        Gateway=0.0.0.0

   Currently, there are no way to specify e.g., the table for the route configured by this setting. To configure the default route with such an additional property, please use the following instead:

     .. code-block:: sh

        [Route]
        Gateway=0.0.0.0
        Table=1234

   If you'd like to create an IPv6 default route bound to the interface, please use the following:

     .. code-block:: sh

        [Route]
        Gateway=::
        Table=1234

   .. versionadded:: 243

.. systemd:option:: LLMNR=
   :group: network-directives

   Takes a boolean or "resolve". When true, enables `Link-Local Multicast Name Resolution <https://tools.ietf.org/html/rfc4795>`_ on the link. When set to "resolve", only resolution is enabled, but not host registration and announcement. Defaults to true. This setting is read by :ref:`systemd-resolved.service(8)`.

   .. versionadded:: 216

.. systemd:option:: MulticastDNS=
   :group: network-directives

   Takes a boolean or "resolve". When true, enables `Multicast DNS <https://tools.ietf.org/html/rfc6762>`_ support on the link. When set to "resolve", only resolution is enabled, but not host or service registration and announcement. Defaults to false. This setting is read by :ref:`systemd-resolved.service(8)`.

   .. versionadded:: 229

.. systemd:option:: DNSOverTLS=
   :group: network-directives

   Takes a boolean or "opportunistic". When true, enables `DNS-over-TLS <https://tools.ietf.org/html/rfc7858>`_ support on the link. When set to "opportunistic", compatibility with non-DNS-over-TLS servers is increased, by automatically turning off DNS-over-TLS servers in this case. This option defines a per-interface setting for :man-pages:`resolved.conf(5)`'s global :systemd:var:`DNSOverTLS=` option. Defaults to unset, and the global setting will be used. This setting is read by :ref:`systemd-resolved.service(8)`.

   .. versionadded:: 239

.. systemd:option:: DNSSEC=
   :group: network-directives

   Takes a boolean or "allow-downgrade". When true, enables `DNSSEC <https://tools.ietf.org/html/rfc4033>`_ DNS validation support on the link. When set to "allow-downgrade", compatibility with non-DNSSEC capable networks is increased, by automatically turning off DNSSEC in this case. This option defines a per-interface setting for :man-pages:`resolved.conf(5)`'s global :systemd:var:`DNSSEC=` option. Defaults to unset, and the global setting will be used. This setting is read by :ref:`systemd-resolved.service(8)`.

   .. versionadded:: 229

.. systemd:option:: DNSSECNegativeTrustAnchors=
   :group: network-directives

   A space-separated list of DNSSEC negative trust anchor domains. If specified and DNSSEC is enabled, look-ups done via the interface's DNS server will be subject to the list of negative trust anchors, and not require authentication for the specified domains, or anything below it. Use this to disable DNSSEC authentication for specific private domains, that cannot be proven valid using the Internet DNS hierarchy. Defaults to the empty list. This setting is read by :ref:`systemd-resolved.service(8)`.

   .. versionadded:: 229

.. systemd:option:: LLDP=
   :group: network-directives

   Controls support for Ethernet LLDP packet reception. LLDP is a link-layer protocol commonly implemented on professional routers and bridges which announces which physical port a system is connected to, as well as other related data. Accepts a boolean or the special value "routers-only". When true, incoming LLDP packets are accepted and a database of all LLDP neighbors maintained. If "routers-only" is set only LLDP data of various types of routers is collected and LLDP data about other types of devices ignored (such as stations, telephones and others). If false, LLDP reception is disabled. Defaults to "routers-only". Use :man-pages:`networkctl(1)` to query the collected neighbor data. LLDP is only available on Ethernet links. See :systemd:var:`EmitLLDP=` below for enabling LLDP packet emission from the local system.

   .. versionadded:: 219

.. systemd:option:: EmitLLDP=
   :group: network-directives

   Controls support for Ethernet LLDP packet emission. Accepts a boolean parameter or the special values "nearest-bridge", "non-tpmr-bridge" and "customer-bridge". Defaults to false, which turns off LLDP packet emission. If not false, a short LLDP packet with information about the local system is sent out in regular intervals on the link. The LLDP packet will contain information about the local hostname, the local machine ID (as stored in :man-pages:`machine-id(5)`) and the local interface name, as well as the pretty hostname of the system (as set in :man-pages:`machine-info(5)`). LLDP emission is only available on Ethernet links. Note that this setting passes data suitable for identification of host to the network and should thus not be enabled on untrusted networks, where such identification data should not be made available. Use this option to permit other systems to identify on which interfaces they are connected to this system. The three special values control propagation of the LLDP packets. The "nearest-bridge" setting permits propagation only to the nearest connected bridge, "non-tpmr-bridge" permits propagation across Two-Port MAC Relays, but not any other bridges, and "customer-bridge" permits propagation until a customer bridge is reached. For details about these concepts, see `IEEE 802.1AB-2016 <https://standards.ieee.org/findstds/standard/802.1AB-2016.html>`_. Note that configuring this setting to true is equivalent to "nearest-bridge", the recommended and most restricted level of propagation. See :systemd:var:`LLDP=` above for an option to enable LLDP reception.

   .. versionadded:: 230

.. systemd:option:: BindCarrier=
   :group: network-directives

   A link name or a list of link names. When set, controls the behavior of the current link. When all links in the list are in an operational down state, the current link is brought down. When at least one link has carrier, the current interface is brought up.

   This forces :systemd:var:`ActivationPolicy=` to be set to "bound".

   .. versionadded:: 220

.. systemd:option:: Address=
   :group: network-directives

   A static IPv4 or IPv6 address and its prefix length, separated by a "/" character. Specify this key more than once to configure several addresses. The format of the address must be as described in :man-pages:`inet_pton(3)`. This is a short-hand for an \[Address] section only containing an Address key (see below). This option may be specified more than once.

   If the specified address is "0.0.0.0" (for IPv4) or "::" (for IPv6), a new address range of the requested size is automatically allocated from a system-wide pool of unused ranges. Note that the prefix length must be equal or larger than 8 for IPv4, and 64 for IPv6. The allocated range is checked against all current network interfaces and all known network configuration files to avoid address range conflicts. The default system-wide pool consists of 192.168.0.0/16, 172.16.0.0/12 and 10.0.0.0/8 for IPv4, and fd00::/8 for IPv6. This functionality is useful to manage a large number of dynamically created network interfaces with the same network configuration and automatic address range assignment.

   If an IPv4 link-local address (169.254.0.0/16) is specified, IPv4 Address Conflict Detection (`RFC 5227 <https://tools.ietf.org/html/rfc5227>`_) is enabled for the address. To assign an IPv4 link-local address without IPv4 Address Conflict Detection, please use \[Address] section to configure the address and disable :systemd:var:`DuplicateAddressDetection=`.

     .. code-block:: sh

        [Address]
        Address=169.254.10.1/24
        DuplicateAddressDetection=none

   If an empty string is specified, then the all previous assignments in both \[Network] and \[Address] sections are cleared.

   .. versionadded:: 211

.. systemd:option:: Gateway=
   :group: network-directives

   The gateway address, which must be in the format described in :man-pages:`inet_pton(3)`. This is a short-hand for a \[Route] section only containing a :systemd:var:`Gateway=` key. This option may be specified more than once.

.. systemd:option:: DNS=
   :group: network-directives

   A DNS server address, which must be in the format described in :man-pages:`inet_pton(3)`. This option may be specified more than once. Each address can optionally take a port number separated with ":", a network interface name or index separated with "%", and a Server Name Indication (SNI) separated with "#". When IPv6 address is specified with a port number, then the address must be in the square brackets. That is, the acceptable full formats are "111.222.333.444:9953%ifname#example.com" for IPv4 and "[1111:2222::3333]:9953%ifname#example.com" for IPv6. If an empty string is assigned, then the all previous assignments are cleared. This setting is read by :ref:`systemd-resolved.service(8)`.

.. systemd:option:: UseDomains=
   :group: network-directives

   Specifies the protocol-independent default value for the same settings in \[IPv6AcceptRA], \[DHCPv4], and \[DHCPv6] sections below. Takes a boolean, or the special value :systemd:option:`route`. See also the same setting in \[DHCPv4] below. Defaults to unset.

   .. versionadded:: 256

.. systemd:option:: Domains=
   :group: network-directives

   A whitespace-separated list of domains which should be resolved using the DNS servers on this link. Each item in the list should be a domain name, optionally prefixed with a tilde ("~"). The domains with the prefix are called "routing-only domains". The domains without the prefix are called "search domains" and are first used as search suffixes for extending single-label hostnames (hostnames containing no dots) to become fully qualified domain names (FQDNs). If a single-label hostname is resolved on this interface, each of the specified search domains are appended to it in turn, converting it into a fully qualified domain name, until one of them may be successfully resolved.

   Both "search" and "routing-only" domains are used for routing of DNS queries: look-ups for hostnames ending in those domains (hence also single label names, if any "search domains" are listed), are routed to the DNS servers configured for this interface. The domain routing logic is particularly useful on multi-homed hosts with DNS servers serving particular private DNS zones on each interface.

   The "routing-only" domain "~." (the tilde indicating definition of a routing domain, the dot referring to the DNS root domain which is the implied suffix of all valid DNS names) has special effect. It causes all DNS traffic which does not match another configured domain routing entry to be routed to DNS servers specified for this interface. This setting is useful to prefer a certain set of DNS servers if a link on which they are connected is available.

   This setting is read by :ref:`systemd-resolved.service(8)`. "Search domains" correspond to the :systemd:var:`domain` and :systemd:var:`search` entries in :man-pages:`resolv.conf(5)`. Domain name routing has no equivalent in the traditional glibc API, which has no concept of domain name servers limited to a specific link.

   .. versionadded:: 216

.. systemd:option:: DNSDefaultRoute=
   :group: network-directives

   Takes a boolean argument. If true, this link's configured DNS servers are used for resolving domain names that do not match any link's configured :systemd:var:`Domains=` setting. If false, this link's configured DNS servers are never used for such domains, and are exclusively used for resolving names that match at least one of the domains configured on this link. If not specified, defaults to an automatic mode: queries not matching any link's configured domains will be routed to this link if it has no routing-only domains configured.

.. systemd:option:: IPv6PrivacyExtensions=
   :group: network-directives

Takes a boolean or the special values "prefer-public" and "kernel". When true, enables the privacy extensions and prefers temporary addresses over public addresses. When "prefer-public", enables the privacy extensions, but prefers public addresses over temporary addresses. When false, the privacy extensions remain disabled. When "kernel", the kernel's default setting will be left in place. When unspecified, the value specified in the same setting in :man-pages:`networkd.conf(5)`, which defaults to "no", will be used.

.. systemd:option:: IPv6AcceptRA=
   :group: network-directives

   Takes a boolean. Controls IPv6 Router Advertisement (RA) reception support for the interface. If true, RAs are accepted; if false, RAs are ignored. When RAs are accepted, they may trigger the start of the DHCPv6 client if the relevant flags are set in the RA data, or if no routers are found on the link.

   This cannot be enabled on devices aggregated in a bond device, or when IPv6 link-local addressing (see :systemd:var:`LinkLocalAddressing=`) or multicasting (see :systemd:var:`Multicast=`) is disabled. Note, multicasting is disabled by default for some configurations, e.g. bridge ports. Hence, in that case :systemd:var:`Multicast=` needs to be explicitly enabled to make this feature usable. When :systemd:var:`IPv6SendRA=`, :systemd:var:`IPv6Forwarding=`, or :systemd:var:`IPMasquerade=` is enabled, this feature is disabled by default, but can be overridden by explicitly enabling this setting. Note, :systemd:var:`IPv6Forwarding=` may be indirectly enabled when the global setting with the same name is enabled, or when :systemd:var:`IPMasquerade=` is enabled on *any other interfaces*\. See also . See also :systemd:var:`IPv6Forwarding=` and :systemd:var:`IPMasquerade=` for more details. Enabled by default otherwise.

   Further settings for the IPv6 RA support may be configured in the \[IPv6AcceptRA] section, see below.

   Also see `IP Sysctl <https://docs.kernel.org/networking/ip-sysctl.html>`_ in the kernel documentation regarding "accept_ra", but note that systemd's setting of :systemd:constant:`1` (i.e. true) corresponds to kernel's setting of :systemd:constant:`2`.

   Note that kernel's implementation of the IPv6 RA protocol is always disabled, regardless of this setting. If this option is enabled, a userspace implementation of the IPv6 RA protocol is used, and the kernel's own implementation remains disabled, since :code:`systemd-networkd` needs to know all details supplied in the advertisements, and these are not available from the kernel if the kernel's own implementation is used.

.. systemd:option:: IPv4DuplicateAddressDetectionTimeoutSec=
   :group: network-directives

   Configures the maximum timeout for IPv4 Duplicate Address Detection (RFC 5227). Must be a value between 1 millisecond and 60 seconds. If set, Duplicate Address Detection takes a randomized time between 57% (4/7) and 100% of the given value. If unset, defaults to 200 milliseconds.

   .. versionadded:: 258

.. systemd:option:: IPv4ReversePathFilter=
   :group: network-directives

   Configure IPv4 Reverse Path Filtering. If enabled, when an IPv4 packet is received, the machine will first check whether the *source* of the packet would be routed through the interface it came in. If there is no route to the source on that interface, the machine will drop the packet. Takes one of of the packet would be routed through the interface it came in. If there is no route to the source on that interface, the machine will drop the packet. Takes one of "no", "strict", or "loose". When "no", no source validation will be done. When "strict", each incoming packet is tested against the FIB and if the incoming interface is not the best reverse path, the packet check will fail. By default, failed packets are discarded. When "loose", each incoming packet's source address is tested against the FIB. The packet is dropped only if the source address is not reachable via any interface on that router. See `RFC 3704 <https://tools.ietf.org/html/rfc1027>`_. When unset, the kernel's default will be used.

   .. versionadded:: 255

.. systemd:option:: MulticastIGMPVersion=
   :group: network-directives

   Configures IPv4 Multicast IGMP Version to be used, and controls the value of :code:`/proc/sys/net/ipv4/conf/INTERFACE/force_igmp_version`. Takes one of "no", "v1", "v2", or "v3". When "no", no enforcement of an IGMP version is applied. IGMPv1/v2 fallbacks are allowed, and :code:`systemd-networkd` will return to IGMPv3 mode after all IGMPv1/v2 Querier Present timers have expired. When "v1", use of IGMP version 1 is enforced. An IGMPv1 report will be returned even if IGMPv2/v3 queries are received. When "v2", use of IGMP version 2 is enforced. An IGMPv2 report will be returned if an IGMPv2/v3 query is received. :code:`systemd-networkd` will fall back to IGMPv1 if an IGMPv1 query is received. When "v3", use of IGMP version 3 is enforced, and the response is the same as with "no". Defaults to unset — the sysctl is not set.

.. systemd:option:: IPv4ProxyARP=

By "faking" its identity, the router accepts responsibility for routing packets to the "real" destination. See `RFC 1027 <https://tools.ietf.org/html/rfc1027>`_. .. systemd:option:: IPv4ProxyARPPrivateVLAN=

   See `RFC 3069 <https://tools.ietf.org/html/rfc3069>`_. When unset, the kernel's default will be used.

.. systemd:option:: IPv6ProxyNDP=
   :group: network-directives

   Takes a boolean. Configures proxy NDP for IPv6. Proxy NDP (Neighbor Discovery Protocol) is a technique for IPv6 to allow routing of addresses to a different destination when peers expect them to be present on a certain physical link. In this case, a router answers Neighbour Advertisement messages intended for another machine by offering its own MAC address as destination. Unlike proxy ARP for IPv4, it is not enabled globally, but will only send Neighbour Advertisement messages for addresses in the IPv6 neighbor proxy table, which can also be shown by :code:`ip -6 neighbour show proxy`. :code:`systemd-networkd` will control the per-interface \`proxy_ndp` switch for each configured interface depending on this option. When unset, the kernel's default will be used.

   .. versionadded:: 234

.. systemd:option:: IPv6ProxyNDPAddress=

This setting implies :systemd:var:`IPv6ProxyNDP=yes` but has no effect if :systemd:var:`IPv6ProxyNDP=` has been set to false. When unset, the kernel's default will be used.

.. systemd:option:: ConfigureWithoutCarrier=
   :group: network-directives

   Takes a boolean. Allows :code:`systemd-networkd` to configure a specific link even if it has no carrier. Defaults to false. If enabled, and the :systemd:var:`IgnoreCarrierLoss=` setting is not explicitly set, then it is enabled as well.

   With this enabled, to make the interface enter the "configured" state, which is required to make :code:`systemd-networkd-wait-online` work properly for the interface, all dynamic address configuration mechanisms like :systemd:var:`DHCP=` and :systemd:var:`IPv6AcceptRA=` (which is enabled by default in most cases) need to be disabled. Also, :systemd:var:`DuplicateAddressDetection=` (which is enabled by default for IPv4 link-local addresses and all IPv6 addresses) needs to be disabled for all static address configurations. Otherwise, without carrier, the interface will be stuck in the "configuring" state, and :code:`systemd-networkd-wait-online` for the interface will timeout. Also, it is recommended to set :systemd:var:`RequiredForOnline=no-carrier` to make :code:`systemd-networkd-wait-online` work for the interface.

   .. versionadded:: 235

.. systemd:option:: IgnoreCarrierLoss=
   :group: network-directives

   Takes a boolean or a timespan. When true, :code:`systemd-networkd` retains both the static and dynamic configuration of the interface even if its carrier is lost. When false, :code:`systemd-networkd` drops both the static and dynamic configuration of the interface. When a timespan is specified, :code:`systemd-networkd` waits for the specified timespan, and ignores the carrier loss if the link regain its carrier within the timespan. Setting 0 seconds is equivalent to "no", and "infinite" is equivalent to "yes".

   Setting a finite timespan may be useful when e.g. in the following cases: *       A wireless interface connecting to a network which has multiple access points with the same SSID.

   *       Enslaving a wireless interface to a bond interface, which may disconnect from the connected access point and causes its carrier to be lost.

   *       The driver of the interface resets when the MTU is changed.

   When :systemd:var:`Bond=` is specified to a wireless interface, defaults to 3 seconds. When the DHCPv4 client is enabled and :systemd:var:`UseMTU=` in the \[DHCPv4] section enabled, defaults to 5 seconds. Otherwise, defaults to the value specified with :systemd:var:`ConfigureWithoutCarrier=`. When :systemd:var:`ActivationPolicy=` is set to "always-up", this is forced to "yes", and ignored any user specified values.

   .. versionadded:: 242

.. systemd:option:: KeepConfiguration=
   :group: network-directives

   Takes a boolean or one of "static", "dynamic-on-stop", and "dynamic". When "static", :code:`systemd-networkd` will not drop statically configured addresses and routes on starting up process. When "dynamic-on-stop", the dynamically configured addresses and routes, such as DHCPv4, DHCPv6, SLAAC, and IPv4 link-local address, will not be dropped when :code:`systemd-networkd` is being stopped. When "dynamic", the dynamically configured addresses and routes will never be dropped, and the lifetime of DHCPv4 leases will be ignored. This is contrary to the DHCP specification, but may be the best choice if, e.g., the root filesystem relies on this connection. The setting "dynamic" implies "dynamic-on-stop", and "yes" implies "dynamic" and "static". Defaults to "dynamic-on-stop" when :code:`systemd-networkd` is running in initrd, "yes" when the root filesystem is a network filesystem, and "no" otherwise.

[Address] Section Options
#########################

An \[Address] section accepts the following keys. Specify several \[Address] sections to configure several addresses.

.. systemd:option:: Address=
   :group: network-directives

   As in the \[Network] section. This setting is mandatory. Each \[Address] section can contain one :systemd:var:`Address=` setting.

   .. versionadded:: 211

.. systemd:option:: Peer=
   :group: network-directives

   The peer address in a point-to-point connection. Accepts the same format as the :systemd:var:`Address=` setting.

   .. versionadded:: 216

.. systemd:option:: Broadcast=
   :group: network-directives

   Takes an IPv4 address or boolean value. The address must be in the format described in :man-pages:`inet_pton(3)`. If set to true, then the IPv4 broadcast address will be derived from the :systemd:var:`Address=` setting. If set to false, then the broadcast address will not be set. Defaults to true, except for wireguard interfaces, where it defaults to false.

   .. versionadded:: 211

.. systemd:option:: Label=
   :group: network-directives

   Specifies the label for the IPv4 address. The label must be a 7-bit ASCII string with a length of 1…15 characters. Defaults to unset.

   .. versionadded:: 211

.. systemd:option:: PreferredLifetime=
   :group: network-directives

   Allows the default "preferred lifetime" of the address to be overridden. Only three settings are accepted: "forever", "infinity", which is the default and means that the address never expires, and "0", which means that the address is considered immediately "expired" and will not be used, unless explicitly requested. A setting of :systemd:option:`PreferredLifetime=0` is useful for addresses which are added to be used only by a specific application, which is then configured to use them explicitly.

   .. versionadded:: 230

.. systemd:option:: Scope=
   :group: network-directives

   The scope of the address, which can be "global" (valid everywhere on the network, even through a gateway), "link" (only valid on this device, will not traverse a gateway) or "host" (only valid within the device itself, e.g. 127.0.0.1) or an integer in the range 0…255. Defaults to "global". IPv4 only - IPv6 scope is automatically assigned by the kernel and cannot be set manually.

   .. versionadded:: 235

.. systemd:option:: RouteMetric=
   :group: network-directives

   The metric of the prefix route, which is pointing to the subnet of the configured IP address, taking the configured prefix length into account. Takes an unsigned integer in the range 0…4294967295. When unset or set to 0, the kernel's default value is used. This setting will be ignored when :systemd:var:`AddPrefixRoute=` is false.

   .. versionadded:: 246

.. systemd:option:: HomeAddress=
   :group: network-directives

   Takes a boolean. Designates this address the "home address" as defined in `RFC 6275 <https://tools.ietf.org/html/rfc6275>`_. Supported only on IPv6. Defaults to false.

   .. versionadded:: 232

.. systemd:option:: DuplicateAddressDetection=
   :group: network-directives

   Takes one of "ipv4", "ipv6", "both", or "none". When "ipv4", performs IPv4 Address Conflict Detection. See `RFC 5227 <https://tools.ietf.org/html/rfc5227>`_. When "ipv6", performs IPv6 Duplicate Address Detection. See `RFC 4862 <https://tools.ietf.org/html/rfc4862>`_. Defaults to "ipv4" for IPv4 link-local addresses (169.254.0.0/16), "ipv6" for IPv6 addresses, and "none" otherwise.

   When enabled, regardless implicitly or not, :systemd:var:`ARP=` is enabled unless it is explicitly configured.

   .. versionadded:: 232

.. systemd:option:: ManageTemporaryAddress=
   :group: network-directives

   Takes a boolean. If true the kernel manage temporary addresses created from this one as template on behalf of Privacy Extensions `RFC 3041 <https://tools.ietf.org/html/rfc3041>`_. For this to become active, the use_tempaddr sysctl setting has to be set to a value greater than zero. The given address needs to have a prefix length of 64. This flag allows using privacy extensions in a manually configured network, just like if stateless auto-configuration was active. Defaults to false.

   .. versionadded:: 232

.. systemd:option:: AddPrefixRoute=
   :group: network-directives

   Takes a boolean. When true, the prefix route for the address is automatically added. Defaults to true.

   .. versionadded:: 245

.. systemd:option:: AutoJoin=
   :group: network-directives

   Takes a boolean. Joining multicast group on ethernet level via :code:`ip maddr` command would not work if we have an Ethernet switch that does IGMP snooping since the switch would not replicate multicast packets on ports that did not have IGMP reports for the multicast addresses. Linux vxlan interfaces created via :code:`ip link add vxlan` or :code:`systemd-networkd`'s netdev kind vxlan have the group option that enables them to do the required join. By extending :code:`ip address` command with option "autojoin" we can get similar functionality for openvswitch (OVS) vxlan interfaces as well as other tunneling mechanisms that need to receive multicast traffic. Defaults to "no".

   .. versionadded:: 232

.. systemd:option:: NetLabel=label
   :group: network-directives

   This setting provides a method for integrating static and dynamic network configuration into Linux `NetLabel <https://docs.kernel.org/netlabel/index.html>`_ subsystem rules, used by `Linux Security Modules (LSMs) <https://en.wikipedia.org/wiki/Linux_Security_Modules>`_ for network access control. The label, with suitable LSM rules, can be used to control connectivity of (for example) a service with peers in the local network. At least with SELinux, only the ingress can be controlled but not egress. The benefit of using this setting is that it may be possible to apply interface independent part of NetLabel configuration at very early stage of system boot sequence, at the time when the network interfaces are not available yet, with :man-pages:`netlabelctl(8)`, and the per-interface configuration with :code:`systemd-networkd` once the interfaces appear later. Currently this feature is only implemented for SELinux.

   The option expects a single NetLabel label. The label must conform to lexicographic restrictions of LSM labels. When an interface is configured with IP addresses, the addresses and subnetwork masks will be appended to the `NetLabel Fallback Peer Labeling <https://github.com/SELinuxProject/selinux-notebook/blob/main/src/network_support.md>`_ rules. They will be removed when the interface is deconfigured. Failures to manage the labels will be ignored.

   .. warning::

       Once labeling is enabled for network traffic, a lot of LSM access control points in Linux networking stack go from dormant to active. Care should be taken to avoid getting into a situation where for example remote connectivity is broken, when the security policy has not been updated to consider LSM per-packet access controls and no rules would allow any network traffic. Also note that additional configuration with :man-pages:`netlabelctl(8)` is needed.

   Example:

     .. code-block:: sh

        [Address]
        NetLabel=system_u:object_r:localnet_peer_t:s0

   With the example rules applying for interface "eth0", when the interface is configured with an IPv4 address of 10.0.0.123/8, :code:`systemd-networkd` performs the equivalent of :code:`netlabelctl` operation

     .. code-block:: sh

        netlabelctl unlbl add interface eth0 address:10.0.0.0/8 label:system_u:object_r:localnet_peer_t:s0

   and the reverse operation when the IPv4 address is deconfigured. The configuration can be used with LSM rules; in case of SELinux to allow a SELinux domain to receive data from objects of SELinux "peer" class. For example:

     .. code-block:: sh

        type localnet_peer_t;
        allow my_server_t localnet_peer_t:peer recv;

   The effect of the above configuration and rules (in absence of other rules as may be the case) is to only allow "my_server_t" (and nothing else) to receive data from local subnet 10.0.0.0/8 of interface "eth0".

   .. versionadded:: 252

.. systemd:option:: NFTSet=source:family:table:set
   :group: network-directives

   This setting provides a method for integrating network configuration into firewall rules with `NFT <https://netfilter.org/projects/nftables/index.html>`_ sets. The benefit of using the setting is that static network configuration (or dynamically obtained network addresses, see similar directives in other sections) can be used in firewall rules with the indirection of NFT set types. For example, access could be granted for hosts in the local subnetwork only. Firewall rules using IP address of an interface are also instantly updated when the network configuration changes, for example via DHCP.

   This option expects a whitespace separated list of NFT set definitions. Each definition consists of a colon-separated tuple of source type (one of "address", "prefix" or "ifindex"), NFT address family (one of "arp", "bridge", "inet", "ip", "ip6", or "netdev"), table name and set name. The names of tables and sets must conform to lexicographic restrictions of NFT table names. The type of the element used in the NFT filter must match the type implied by the directive ("address", "prefix" or "ifindex") and address type (IPv4 or IPv6) as shown in the table below.

   .. list-table:: Defined :systemd:var:`source type` values
      :header-rows: 1

      * - Source type
        - Description
        - Corresponding NFT type name
      * - "address"
        - host IP address
        - "ipv4_addr" or "ipv6_addr"
      * - "prefix"
        - network prefix
        - "ipv4_addr" or "ipv6_addr", with "flags interval"
      * - "ifindex"
        - interface index
        - "iface_index"

   When an interface is configured with IP addresses, the addresses, subnetwork masks or interface index will be appended to the NFT sets. The information will be removed when the interface is deconfigured. :code:`systemd-networkd` only inserts elements to (or removes from) the sets, so the related NFT rules, tables and sets must be prepared elsewhere in advance. Failures to manage the sets will be ignored.

   Example:

     .. code-block:: sh

        [Address]
        NFTSet=prefix:netdev:filter:eth_ipv4_prefix

   Corresponding NFT rules:

     .. code-block:: sh

        table netdev filter {
                set eth_ipv4_prefix {
                        type ipv4_addr
                        flags interval
                }
                chain eth_ingress {
                        type filter hook ingress device "eth0" priority filter; policy drop;
                        ip daddr != @eth_ipv4_prefix drop
                        accept
                }
        }

   .. versionadded:: 255

.. systemd:option:: SourcePort=

.. systemd:option:: DestinationPort=

.. systemd:option:: IPProtocol=
   :group: network-directives

.. systemd:option:: InvertRule=

.. systemd:option:: Family=

[Route] Section Options
#######################

The \[Route] section accepts the following settings. Specify several \[Route] sections to configure several routes.

.. systemd:option:: Gateway=
   :group: network-directives

   Takes the gateway address or the special values "_dhcp4" and "_ipv6ra". If "_dhcp4" or "_ipv6ra" is set, then the gateway address provided by DHCPv4 or IPv6 RA is used. When"_dhcp4", the acquired DHCPv4 address will be used as the preferred source address of the route, unless it is explicitly configured in :systemd:var:`PreferredSource=`.

   .. versionadded:: 211

.. systemd:option:: GatewayOnLink=
   :group: network-directives

   Takes a boolean. If set to true, the kernel does not have to check if the gateway is reachable directly by the current machine (i.e., attached to the local network), so that we can insert the route in the kernel table without it being complained about. Defaults to "no".

   .. versionadded:: 234

.. systemd:option:: Destination=
   :group: network-directives

   The destination prefix of the route. Possibly followed by a slash and the prefix length. If omitted, a full-length host route is assumed.

   .. versionadded:: 211

.. systemd:option:: Source=
   :group: network-directives

   The source prefix of the route. Possibly followed by a slash and the prefix length. If omitted, a full-length host route is assumed.

   .. versionadded:: 218

.. systemd:option:: Metric=
   :group: network-directives

   The metric of the route. Takes an unsigned integer in the range 0…4294967295. Defaults to unset, and the kernel's default will be used.

   .. versionadded:: 216

.. systemd:option:: IPv6Preference=
   :group: network-directives

   Specifies the route preference as defined in `RFC 4191 <https://tools.ietf.org/html/rfc4191>`_ for Router Discovery messages. Which can be one of "low" the route has a lowest priority, "medium" the route has a default priority or "high" the route has a highest priority.

   .. versionadded:: 234

.. systemd:option:: Scope=
   :group: network-directives

   The scope of the IPv4 route, which can be "global", "site", "link", "host", or "nowhere":

   *       "global" means the route can reach hosts more than one hop away.

   *       "site" means an interior route in the local autonomous system.

   *       "link" means the route can only reach hosts on the local network (one hop away).

   *       "host" means the route will not leave the local machine (used for internal addresses like 127.0.0.1).

   *       "nowhere" means the destination does not exist.

   For IPv4 route, defaults to "host" if :systemd:var:`Type=` is "local" or "nat", and "link" if :systemd:var:`Type=` is "broadcast", "multicast", "anycast", or "unicast". In other cases, defaults to "global". The value is not used for IPv6.

   .. versionadded:: 219

.. systemd:option:: PreferredSource=
   :group: network-directives

   The preferred source address of the route. Takes "no" or an address in the format described in :man-pages:`inet_pton(3)`. If :systemd:var:`Gateway=_dhcp4` is specified, defaults to the acquired DHCPv4 address. Otherwise, defaults to unset. The value "no" may be useful to configure a route with :systemd:var:`Gateway=_dhcp4` without setting preferred source route address.

   .. versionadded:: 227

.. systemd:option:: Table=
   :group: network-directives

   The table identifier for the route. Takes one of predefined names "default", "main", and "local", and names defined in :systemd:var:`RouteTable=` in :man-pages:`networkd.conf(5)`, or a number between 1 and 4294967295. The table can be retrieved using :code:`ip route show table num`. If unset and :systemd:var:`Type=` is "local", "broadcast", "anycast", or "nat", then "local" is used. In other cases, defaults to "main".

   .. versionadded:: 230

.. systemd:option:: HopLimit=
   :group: network-directives

   Configures per route hop limit. Takes an integer in the range 1…255. See also :systemd:var:`IPv6HopLimit=`.

   .. versionadded:: 255

.. systemd:option:: Protocol=
   :group: network-directives

   The protocol identifier for the route. Takes a number between 0 and 255 or the special values "kernel", "boot", "static", "ra" and "dhcp". Defaults to "static".

   .. versionadded:: 234

.. systemd:option:: Type=
   :group: network-directives

   Specifies the type for the route. Takes one of "unicast", "local", "broadcast", "anycast", "multicast", "blackhole", "unreachable", "prohibit", "throw", "nat", and "xresolve". If "unicast", a regular route is defined, i.e. a route indicating the path to take to a destination network address. If "blackhole", packets to the defined route are discarded silently. If "unreachable", packets to the defined route are discarded and the ICMP message "Host Unreachable" is generated. If "prohibit", packets to the defined route are discarded and the ICMP message "Communication Administratively Prohibited" is generated. If "throw", route lookup in the current routing table will fail and the route selection process will return to Routing Policy Database (RPDB). Defaults to "unicast".

   .. versionadded:: 235

.. systemd:option:: InitialCongestionWindow=
   :group: network-directives

   The TCP initial congestion window is used during the start of a TCP connection. During the start of a TCP session, when a client requests a resource, the server's initial congestion window determines how many packets will be sent during the initial burst of data without waiting for acknowledgement. Takes a number between 1 and 1023. Note that 100 is considered an extremely large value for this option. When unset, the kernel's default (typically 10) will be used.

   .. versionadded:: 237

.. systemd:option:: InitialAdvertisedReceiveWindow=
   :group: network-directives

   The TCP initial advertised receive window is the amount of receive data (in bytes) that can initially be buffered at one time on a connection. The sending host can send only that amount of data before waiting for an acknowledgment and window update from the receiving host. Takes a number between 1 and 1023. Note that 100 is considered an extremely large value for this option. When unset, the kernel's default will be used.

   .. versionadded:: 237

.. systemd:option:: QuickAck=
   :group: network-directives

   Takes a boolean. When true, the TCP quick ACK mode for the route is enabled. When unset, the kernel's default will be used.

   .. versionadded:: 237

.. systemd:option:: FastOpenNoCookie=
   :group: network-directives

   Takes a boolean. When true enables TCP fastopen without a cookie on a per-route basis. When unset, the kernel's default will be used.

   .. versionadded:: 243

.. systemd:option:: MTUBytes=
   :group: network-directives

   The maximum transmission unit in bytes to set for the route. The usual suffixes K, M, G, are supported and are understood to the base of 1024.

   .. versionadded:: 239

.. systemd:option:: TCPAdvertisedMaximumSegmentSize=
   :group: network-directives

   Specifies the Path MSS (in bytes) hints given on TCP layer. The usual suffixes K, M, G, are supported and are understood to the base of 1024. An unsigned integer in the range 1…4294967294. When unset, the kernel's default will be used.

   .. versionadded:: 248

.. systemd:option:: TCPCongestionControlAlgorithm=
   :group: network-directives

   Specifies the TCP congestion control algorithm for the route. Takes a name of the algorithm, e.g. "bbr", "dctcp", or "vegas". When unset, the kernel's default will be used.

   .. versionadded:: 252

.. systemd:option:: TCPRetransmissionTimeoutSec=
   :group: network-directives

   Specifies the TCP Retransmission Timeout (RTO) for the route. Takes time values in seconds. This value specifies the timeout of an alive TCP connection, when retransmissions remain unacknowledged. When unset, the kernel's default will be used.

   .. versionadded:: 255

.. systemd:option:: MultiPathRoute=address[@name] [weight]
   :group: network-directives

   Configures multipath route. Multipath routing is the technique of using multiple alternative paths through a network. Takes gateway address. Optionally, takes a network interface name or index separated with "@", and a weight in 1..256 for this multipath route separated with whitespace. This setting can be specified multiple times. If an empty string is assigned, then the all previous assignments are cleared.

   .. versionadded:: 245

.. systemd:option:: NextHop=
   :group: network-directives

[DHCPv4] Section Options
########################

The \[DHCPv4] section configures the DHCPv4 client, if it is enabled with the :code:`DHCP=` setting described above:

.. COMMENT: DHCP packet contents

.. systemd:option:: RequestAddress=
   :group: network-directives

   Takes an IPv4 address. When specified, the Requested IP Address option (option code 50) is added with it to the initial DHCPDISCOVER message sent by the DHCP client. Defaults to unset, and an already assigned dynamic address to the interface is automatically picked.

   .. versionadded:: 255

.. systemd:option:: SendHostname=
   :group: network-directives

   When true (the default), the machine's hostname (or the value specified with :systemd:var:`Hostname=`, described below) will be sent to the DHCP server. Note that the hostname must consist only of 7-bit ASCII lower-case characters and no spaces or dots, and be formatted as a valid DNS domain name. Otherwise, the hostname is not sent even if this option is true.

   .. versionadded:: 215

.. systemd:option:: Hostname=
   :group: network-directives

   Use this value for the hostname which is sent to the DHCP server, instead of machine's hostname. Note that the specified hostname must consist only of 7-bit ASCII lower-case characters and no spaces or dots, and be formatted as a valid DNS domain name.

   .. versionadded:: 223

.. systemd:option:: MUDURL=
   :group: network-directives

   When configured, the specified Manufacturer Usage Description (MUD) URL will be sent to the DHCPv4 server. Takes a URL of length up to 255 characters. A superficial verification that the string is a valid URL will be performed. DHCPv4 clients are intended to have at most one MUD URL associated with them. See `RFC 8520 <https://tools.ietf.org/html/rfc8520>`_.

   MUD is an embedded software standard defined by the IETF that allows IoT device makers to advertise device specifications, including the intended communication patterns for their device when it connects to the network. The network can then use this to author a context-specific access policy, so the device functions only within those parameters.

   .. versionadded:: 246

If set to :systemd:option:`duid`, an RFC4361-compliant Client ID, which is the combination of IAID and DUID, is used. IAID can be configured by :systemd:var:`IAID=`. DUID can be configured by :systemd:var:`DUIDType=` and :systemd:var:`DUIDRawData=`. When :systemd:var:`Anonymize=` is enabled, :systemd:option:`mac` is unconditionally used and the specified value will be ignored. When unspecified, the value specified in the same setting in :man-pages:`networkd.conf(5)` will be used.

   .. versionadded:: 220

.. systemd:option:: VendorClassIdentifier=
   :group: network-directives

   The vendor class identifier used to identify vendor type and configuration.

   .. versionadded:: 216

.. systemd:option:: UserClass=
   :group: network-directives

   A DHCPv4 client can use UserClass option to identify the type or category of user or applications it represents. The information contained in this option is a string that represents the user class of which the client is a member. Each class sets an identifying string of information to be used by the DHCP service to classify clients. Takes a whitespace-separated list of strings.

   .. versionadded:: 239

.. systemd:option:: DUIDType=
   :group: network-directives

   Override the global :systemd:var:`DUIDType=` setting for this network. See :man-pages:`networkd.conf(5)` for a description of possible values.

.. systemd:option:: DUIDRawData=

.. systemd:option:: IAID=
   :group: network-directives

.. systemd:option:: RapidCommit=
   :group: network-directives

   Takes a boolean. The DHCPv4 client can obtain configuration parameters from a DHCPv4 server through a rapid two-message exchange (discover and ack). When the rapid commit option is set by both the DHCPv4 client and the DHCPv4 server, the two-message exchange is used.    Takes a boolean. When true, the options sent to the DHCP server will follow the `RFC 7844 <https://tools.ietf.org/html/rfc7844>`_ (Anonymity Profiles for DHCP Clients) to minimize disclosure of identifying information. Defaults to false.

   This option should only be set to true when :systemd:var:`MACAddressPolicy=` is set to :systemd:option:`random` (see :ref:`systemd.link(5)`).

   When true, :systemd:var:`ClientIdentifier=mac`, :systemd:var:`RapidCommit=no`, :systemd:var:`SendHostname=no`, :systemd:var:`Use6RD=no`, :systemd:var:`UseCaptivePortal=no`, :systemd:var:`UseMTU=no`, :systemd:var:`UseNTP=no`, :systemd:var:`UseSIP=no`, and :systemd:var:`UseTimezone=no` are implied and these settings in the .network file are silently ignored. Also, :systemd:var:`Hostname=`, :systemd:var:`MUDURL=`, :systemd:var:`RequestAddress=`, :systemd:var:`RequestOptions=`, :systemd:var:`SendOption=`, :systemd:var:`SendVendorOption=`, :systemd:var:`UserClass=`, and :systemd:var:`VendorClassIdentifier=` are silently ignored.

   With this option enabled DHCP requests will mimic those generated by Microsoft Windows, in order to reduce the ability to fingerprint and recognize installations. This means DHCP request sizes will grow and lease data will be more comprehensive than normally, though most of the requested data is not actually used.

Special characters in the data string may be escaped using `C-style escapes <https://en.wikipedia.org/wiki/Escape_sequences_in_C#Table_of_escape_sequences>`_. [DHCPPrefixDelegation] Section Options
######################################

The \[DHCPPrefixDelegation] section configures subnet prefixes of the delegated prefixes acquired by a DHCPv6 client or by a DHCPv4 client through the 6RD option on another interface. The settings in this section are used only when the :code:`DHCPPrefixDelegation=` setting in the \[Network] section is enabled.

.. systemd:option:: UplinkInterface=
   :group: network-directives

   Specifies the name or the index of the uplink interface, or one of the special values ":self" and ":auto". When ":self", the interface itself is considered the uplink interface, and :systemd:var:`WithoutRA=solicit` is implied if the setting is not explicitly specified. When ":auto", the first link which acquired prefixes to be delegated from the DHCPv6 or DHCPv4 server is selected. Defaults to ":auto".

   .. versionadded:: 250

.. systemd:option:: SubnetId=
   :group: network-directives

   Configure a specific subnet ID on the interface from a (previously) received prefix delegation. You can either set "auto" (the default) or a specific subnet ID (as defined in `RFC 4291 <https://tools.ietf.org/html/rfc4291#section-2.5.4>`_, section 2.5.4), in which case the allowed value is hexadecimal, from 0 to 0x7fffffffffffffff inclusive.

   .. versionadded:: 246

.. systemd:option:: Announce=
   :group: network-directives

   Takes a boolean. When enabled, and :systemd:var:`IPv6SendRA=` in \[Network] section is enabled, the delegated prefixes are distributed through the IPv6 Router Advertisement. This setting will be ignored when the :systemd:var:`DHCPPrefixDelegation=` setting is enabled on the upstream interface. Defaults to yes.

   .. versionadded:: 247

.. systemd:option:: Assign=
   :group: network-directives

   Takes a boolean. Specifies whether to add an address from the delegated prefixes which are received from the WAN interface by the DHCPv6 Prefix Delegation. When true (on LAN interface), the EUI-64 algorithm will be used by default to form an interface identifier from the delegated prefixes. See also :systemd:var:`Token=` setting below. Defaults to yes.

   .. versionadded:: 246

.. systemd:option:: Token=
   :group: network-directives

   Specifies an optional address generation mode for assigning an address in each delegated prefix. This accepts the same syntax as :systemd:var:`Token=` in the \[IPv6AcceptRA] section. If :systemd:var:`Assign=` is set to false, then this setting will be ignored. Defaults to unset, which means the EUI-64 algorithm will be used.

   .. versionadded:: 246

.. systemd:option:: ManageTemporaryAddress=
   :group: network-directives

   As in the \[Address] section, but defaults to true.

   .. versionadded:: 248

.. systemd:option:: RouteMetric=
   :group: network-directives

   The metric of the route to the delegated prefix subnet. Takes an unsigned integer in the range 0…4294967295. When set to 0, the kernel's default value is used. Defaults to 256.

   .. versionadded:: 249

.. systemd:option:: NetLabel=
   :group: network-directives

   This applies the NetLabel for the addresses received with DHCP, like :systemd:var:`NetLabel=` in \[Address] section applies it to statically configured addresses. See :systemd:var:`NetLabel=` in \[Address] section for more details.

   .. versionadded:: 252

.. systemd:option:: NFTSet=
   :group: network-directives

   This applies the NFT set for the network configuration received with DHCP, like :systemd:var:`NFTSet=` in \[Address] section applies it to static configuration. .. systemd:option:: Token=
   :group: network-directives

   Specifies an optional address generation mode for the Stateless Address Autoconfiguration (SLAAC). The following values are supported:

   .. systemd:option:: eui64
      :group: network-directives

         The EUI-64 algorithm will be used to generate an address for that prefix. Only supported by Ethernet or InfiniBand interfaces.

         .. versionadded:: 250

   .. systemd:option:: static:ADDRESS
      :group: network-directives

         An IPv6 address must be specified after a colon (":"), and the lower bits of the supplied address are combined with the upper bits of a prefix received in a Router Advertisement (RA) message to form a complete address. Note that if multiple prefixes are received in an RA message, or in multiple RA messages, addresses will be formed from each of them using the supplied address. This mode implements SLAAC but uses a static interface identifier instead of an identifier generated by using the EUI-64 algorithm. Because the interface identifier is static, if Duplicate Address Detection detects that the computed address is a duplicate (in use by another node on the link), then this mode will fail to provide an address for that prefix. If an IPv6 address without mode is specified, then "static" mode is assumed.

         .. versionadded:: 250

   .. systemd:option:: prefixstable[:ADDRESS][,UUID]
      :group: network-directives

         The algorithm specified in `RFC 7217 <https://tools.ietf.org/html/rfc7217>`_ will be used to generate interface identifiers. This mode can optionally take an IPv6 address separated with a colon (":"). If an IPv6 address is specified, then an interface identifier is generated only when a prefix received in an RA message matches the supplied address.

         This mode can also optionally take a non-null UUID in the format which :code:`sd_id128_from_string()` accepts, e.g. "86b123b969ba4b7eb8b3d8605123525a" or "86b123b9-69ba-4b7e-b8b3-d8605123525a". If a UUID is specified, the value is used as the secret key to generate interface identifiers. If not specified, then an application specific ID generated with the system's machine-ID will be used as the secret key. See :ref:`sd-id128(3)`, :ref:`sd_id128_from_string(3)`, and :ref:`sd_id128_get_machine(3)`.

         Note that the "prefixstable" algorithm uses both the interface name and MAC address as input to the hash to compute the interface identifier, so if either of those are changed the resulting interface identifier (and address) will be changed, even if the prefix received in the RA message has not been changed.

         .. versionadded:: 250

   If no address generation mode is specified (which is the default), or a received prefix does not match any of the addresses provided in "prefixstable" mode, then the EUI-64 algorithm will be used for Ethernet or InfiniBand interfaces, otherwise "prefixstable" will be used to form an interface identifier for that prefix.

   This setting can be specified multiple times. If an empty string is assigned, then the all previous assignments are cleared.

   Examples:

     .. code-block:: sh

        Token=eui64
        Token=::1a:2b:3c:4d
        Token=static:::1a:2b:3c:4d
        Token=prefixstable
        Token=prefixstable:2002:da8:1::

   .. versionadded:: 250

.. systemd:option:: UseDomains=
   :group: network-directives

   Takes a boolean, or the special value "route". When true, the domain name received via IPv6 Router Advertisement (RA) will be used as DNS search domain over this link, similarly to the effect of the :systemd:option:`Domains=` setting. If set to "route", the domain name received via IPv6 RA will be used for routing DNS queries only, but not for searching, similarly to the effect of the :systemd:option:`Domains=` setting when the argument is prefixed with "~". [DHCPServer] Section Options
############################

The \[DHCPServer] section contains settings for the DHCP server, if enabled via the :code:`DHCPServer=` option described above:

.. systemd:option:: ServerAddress=
   :group: network-directives

   Specifies the server address for the DHCP server. Takes an IPv4 address with prefix length separated with a slash, e.g. "192.168.0.1/24". Defaults to unset, and one of static IPv4 addresses configured in \[Network] or \[Address] section will be automatically selected. This setting may be useful when the interface on which the DHCP server is running has multiple static IPv4 addresses.

   This implies :systemd:var:`Address=` in \[Network] or \[Address] section with the same address and prefix length. That is,

     .. code-block:: sh

        [Network]
        DHCPServer=yes
        Address=192.168.0.1/24
        Address=192.168.0.2/24
        [DHCPServer]
        ServerAddress=192.168.0.1/24

   or

     .. code-block:: sh

        [Network]
        DHCPServer=yes
        [Address]
        Address=192.168.0.1/24
        [Address]
        Address=192.168.0.2/24
        [DHCPServer]
        ServerAddress=192.168.0.1/24

   are equivalent to the following:

     .. code-block:: sh

        [Network]
        DHCPServer=yes
        Address=192.168.0.2/24
        [DHCPServer]
        ServerAddress=192.168.0.1/24

   Since version 255, like the :systemd:var:`Address=` setting in \[Network] or \[Address] section, this also supports a null address, e.g. "0.0.0.0/24", and an unused address will be automatically selected. For more details about the automatic address selection, see :systemd:var:`Address=` setting in \[Network] section in the above.

   .. versionadded:: 249

.. systemd:option:: PoolOffset=, PoolSize=
   :group: network-directives

   Configures the pool of addresses to hand out. The pool is a contiguous sequence of IP addresses in the subnet configured for the server address, which does not include the subnet nor the broadcast address. :systemd:var:`PoolOffset=` takes the offset of the pool from the start of subnet, or zero to use the default value. :systemd:var:`PoolSize=` takes the number of IP addresses in the pool or zero to use the default value. By default, the pool starts at the first address after the subnet address and takes up the rest of the subnet, excluding the broadcast address. If the pool includes the server address (the default), this is reserved and not handed out to clients.

   .. versionadded:: 226

.. systemd:option:: DefaultLeaseTimeSec=, MaxLeaseTimeSec=
   :group: network-directives

   Control the default and maximum DHCP lease time to pass to clients. These settings take time values in seconds or another common time unit, depending on the suffix. The default lease time is used for clients that did not ask for a specific lease time. If a client asks for a lease time longer than the maximum lease time, it is automatically shortened to the specified time. The default lease time defaults to 1h, the maximum lease time to 12h. Shorter lease times are beneficial if the configuration data in DHCP leases changes frequently and clients shall learn the new settings with shorter latencies. Longer lease times reduce the generated DHCP network traffic.

   .. versionadded:: 226

.. systemd:option:: UplinkInterface=
   :group: network-directives

   Specifies the name or the index of the uplink interface, or one of the special values ":none" and ":auto". When emitting DNS, NTP, or SIP servers is enabled but no servers are specified, the servers configured in the uplink interface will be emitted. When ":auto", the link which has a default gateway with the highest priority will be automatically selected. When ":none", no uplink interface will be selected. Defaults to ":auto".

   .. versionadded:: 249

.. systemd:option:: EmitDNS=, DNS=
   :group: network-directives

   :systemd:var:`EmitDNS=` takes a boolean. Configures whether the DHCP leases handed out to clients shall contain DNS server information. Defaults to "yes". The DNS servers to pass to clients may be configured with the :systemd:var:`DNS=` option, which takes a list of IPv4 addresses, or special value "_server_address" which will be converted to the address used by the DHCP server.

   If the :systemd:var:`EmitDNS=` option is enabled but no servers configured, the servers are automatically propagated from an "uplink" interface that has appropriate servers set. The "uplink" interface is determined by the default route of the system with the highest priority. Note that this information is acquired at the time the lease is handed out, and does not take uplink interfaces into account that acquire DNS server information at a later point. If no suitable uplink interface is found the DNS server data from :code:`/etc/resolv.conf` is used. Also, note that the leases are not refreshed if the uplink network configuration changes. To ensure clients regularly acquire the most current uplink DNS server information, it is thus advisable to shorten the DHCP lease time via :systemd:var:`MaxLeaseTimeSec=` described above.

   This setting can be specified multiple times. If an empty string is specified, then all DNS servers specified earlier are cleared.

   .. versionadded:: 226

.. systemd:option:: EmitNTP=, NTP=, EmitSIP=, SIP=, EmitPOP3=, POP3=, EmitSMTP=, SMTP=, EmitLPR=, LPR=
   :group: network-directives

   Similar to the :systemd:var:`EmitDNS=` and :systemd:var:`DNS=` settings described above, these settings configure whether and what server information for the indicate protocol shall be emitted as part of the DHCP lease. The same syntax, propagation semantics and defaults apply as for :systemd:var:`EmitDNS=` and :systemd:var:`DNS=`.

   .. versionadded:: 226

.. systemd:option:: EmitRouter=, Router=
   :group: network-directives

   The :systemd:var:`EmitRouter=` setting takes a boolean value, and configures whether the DHCP lease should contain the router option. The :systemd:var:`Router=` setting takes an IPv4 address, and configures the router address to be emitted. When the :systemd:var:`Router=` setting is not specified, then the server address will be used for the router option. When the :systemd:var:`EmitRouter=` setting is disabled, the :systemd:var:`Router=` setting will be ignored. The :systemd:var:`EmitRouter=` setting defaults to true, and the :systemd:var:`Router=` setting defaults to unset.

   .. versionadded:: 230

.. systemd:option:: EmitTimezone=, Timezone=
   :group: network-directives

   Takes a boolean. Configures whether the DHCP leases handed out to clients shall contain timezone information. Defaults to "yes". The :systemd:var:`Timezone=` setting takes a timezone string (such as "Europe/Berlin" or "UTC") to pass to clients. If no explicit timezone is set, the system timezone of the local host is propagated, as determined by the :code:`/etc/localtime` symlink.

   .. versionadded:: 226

.. systemd:option:: EmitDomain=
   :group: network-directives

   Takes a boolean. Configures whether the DHCP leases handed out to clients shall contain domain name information (DHCP option 15). Defaults to "no".

   .. versionadded:: 259

.. systemd:option:: Domain=
   :group: network-directives

   Takes a domain name (such as "example.com") to pass to DHCP clients. This configures the DNS default domain for DHCP clients. When set, DHCP clients will use this as their DNS search domain.

   When :systemd:var:`EmitDomain=yes` is set but :systemd:var:`Domain=` is not configured, the domain name will be automatically derived from the system's fully qualified hostname. For example, if the system's hostname is "host.example.com", the domain "example.com" will be sent to clients. If the system's hostname does not contain a domain part (e.g., hostname is just "host"), no domain name will be sent to DHCP clients. When empty or unset, defaults to no domain name.

   .. versionadded:: 259

.. systemd:option:: BootServerAddress=
   :group: network-directives

   Takes an IPv4 address of the boot server used by e.g. PXE boot systems. When specified, this address is sent in the :systemd:option:`siaddr` field of the DHCP message header. See `RFC 2131 <https://www.rfc-editor.org/rfc/rfc2131.html>`_ for more details. Defaults to unset.

   .. versionadded:: 251

.. systemd:option:: BootServerName=
   :group: network-directives

   Takes a name of the boot server used by e.g. PXE boot systems. When specified, this name is sent in the DHCP option 66 ("TFTP server name"). See `RFC 2132 <https://www.rfc-editor.org/rfc/rfc2132.html>`_ for more details. Defaults to unset.

   Note that typically setting one of :systemd:var:`BootServerName=` or :systemd:var:`BootServerAddress=` is sufficient, but both can be set too, if desired.

   .. versionadded:: 251

.. systemd:option:: BootFilename=
   :group: network-directives

   Takes a path or URL to a file loaded by e.g. a PXE boot loader. When specified, this path is sent in the DHCP option 67 ("Bootfile name"). See `RFC 2132 <https://www.rfc-editor.org/rfc/rfc2132.html>`_ for more details. Defaults to unset.

   .. versionadded:: 251

.. systemd:option:: IPv6OnlyPreferredSec=
   :group: network-directives

   Takes a timespan. Controls the `RFC 8925 <https://tools.ietf.org/html/rfc8925>`_ IPv6-Only Preferred option. Specifies the DHCPv4 option to indicate that a host supports an IPv6-only mode and is willing to forgo obtaining an IPv4 address if the network provides IPv6 connectivity. Defaults to unset, and not send the option. The minimum allowed value is 300 seconds.

   .. versionadded:: 255

.. systemd:option:: SendOption=
   :group: network-directives

   Send a raw option with value via DHCPv4 server. Takes a DHCP option number, data type and data (":emphasis:`option`::emphasis:`type`::emphasis:`value`"). Special characters in the data string may be escaped using `C-style escapes <https://en.wikipedia.org/wiki/Escape_sequences_in_C#Table_of_escape_sequences>`_. .. systemd:option:: SendVendorOption=
   :group: network-directives

   Send a vendor option with value via DHCPv4 server. Takes a DHCP option number, data type and data (":emphasis:`option`::emphasis:`type`::emphasis:`value`"). Special characters in the data string may be escaped using `C-style escapes <https://en.wikipedia.org/wiki/Escape_sequences_in_C#Table_of_escape_sequences>`_. .. systemd:option:: BindToInterface=
   :group: network-directives

   Takes a boolean value. When "yes", DHCP server socket will be bound to its network interface and all socket communication will be restricted to this interface. Defaults to "yes", except if :systemd:var:`RelayTarget=` is used (see below), in which case it defaults to "no".

.. systemd:option:: RelayAgentCircuitId=

   Specifies value for Agent Circuit ID suboption of Relay Agent Information option. .. systemd:option:: RelayAgentRemoteId=
   :group: network-directives

.. systemd:option:: RapidCommit=
   :group: network-directives

   Takes a boolean. When true, the server supports `RFC 4039 <https://datatracker.ietf.org/doc/html/rfc4039>`_.    .. versionadded:: 255

.. systemd:option:: PersistLeases=
   :group: network-directives

   Takes a boolean or special value "runtime". When "yes", the DHCP server will load and save leases in the persistent storage. When "runtime", the DHCP server will load and save leases in the runtime storage, hence bound leases will be lost when the runtime storage is cleared by e.g. by calling :code:`systemctl clean systemd-networkd.service` or the system is rebooted. When "no", the DHCP server will neither load nor save leases in the persistent storage, hence bound leases will be lost when the interface is reconfigured e.g. by :code:`networkctl reconfigure`, or :ref:`systemd-networkd.service(8)` is restarted. Using "runtime" and "no" may cause address conflict on the network after the leases are lost. So, please take an extra care when disable this setting. When unspecified, the value specified in the same setting in :man-pages:`networkd.conf(5)`, which defaults to "yes", will be used.

   When :systemd:var:`RelayTarget=` is specified, this setting will be ignored and no leases will be saved, as there will be no bound lease on the server.

   .. versionadded:: 256

.. systemd:option:: LocalLeaseDomain=
   :group: network-directives

   Takes a DNS domain name as argument. The hostnames are suffixed with the specified domain name.

   Note that this purely about hostname resolution on the local system, i.e. from programs with access to the same :code:`systemd-resolved` instances via D-Bus IPC, Varlink IPC, or the local DNS stub.

[DHCPServerStaticLease] Section Options
#######################################

The "[DHCPServerStaticLease]" section configures a static DHCP lease to assign a fixed IPv4 address to a specific device based on its MAC address. This section can be specified multiple times.

.. systemd:option:: MACAddress=
   :group: network-directives

   The hardware address of a device to match. This key is mandatory.

   .. versionadded:: 249

.. systemd:option:: Address=
   :group: network-directives

   The IPv4 address that should be assigned to the device that was matched with :systemd:var:`MACAddress=`. This key is mandatory.

   .. versionadded:: 249

.. systemd:option:: Hostname=
   :group: network-directives

   The hostname to send to the client in DHCP replies. This can be either a simple hostname (e.g., "mydevice") or a fully qualified domain name (e.g., "mydevice.example.com"), following RFC 1123 naming conventions. Each label can be up to 63 characters, with a total maximum length of 253 characters for FQDNs. When this option is set, the DHCP server will include the hostname in DHCP replies (both OFFER and ACK) to the client with the matched MAC address.

   The server automatically selects the appropriate DHCP option based on the hostname format: simple hostnames (single DNS label) are sent via option 12 (Host Name) per RFC 2132, while FQDNs with multiple labels are sent via option 81 (Client FQDN) per RFC 4702 using DNS wire format encoding. The configured hostname is sent unconditionally, any hostname requested by the client in its DHCP message is ignored.

   .. versionadded:: 259

[IPv6SendRA] Section Options
############################

The \[IPv6SendRA] section contains settings for sending IPv6 Router Advertisements and whether to act as a router, if enabled via the :code:`IPv6SendRA=` option described above. IPv6 network prefixes or routes are defined with one or more \[IPv6Prefix] or \[IPv6RoutePrefix] sections.

.. systemd:option:: Managed=, OtherInformation=
   :group: network-directives

   Takes a boolean. Controls whether a DHCPv6 server is used to acquire IPv6 addresses on the network link when :systemd:var:`Managed=` is set to "true" or if only additional network information can be obtained via DHCPv6 for the network link when :systemd:var:`OtherInformation=` is set to "true". Both settings default to "false", which means that a DHCPv6 server is not being used.

   .. versionadded:: 235

.. systemd:option:: RouterLifetimeSec=
   :group: network-directives

   Takes a timespan. Configures the IPv6 router lifetime in seconds. The value must be 0 seconds, or between 4 seconds and 9000 seconds. When set to 0, the host is not acting as a router. Defaults to 1800 seconds (30 minutes).

[Bridge] Section Options

The \[Bridge] section accepts the following keys:

.. systemd:option:: UnicastFlood=

   .. versionadded:: 223

.. systemd:option:: MulticastFlood=
   :group: network-directives

   Takes a boolean. Controls whether the bridge should flood traffic for which an MDB entry is missing and the destination is unknown through this port. When unset, the kernel's default will be used.

   .. versionadded:: 242

.. systemd:option:: MulticastToUnicast=
   :group: network-directives

   Takes a boolean. Multicast to unicast works on top of the multicast snooping feature of the bridge. Which means unicast copies are only delivered to hosts which are interested in it. When unset, the kernel's default will be used.

   .. versionadded:: 240

.. systemd:option:: NeighborSuppression=
   :group: network-directives

   Takes a boolean. Configures whether ARP and ND neighbor suppression is enabled for this port. When unset, the kernel's default will be used.

   .. versionadded:: 242

.. systemd:option:: Learning=
   :group: network-directives

   Takes a boolean. Configures whether MAC address learning is enabled for this port. When unset, the kernel's default will be used.

   .. versionadded:: 242

.. systemd:option:: HairPin=
   :group: network-directives

   Takes a boolean. Configures whether traffic may be sent back out of the port on which it was received. When this flag is false, then the bridge will not forward traffic back out of the receiving port. When unset, the kernel's default will be used.

   .. versionadded:: 223

.. systemd:option:: Isolated=
   :group: network-directives

   Takes a boolean. Configures whether this port is isolated or not. Within a bridge, isolated ports can only communicate with non-isolated ports. When set to true, this port can only communicate with other ports whose Isolated setting is false. When set to false, this port can communicate with any other ports. When unset, the kernel's default will be used.

   .. versionadded:: 251

.. systemd:option:: UseBPDU=
   :group: network-directives

   Takes a boolean. Configures whether STP Bridge Protocol Data Units will be processed by the bridge port. When unset, the kernel's default will be used.

   .. versionadded:: 223

.. systemd:option:: FastLeave=
   :group: network-directives

   Takes a boolean. This flag allows the bridge to immediately stop multicast traffic on a port that receives an IGMP Leave message. It is only used with IGMP snooping if enabled on the bridge. When unset, the kernel's default will be used.

   .. versionadded:: 223

.. systemd:option:: AllowPortToBeRoot=
   :group: network-directives

   Takes a boolean. Configures whether a given port is allowed to become a root port. Only used when STP is enabled on the bridge. When unset, the kernel's default will be used.

   .. versionadded:: 223

.. systemd:option:: ProxyARP=
   :group: network-directives

   Takes a boolean. Configures whether proxy ARP to be enabled on this port. When unset, the kernel's default will be used.

   .. versionadded:: 243

.. systemd:option:: ProxyARPWiFi=
   :group: network-directives

   Takes a boolean. Configures whether proxy ARP to be enabled on this port which meets extended requirements by IEEE 802.11 and Hotspot 2.0 specifications. When unset, the kernel's default will be used.

   .. versionadded:: 243

.. systemd:option:: MulticastRouter=
   :group: network-directives

   Configures this port for having multicast routers attached. A port with a multicast router will receive all multicast traffic. Takes one of "no" to disable multicast routers on this port, "query" to let the system detect the presence of routers, "permanent" to permanently enable multicast traffic forwarding on this port, or "temporary" to enable multicast routers temporarily on this port, not depending on incoming queries. When unset, the kernel's default will be used.

   .. versionadded:: 243

.. systemd:option:: Cost=
   :group: network-directives

   Sets the "cost" of sending packets of this interface. Each port in a bridge may have a different speed and the cost is used to decide which link to use. Faster interfaces should have lower costs. It is an integer value between 1 and 65535.

   .. versionadded:: 218

.. systemd:option:: Priority=
   :group: network-directives

   Sets the "priority" of sending packets on this interface. Each port in a bridge may have a different priority which is used to decide which link to use. Lower value means higher priority. It is an integer value between 0 to 63. :code:`systemd-networkd` does not set any default, meaning the kernel default value of 32 is used.

   .. versionadded:: 234

.. systemd:option:: Locked=, MACAuthenticationBypass=
   :group: network-directives

   Takes a boolean. Configures whether the port is "locked" and does not allow traffic forwarded until fully authenticated, e.g. via 802.1x. When unset, the kernel's default will be used.

   .. versionadded:: 258

   Takes a boolean. Configures whether a locked port has "MAC Authentication Bypass" enabled and creates newly learned fdb entries in a "locked" state. User space can authenticate these entries by clearing the locked flag. Requires Learning to be enabled. When unset, the kernel's default will be used.

   .. versionadded:: 258

.. systemd:option:: VLANTunnel=
   :group: network-directives

   Takes a boolean. Configures whether vlan tunnel mode is to be enabled on this port. When unset, the kernel's default will be used.

   .. versionadded:: 258

[CAN] Section Options
#####################

The \[CAN] section manages the Controller Area Network (CAN bus) and accepts the following keys:

.. systemd:option:: BitRate=
   :group: network-directives

   The bitrate of CAN device in bits per second. The usual SI prefixes (K, M) with the base of 1000 can be used here. Takes a number in the range 1…4294967295.

   .. versionadded:: 239

.. systemd:option:: SamplePoint=
   :group: network-directives

   Optional sample point in percent with one decimal (e.g. "75%", "87.5%") or permille (e.g. "875‰"). This will be ignored when :systemd:var:`BitRate=` is unspecified.

   .. versionadded:: 239

.. systemd:option:: TimeQuantaNSec=, PropagationSegment=, PhaseBufferSegment1=, PhaseBufferSegment2=, SyncJumpWidth=
   :group: network-directives

   Specifies the time quanta, propagation segment, phase buffer segment 1 and 2, and the synchronization jump width, which allow one to define the CAN bit-timing in a hardware independent format as proposed by the Bosch CAN 2.0 Specification. :systemd:var:`TimeQuantaNSec=` takes a timespan in nanoseconds. :systemd:var:`PropagationSegment=`, :systemd:var:`PhaseBufferSegment1=`, :systemd:var:`PhaseBufferSegment2=`, and :systemd:var:`SyncJumpWidth=` take number of time quantum specified in :systemd:var:`TimeQuantaNSec=` and must be an unsigned integer in the range 0…4294967295. These settings except for :systemd:var:`SyncJumpWidth=` will be ignored when :systemd:var:`BitRate=` is specified.

   .. versionadded:: 250

.. systemd:option:: DataBitRate=, DataSamplePoint=
   :group: network-directives

   The bitrate and sample point for the data phase, if CAN-FD is used. These settings are analogous to the :systemd:var:`BitRate=` and :systemd:var:`SamplePoint=` keys.

   .. versionadded:: 246

.. systemd:option:: DataTimeQuantaNSec=, DataPropagationSegment=, DataPhaseBufferSegment1=, DataPhaseBufferSegment2=, DataSyncJumpWidth=
   :group: network-directives

   Specifies the time quanta, propagation segment, phase buffer segment 1 and 2, and the synchronization jump width for the data phase, if CAN-FD is used. These settings are analogous to the :systemd:var:`TimeQuantaNSec=` or related settings.

   .. versionadded:: 250

.. systemd:option:: FDMode=
   :group: network-directives

   Takes a boolean. When "yes", CAN-FD mode is enabled for the interface. Note, that a bitrate and optional sample point should also be set for the CAN-FD data phase using the :systemd:var:`DataBitRate=` and :systemd:var:`DataSamplePoint=` keys, or :systemd:var:`DataTimeQuanta=` and related settings.

   .. versionadded:: 246

.. systemd:option:: FDNonISO=
   :group: network-directives

   Takes a boolean. When "yes", non-ISO CAN-FD mode is enabled for the interface. When unset, the kernel's default will be used.

   .. versionadded:: 246

.. systemd:option:: RestartSec=
   :group: network-directives

   Automatic restart delay time. If set to a non-zero value, a restart of the CAN controller will be triggered automatically in case of a bus-off condition after the specified delay time. Subsecond delays can be specified using decimals (e.g. "0.1s") or a "ms" or "us" postfix. Using "infinity" or "0" will turn the automatic restart off. By default, automatic restart is disabled.

   .. versionadded:: 239

.. systemd:option:: Termination=
   :group: network-directives

   Takes a boolean or a termination resistor value in ohm in the range 0…65535. When "yes", the termination resistor is set to 120 ohm. When "no" or "0" is set, the termination resistor is disabled. When unset, the kernel's default will be used.

   .. versionadded:: 246

.. systemd:option:: TripleSampling=
   :group: network-directives

   Takes a boolean. When "yes", three samples (instead of one) are used to determine the value of a received bit by majority rule. When unset, the kernel's default will be used.

   .. versionadded:: 242

.. systemd:option:: BusErrorReporting=
   :group: network-directives

   Takes a boolean. When "yes", reporting of CAN bus errors is activated (those include single bit, frame format, and bit stuffing errors, unable to send dominant bit, unable to send recessive bit, bus overload, active error announcement, error occurred on transmission). When unset, the kernel's default will be used. Note: in case of a CAN bus with a single CAN device, sending a CAN frame may result in a huge number of CAN bus errors.

   .. versionadded:: 248

.. systemd:option:: ListenOnly=
   :group: network-directives

   Takes a boolean. When "yes", listen-only mode is enabled. When the interface is in listen-only mode, the interface neither transmit CAN frames nor send ACK bit. Listen-only mode is important to debug CAN networks without interfering with the communication or acknowledge the CAN frame. When unset, the kernel's default will be used.

   .. versionadded:: 246

.. systemd:option:: Loopback=
   :group: network-directives

   Takes a boolean. When "yes", loopback mode is enabled. When the loopback mode is enabled, the interface treats messages transmitted by itself as received messages. The loopback mode is important to debug CAN networks. When unset, the kernel's default will be used.

   .. versionadded:: 250

.. systemd:option:: OneShot=
   :group: network-directives

   Takes a boolean. When "yes", one-shot mode is enabled. When unset, the kernel's default will be used.

   .. versionadded:: 250

.. systemd:option:: PresumeACK=
   :group: network-directives

   Takes a boolean. When "yes", the interface will ignore missing CAN ACKs. When unset, the kernel's default will be used.

   .. versionadded:: 250

.. systemd:option:: ClassicDataLengthCode=
   :group: network-directives

   Takes a boolean. When "yes", the interface will handle the 4bit data length code (DLC). When unset, the kernel's default will be used.

   .. versionadded:: 250

.. systemd:option:: Bandwidth=

.. systemd:option:: AutoRateIngress=
   :group: network-directives

   Takes a boolean value. Enables automatic capacity estimation based on traffic arriving at this qdisc. This is most likely to be useful with cellular links, which tend to change quality randomly. If this setting is enabled, the :systemd:var:`Bandwidth=` setting is used as an initial estimate. Defaults to unset, and the kernel's default is used.

   .. versionadded:: 250

.. systemd:option:: OverheadBytes=
   :group: network-directives

   Specifies that bytes to be addeded to the size of each packet. Bytes may be negative. Takes an integer in the range -64…256. Defaults to unset and kernel's default is used.

   .. versionadded:: 246

.. systemd:option:: MPUBytes=
   :group: network-directives

   Rounds each packet (including overhead) up to the specified bytes. Takes an integer in the range 1…256. Defaults to unset and kernel's default is used.

   .. versionadded:: 250

.. systemd:option:: CompensationMode=
   :group: network-directives

   Takes one of "none", "atm", or "ptm". Specifies the compensation mode for overhead calculation. When "none", no compensation is taken into account. When "atm", enables the compensation for ATM cell framing, which is normally found on ADSL links. When "ptm", enables the compensation for PTM encoding, which is normally found on VDSL2 links and uses a 64b/65b encoding scheme. Defaults to unset and the kernel's default is used.

   .. versionadded:: 250

.. systemd:option:: UseRawPacketSize=
   :group: network-directives

   Takes a boolean value. When true, the packet size reported by the Linux kernel will be used, instead of the underlying IP packet size. Defaults to unset, and the kernel's default is used.

   .. versionadded:: 250

.. systemd:option:: FlowIsolationMode=
   :group: network-directives

   CAKE places packets from different flows into different queues, then packets from each queue are delivered fairly. This specifies whether the fairness is based on source address, destination address, individual flows, or any combination of those. The available values are:

   .. systemd:option:: none
      :group: network-directives

         The flow isolation is disabled, and all traffic passes through a single queue.

         .. versionadded:: 250

   .. systemd:option:: src-host
      :group: network-directives

         Flows are defined only by source address. Equivalent to the "srchost" option for :code:`tc qdisc` command. See also :man-pages:`tc-cake(8)`.

         .. versionadded:: 250

   .. systemd:option:: dst-host
      :group: network-directives

         Flows are defined only by destination address. Equivalent to the "dsthost" option for :code:`tc qdisc` command. See also :man-pages:`tc-cake(8)`.

         .. versionadded:: 250

   .. systemd:option:: hosts
      :group: network-directives

         Flows are defined by source-destination host pairs. Equivalent to the same option for :code:`tc qdisc` command. See also :man-pages:`tc-cake(8)`.

         .. versionadded:: 250

   .. systemd:option:: flows
      :group: network-directives

         Flows are defined by the entire 5-tuple of source address, destination address, transport protocol, source port and destination port. Equivalent to the same option for :code:`tc qdisc` command. See also :man-pages:`tc-cake(8)`.

         .. versionadded:: 250

   .. systemd:option:: dual-src-host
      :group: network-directives

         Flows are defined by the 5-tuple (see "flows" in the above), and fairness is applied first over source addresses, then over individual flows. Equivalent to the "dual-srchost" option for :code:`tc qdisc` command. See also :man-pages:`tc-cake(8)`.

         .. versionadded:: 250

   .. systemd:option:: dual-dst-host
      :group: network-directives

         Flows are defined by the 5-tuple (see "flows" in the above), and fairness is applied first over destination addresses, then over individual flows. Equivalent to the "dual-dsthost" option for :code:`tc qdisc` command. See also :man-pages:`tc-cake(8)`.

         .. versionadded:: 250

   .. systemd:option:: triple
      :group: network-directives

         Flows are defined by the 5-tuple (see "flows"), and fairness is applied over source and destination addresses, and also over individual flows. Equivalent to the "triple-isolate" option for :code:`tc qdisc` command. See also :man-pages:`tc-cake(8)`.

         .. versionadded:: 250

   Defaults to unset and the kernel's default is used.

   .. versionadded:: 250

.. systemd:option:: NAT=
   :group: network-directives

   Takes a boolean value. When true, CAKE performs a NAT lookup before applying flow-isolation rules, to determine the true addresses and port numbers of the packet, to improve fairness between hosts inside the NAT. This has no practical effect when :systemd:var:`FlowIsolationMode=` is "none" or "flows", or if NAT is performed on a different host. Defaults to unset, and the kernel's default is used.

   .. versionadded:: 250

.. systemd:option:: PriorityQueueingPreset=
   :group: network-directives

   CAKE divides traffic into "tins", and each tin has its own independent set of flow-isolation queues, bandwidth threshold, and priority. This specifies the preset of tin profiles. The available values are:

   .. systemd:option:: besteffort
      :group: network-directives

         Disables priority queueing by placing all traffic in one tin.

         .. versionadded:: 250

   .. systemd:option:: precedence
      :group: network-directives

         Enables priority queueing based on the legacy interpretation of TOS "Precedence" field. Use of this preset on the modern Internet is firmly discouraged.

         .. versionadded:: 250

   .. systemd:option:: diffserv8
      :group: network-directives

         Enables priority queueing based on the Differentiated Service ("DiffServ") field with eight tins: Background Traffic, High Throughput, Best Effort, Video Streaming, Low Latency Transactions, Interactive Shell, Minimum Latency, and Network Control.

         .. versionadded:: 250

   .. systemd:option:: diffserv4
      :group: network-directives

         Enables priority queueing based on the Differentiated Service ("DiffServ") field with four tins: Background Traffic, Best Effort, Streaming Media, and Latency Sensitive.

         .. versionadded:: 250

   .. systemd:option:: diffserv3
      :group: network-directives

         Enables priority queueing based on the Differentiated Service ("DiffServ") field with three tins: Background Traffic, Best Effort, and Latency Sensitive.

         .. versionadded:: 250

   Defaults to unset, and the kernel's default is used.

   .. versionadded:: 250

.. systemd:option:: FirewallMark=
   :group: network-directives

   Takes an integer in the range 1…4294967295. When specified, firewall-mark-based overriding of CAKE's tin selection is enabled. Defaults to unset, and the kernel's default is used.

   .. versionadded:: 250

.. systemd:option:: Wash=
   :group: network-directives

   Takes a boolean value. When true, CAKE clears the DSCP fields, except for ECN bits, of any packet passing through CAKE. Defaults to unset, and the kernel's default is used.

   .. versionadded:: 250

.. systemd:option:: SplitGSO=
   :group: network-directives

   Takes a boolean value. When true, CAKE will split General Segmentation Offload (GSO) super-packets into their on-the-wire components and dequeue them individually. Defaults to unset, and the kernel's default is used.

   .. versionadded:: 250

.. systemd:option:: RTTSec=
   :group: network-directives

   Specifies the RTT for the filter. Takes a timespan. Typical values are e.g. 100us for extremely high-performance 10GigE+ networks like datacentre, 1ms for non-WiFi LAN connections, 100ms for typical internet connections. Defaults to unset, and the kernel's default will be used.

   .. versionadded:: 253

.. systemd:option:: AckFilter=
   :group: network-directives

   Takes a boolean value, or special value "aggressive". If enabled, ACKs in each flow are queued and redundant ACKs to the upstream are dropped. If yes, the filter will always keep at least two redundant ACKs in the queue, while in "aggressive" mode, it will filter down to a single ACK. This may improve download throughput on links with very asymmetrical rate limits. Defaults to unset, and the kernel's default will be used.

   .. versionadded:: 253

[BridgeVLAN] Section Options
############################

The \[BridgeVLAN] section manages the VLAN ID configuration of a bridge master or enslaved device. To make the settings in this section take an effect, :code:`VLANFiltering=` option has to be enabled on the bridge master, see the \[Bridge] section in :ref:`systemd.netdev(5)`, and each enslaved device needs to define the relevant VLAN IDs in its own \[BridgeVLAN] section, which it has in common with the bridge master. All assigned VLAN IDs on the interface that are not configured in the .network file will be removed. If VLAN IDs on an interface need to be managed by other tools, then the settings in this section cannot be used in the matching .network file and :code:`VLANFiltering=` needs to be disabled on the bridge master.

.. systemd:option:: VLAN=
   :group: network-directives

   The VLAN ID allowed on the port. This can be either a single ID or a range M-N. Takes an integer in the range 1…4094. This setting can be specified multiple times. If an empty string is assigned, then the all previous assignments are cleared.

   .. versionadded:: 231

.. systemd:option:: EgressUntagged=
   :group: network-directives

   The VLAN ID specified here will be used to untag frames on egress. Configuring :systemd:var:`EgressUntagged=` implicates the use of :systemd:var:`VLAN=` above and will enable the VLAN ID for ingress as well. This can be either a single ID or a range M-N. This setting can be specified multiple times. If an empty string is assigned, then the all previous assignments are cleared.

   .. versionadded:: 231

.. systemd:option:: PVID=
   :group: network-directives

   The port VLAN ID specified here is assigned to all untagged frames at ingress. Takes an VLAN ID or negative boolean value (e.g. "no"). When false, the currently assigned port VLAN ID will be dropped. Configuring :systemd:var:`PVID=` implicates the use of :systemd:var:`VLAN=` setting in the above and will enable the VLAN ID for ingress as well. Defaults to unset, and will keep the assigned port VLAN ID if exists.

   .. versionadded:: 231

Examples
########

Static network configuration
----------------------------

.. code-block:: sh

   # /etc/systemd/network/50-static.network
   [Match]
   Name=enp2s0
   [Network]
   Address=192.168.0.15/24
   Gateway=192.168.0.1

This brings interface "enp2s0" up with a static address. The specified gateway will be used for a default route.

DHCP on ethernet links
----------------------

.. code-block:: sh

   # /etc/systemd/network/80-dhcp.network
   [Match]
   Name=en*
   [Network]
   DHCP=yes

This will enable DHCPv4 and DHCPv6 on all interfaces with names starting with "en" (i.e. ethernet interfaces).

IPv6 Prefix Delegation (DHCPv6 PD)
----------------------------------

.. code-block:: sh

   # /etc/systemd/network/55-dhcpv6-pd-upstream.network
   [Match]
   Name=enp1s0
   [Network]
   DHCP=ipv6
   # The lines below are optional, to also assign an address in the delegated prefix
   # to the upstream interface. Uncomment the lines below if necessary.
   #[Network]
   #DHCPPrefixDelegation=yes
   #[DHCPPrefixDelegation]
   #UplinkInterface=:self
   #SubnetId=0
   #Announce=no
   # If the upstream network does not provides any Router Advertisement (RA) messages,
   # then uncomment the lines below to make the DHCPv6 client forcibly started in the
   # managed mode.
   #[Network]
   #IPv6AcceptRA=no
   #[DHCPv6]
   #WithoutRA=solicit
   # If the upstream network provides Router Advertisement (RA) messages with the
   # Managed bit unset, then uncomment the lines below to make the DHCPv6 client
   # forcibly started in the managed mode when an RA is received.
   #[DHCPv6]
   #UseAddress=no
   #[IPv6AcceptRA]
   #DHCPv6Client=always

.. code-block:: sh

   # /etc/systemd/network/55-dhcpv6-pd-downstream.network
   [Match]
   Name=enp2s0
   [Network]
   DHCPPrefixDelegation=yes
   IPv6SendRA=yes
   # It is expected that the host is acting as a router. So, usually it is not
   # necessary to receive Router Advertisement from other hosts in the downstream network.
   IPv6AcceptRA=no
   [DHCPPrefixDelegation]
   UplinkInterface=enp1s0
   SubnetId=1
   Announce=yes

This will enable DHCPv6-PD on the interface enp1s0 as an upstream interface where the DHCPv6 client is running and enp2s0 as a downstream interface where the prefix is delegated to. The delegated prefixes are distributed by IPv6 Router Advertisement on the downstream network.

IPv6 Prefix Delegation (DHCPv4 6RD)
-----------------------------------

.. code-block:: sh

   # /etc/systemd/network/55-dhcpv4-6rd-upstream.network
   [Match]
   Name=enp1s0
   [Network]
   DHCP=ipv4
   # When DHCPv4-6RD is used, the upstream network does not support IPv6.
   # Hence, it is not necessary to wait for Router Advertisement, which is enabled by default.
   IPv6AcceptRA=no
   [DHCPv4]
   Use6RD=yes

.. code-block:: sh

   # /etc/systemd/network/55-dhcpv4-6rd-downstream.network
   [Match]
   Name=enp2s0
   [Network]
   DHCPPrefixDelegation=yes
   IPv6SendRA=yes
   # It is expected that the host is acting as a router. So, usually it is not
   # necessary to receive Router Advertisement from other hosts in the downstream network.
   IPv6AcceptRA=no
   [DHCPPrefixDelegation]
   UplinkInterface=enp1s0
   SubnetId=1
   Announce=yes

This will enable DHCPv4-6RD on the interface enp1s0 as an upstream interface where the DHCPv4 client is running and enp2s0 as a downstream interface where the prefix is delegated to. The delegated prefixes are distributed by IPv6 Router Advertisement on the downstream network.

A bridge with two enslaved links
--------------------------------

.. code-block:: sh

   # /etc/systemd/network/25-bridge-static.netdev
   [NetDev]
   Name=bridge0
   Kind=bridge

.. code-block:: sh

   # /etc/systemd/network/25-bridge-static.network
   [Match]
   Name=bridge0
   [Network]
   Address=192.168.0.15/24
   Gateway=192.168.0.1
   DNS=192.168.0.1

.. code-block:: sh

   # /etc/systemd/network/25-bridge-slave-interface-1.network
   [Match]
   Name=enp2s0
   [Network]
   Bridge=bridge0

.. code-block:: sh

   # /etc/systemd/network/25-bridge-slave-interface-2.network
   [Match]
   Name=wlp3s0
   [Network]
   Bridge=bridge0

This creates a bridge and attaches devices "enp2s0" and "wlp3s0" to it. The bridge will have the specified static address and network assigned, and a default route via the specified gateway will be added. The specified DNS server will be added to the global list of DNS resolvers.

Bridge port with VLAN forwarding
--------------------------------

.. code-block:: sh

   # /etc/systemd/network/25-bridge-slave-interface-1.network
   [Match]
   Name=enp2s0
   [Network]
   Bridge=bridge0
   [BridgeVLAN]
   VLAN=1-32
   PVID=42
   EgressUntagged=42
   [BridgeVLAN]
   VLAN=100-299
   [BridgeVLAN]
   EgressUntagged=300-400

This overrides the configuration specified in the previous example for the interface "enp2s0", and enables VLAN on that bridge port. VLAN IDs 1-32, 42, 100-400 will be allowed. Packets tagged with VLAN IDs 42, 300-400 will be untagged when they leave on this interface. Untagged packets which arrive on this interface will be assigned VLAN ID 42.

.. code-block:: sh

   /etc/systemd/network/25-tunnels.network
   [Match]
   Name=ens1
   [Network]
   Tunnel=ipip-tun
   Tunnel=sit-tun
   Tunnel=gre-tun
   Tunnel=vti-tun

.. code-block:: sh

   /etc/systemd/network/25-tunnel-ipip.netdev
   [NetDev]
   Name=ipip-tun
   Kind=ipip

.. code-block:: sh

   /etc/systemd/network/25-tunnel-sit.netdev
   [NetDev]
   Name=sit-tun
   Kind=sit

.. code-block:: sh

   /etc/systemd/network/25-tunnel-gre.netdev
   [NetDev]
   Name=gre-tun
   Kind=gre

.. code-block:: sh

   /etc/systemd/network/25-tunnel-vti.netdev
   [NetDev]
   Name=vti-tun

This will bring interface "ens1" up and create an IPIP tunnel, a SIT tunnel, a GRE tunnel, and a VTI tunnel using it.

A bond device
-------------

.. code-block:: sh

   # /etc/systemd/network/30-bond1.network
   [Match]
   Name=bond1
   [Network]
   DHCP=ipv6

.. code-block:: sh

   # /etc/systemd/network/30-bond1.netdev
   [NetDev]
   Name=bond1
   Kind=bond

.. code-block:: sh

   # /etc/systemd/network/30-bond1-dev1.network
   [Match]
   MACAddress=52:54:00:e9:64:41
   [Network]
   Bond=bond1

.. code-block:: sh

   # /etc/systemd/network/30-bond1-dev2.network
   [Match]
   MACAddress=52:54:00:e9:64:42
   [Network]
   Bond=bond1

This will create a bond device "bond1" and enslave the two devices with MAC addresses 52:54:00:e9:64:41 and 52:54:00:e9:64:42 to it. IPv6 DHCP will be used to acquire an address.

Virtual Routing and Forwarding (VRF)
------------------------------------

Add the "bond1" interface to the VRF master interface "vrf1". This will redirect routes generated on this interface to be within the routing table defined during VRF creation. For kernels before 4.8 traffic will not be redirected towards the VRFs routing table unless specific ip-rules are added.

.. code-block:: sh

   # /etc/systemd/network/25-vrf.network
   [Match]
   Name=bond1
   [Network]
   VRF=vrf1

MacVTap
-------

This brings up a network interface "macvtap-test" and attaches it to "enp0s25".

.. code-block:: sh

   # /usr/lib/systemd/network/25-macvtap.network
   [Match]
   Name=enp0s25
   [Network]
   MACVTAP=macvtap-test

A Xfrm interface with physical underlying device.
-------------------------------------------------

.. code-block:: sh

   # /etc/systemd/network/27-xfrm.netdev
   [NetDev]
   Name=xfrm0
   Kind=xfrm
   [Xfrm]
   InterfaceId=7

.. code-block:: sh

   # /etc/systemd/network/27-eth0.network
   [Match]
   Name=eth0
   [Network]
   Xfrm=xfrm0

This creates a "xfrm0" interface and binds it to the "eth0" device. This allows hardware based ipsec offloading to the "eth0" nic. If offloading is not needed, xfrm interfaces can be assigned to the "lo" device.
