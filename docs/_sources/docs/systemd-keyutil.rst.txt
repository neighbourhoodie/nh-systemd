==================
systemd-keyutil(1)
==================

Name
####

systemd-keyutil — Perform various operations on private keys and X.509 certificates

Synopsis
########

:code:`systemd-keyutil [OPTIONS...] {COMMAND}`

Description
###########

:code:`systemd-keyutil` can be used to perform various operations on private keys and X.509 certificates.

Commands
########

.. systemd:option:: validate

   Checks that we can load the private key and certificate specified with :code:`--private-key=` and :code:`--certificate=` respectively.

   As a side effect, if the private key is loaded from a PIN-protected hardware token, this command can be used to cache the PIN in the kernel keyring. The :code:`$SYSTEMD_ASK_PASSWORD_KEYRING_TIMEOUT_SEC` and :code:`$SYSTEMD_ASK_PASSWORD_KEYRING_TYPE` environment variables can be used to control how long and in which kernel keyring the PIN is cached.

   .. versionadded:: 257

.. systemd:option:: public

   This commands prints the public key in PEM format extracted from either the certificate given with :code:`--certificate=` or the private key given with :code:`--private-key=`.

   .. versionadded:: 257

.. systemd:option:: pkcs7

   This command embeds the PKCS#1 signature (RSA) provided with :code:`--signature=` in a PKCS#7 signature using the certificate given with :code:`--certificate=` and writes it to the file specified with :code:`--output=` in PKCS#7 format (p7s). If :code:`--content=` is provided it is included in the p7s, otherwise a "detached" signature is created. The :code:`--hash-algorithm=` option, which defaults to "SHA256", specifies what hash algorithm was used to generate the signature.

   .. versionadded:: 258

Options
#######

The following options are understood:

.. systemd:option:: --private-key=PATH/URI, --private-key-source=TYPE[:NAME], --certificate=PATH, --certificate-source=TYPE[:NAME]

   Set the private key and certificate to use. The :code:`--certificate=` option takes a path to a PEM encoded X.509 certificate or a URI that's passed to the OpenSSL provider configured with :code:`--certificate-source`. The :code:`--certificate-source` takes one of "file" or "provider", with the latter being followed by a specific provider identifier, separated with a colon, e.g. "provider:pkcs11". The :code:`--private-key=` option can take a path or a URI that will be passed to the OpenSSL engine or provider, as specified by :code:`--private-key-source=` as a "type:name" tuple, such as "engine:pkcs11".

   .. versionadded:: 257

.. systemd:option:: --signature=PATH

   Input PKCS#1 signature for the :code:`pkcs7` command.

   .. versionadded:: 258

.. systemd:option:: --content=PATH

   Input data that corresponds to the PKCS#1 signature for the :code:`pkcs7` command, used for generating inline (i.e. non-"detached") PKCS#7 signatures.

   .. versionadded:: 258

.. systemd:option:: --hash-algorithm=ALGORITHM

   Hash algorithm used to generate the PKCS#1 signature for the :code:`pkcs7` command. This should be a valid openssl digest algorithm; use "openssl list -digest-algorithms" to see a list of valid algorithms on your system. Defaults to "SHA256".

   .. versionadded:: 258

.. systemd:option:: --output=PATH

   Output PKCS#7 signature for the :code:`pkcs7` command.

   .. versionadded:: 258
