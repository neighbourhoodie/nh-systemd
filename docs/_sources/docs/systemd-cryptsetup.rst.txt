=====================
systemd-cryptsetup(8)
=====================

Name
####

systemd-cryptsetup, systemd-cryptsetup@.service — Full disk decryption logic

Synopsis
########

:code:`systemd-cryptsetup [OPTIONS...] attach VOLUME SOURCE-DEVICE [KEY-FILE] [CRYPTTAB-OPTIONS]`

:code:`systemd-cryptsetup [OPTIONS...] detach VOLUME`

:code:`systemd-cryptsetup@.service`

:code:`system-systemd\\x2dcryptsetup.slice`

Description
###########

:code:`systemd-cryptsetup` is used to set up (with :code:`attach`) and tear down (with :code:`detach`) access to an encrypted block device. It is primarily used via :code:`systemd-cryptsetup@.service` during early boot, but may also be called manually. The positional arguments :code:`VOLUME`, :code:`SOURCE-DEVICE`, :code:`KEY-FILE`, and :code:`CRYPTTAB-OPTIONS` have the same meaning as the fields in :man-pages:`crypttab(5)`.

:code:`systemd-cryptsetup@.service` is a service responsible for providing access to encrypted block devices. It is instantiated for each device that requires decryption.

:code:`systemd-cryptsetup@.service` instances are part of the :code:`system-systemd\\x2dcryptsetup.slice` slice, which is destroyed only very late in the shutdown procedure. This allows the encrypted devices to remain up until filesystems have been unmounted.

:code:`systemd-cryptsetup@.service` will ask for hard disk passwords via the `password agent logic <https://systemd.io/PASSWORD_AGENTS/>`_, in order to query the user for the password using the right mechanism at boot and during runtime.

At early boot and when the system manager configuration is reloaded, :code:`/etc/crypttab` is translated into :code:`systemd-cryptsetup@.service` units by :ref:`systemd-cryptsetup-generator(8)`.

In order to unlock a volume a password or binary key is required. :code:`systemd-cryptsetup@.service` tries to acquire a suitable password or binary key via the following mechanisms, tried in order:

1.    If a key file is explicitly configured (via the third column in :code:`/etc/crypttab`), a key read from it is used. If a PKCS#11 token, FIDO2 token or TPM2 device is configured (using the :code:`pkcs11-uri=`, :code:`fido2-device=`, :code:`tpm2-device=` options) the key is decrypted before use.

2.    If no key file is configured explicitly this way, a key file is automatically loaded from :code:`/etc/cryptsetup-keys.d/volume.key` and :code:`/run/cryptsetup-keys.d/volume.key`, if present. Here too, if a PKCS#11/FIDO2/TPM2 token/device is configured, any key found this way is decrypted before use.

3.    If the :code:`try-empty-password` option is specified then unlocking the volume with an empty password is attempted.

4.    If the :code:`password-cache=` option is set to "yes" or "read-only", the kernel keyring is then checked for a suitable cached password from previous attempts.

5.    Finally, the user is queried for a password, possibly multiple times, unless the :code:`headless` option is set.

If no suitable key may be acquired via any of the mechanisms describes above, volume activation fails.

Credentials
###########

:code:`systemd-cryptsetup` supports the service credentials logic as implemented by :code:`ImportCredential=`/:code:`LoadCredential=`/:code:`SetCredential=` (see :ref:`systemd.exec(5)` for details). The following credentials are used by "systemd-crypsetup@root.service" (generated by :code:`systemd-gpt-auto-generator`) when passed in:

.. systemd:option:: cryptsetup.passphrase
   :group: system-credentials

   This credential specifies the passphrase of the LUKS volume.

   .. versionadded:: 256

.. systemd:option:: cryptsetup.tpm2-pin
   :group: system-credentials

   This credential specifies the TPM pin.

   .. versionadded:: 256

.. systemd:option:: cryptsetup.fido2-pin
   :group: system-credentials

   This credential specifies the FIDO2 token pin.

   .. versionadded:: 256

.. systemd:option:: cryptsetup.pkcs11-pin
   :group: system-credentials

   This credential specifies the PKCS11 token pin.

   .. versionadded:: 256

.. systemd:option:: cryptsetup.luks2-pin
   :group: system-credentials

   This credential specifies the pin requested by generic LUKS2 token modules.

   .. versionadded:: 256
