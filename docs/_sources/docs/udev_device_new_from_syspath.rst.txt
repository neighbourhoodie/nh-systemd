Description
###########

:code:`udev_device_new_from_syspath()`, :code:`udev_device_new_from_devnum()`, :code:`udev_device_new_from_subsystem_sysname()`, :code:`udev_device_new_from_device_id()`, and :code:`udev_device_new_from_environment()` allocate a new udev device object and returns a pointer to it. This object is opaque and must not be accessed by the caller via different means than functions provided by libudev. Initially, the reference count of the device is 1. You can acquire further references, and drop gained references via :code:`udev_device_ref()` and :code:`udev_device_unref()`. Once the reference count hits 0, the device object is destroyed and freed.

:code:`udev_device_new_from_syspath()`, :code:`udev_device_new_from_devnum()`, :code:`udev_device_new_from_subsystem_sysname()`, and :code:`udev_device_new_from_device_id()` create the device object based on information found in :code:`/sys/`, annotated with properties from the udev-internal device database. A syspath is any subdirectory of :code:`/sys/`, with the restriction that a subdirectory of :code:`/sys/devices` (or a symlink to one) represents a real device and as such must contain a :code:`uevent` file. :code:`udev_device_new_from_devnum()` takes a device type, which can be :code:`b` for block devices or :code:`c` for character devices, as well as a devnum (see :man-pages:`makedev(3)`). :code:`udev_device_new_from_subsystem_sysname()` looks up devices based on the provided subsystem and sysname (see :man-pages:`udev_device_get_subsystem(3)` and :man-pages:`udev_device_get_sysname(3)`) and :code:`udev_device_new_from_device_id()` looks up devices based on the provided device ID, which is a special string in one of the following four forms: .. list-table:: Device ID strings
   :header-rows: 1

   * - Example
     - Explanation
   * - :code:`b8:2`
     - block device major:minor
   * - :code:`c128:1`
     - char device major:minor
   * - :code:`n3`
     - network device ifindex
   * - :code:`+sound:card29`
     - kernel driver core subsystem:device name

:code:`udev_device_new_from_environment()` creates a device from the current environment (see :man-pages:`environ(7)`). Each key-value pair is interpreted in the same way as if it was received in an uevent (see :man-pages:`udev_monitor_receive_device(3)`). The keys :code:`DEVPATH`, :code:`SUBSYSTEM`, :code:`ACTION`, and :code:`SEQNUM` are mandatory.

Return Value
############

On success, :code:`udev_device_new_from_syspath()`, :code:`udev_device_new_from_devnum()`, :code:`udev_device_new_from_subsystem_sysname()`, :code:`udev_device_new_from_device_id()` and :code:`udev_device_new_from_environment()` return a pointer to the allocated udev device. On failure, :code:`NULL` is returned, and :code:`errno` is set appropriately. :code:`udev_device_ref()` returns the argument that it was passed, unmodified. :code:`udev_device_unref()` always returns :code:`NULL`.
