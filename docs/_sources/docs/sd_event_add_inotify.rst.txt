Description
###########

:code:`sd_event_add_inotify()` adds a new :man-pages:`inotify(7)` file system inode event source to an event loop. The event loop object is specified in the :code:`event` parameter, the event source object is returned in the :code:`source` parameter. The :code:`path` parameter specifies the path of the file system inode to watch. The :code:`mask` parameter specifies which types of inode events to watch specifically. It must contain an OR-ed combination of :code:`IN_ACCESS`, :code:`IN_ATTRIB`, :code:`IN_CLOSE_WRITE`, … flags. See :man-pages:`inotify(7)` for further information.

The :code:`handler` must reference a function to call when the inode changes or :code:`NULL`. The handler function will be passed the :code:`userdata` pointer, which may be chosen freely by the caller. The handler also receives a pointer to a struct inotify_event structure containing information about the inode event. The handler may return negative to signal an error (see below), other return values are ignored. If :code:`handler` is :code:`NULL`, a default handler that calls :ref:`sd_event_exit(3)` will be used.

:code:`sd_event_add_inotify_fd()` is identical to :code:`sd_event_add_inotify()`, except that it takes a file descriptor to an inode (possibly an :code:`O_PATH` one, but any other will do too) instead of a path in the file system.

If multiple event sources are installed for the same inode the backing inotify watch descriptor is automatically shared. The mask parameter may contain any flag defined by the inotify API, with the exception of :code:`IN_MASK_ADD`.

The handler is enabled continuously (:code:`SD_EVENT_ON`), but this may be changed with :ref:`sd_event_source_set_enabled(3)`. Alternatively, the :code:`IN_ONESHOT` mask flag may be used to request :code:`SD_EVENT_ONESHOT` mode. If the handler function returns a negative error code, it will be disabled after the invocation, even if the :code:`SD_EVENT_ON` mode was requested before.

As a special limitation the priority of inotify event sources may only be altered (see :ref:`sd_event_source_set_priority(3)`) in the time between creation of the event source object with :code:`sd_event_add_inotify()` and the beginning of the next event loop iteration. Attempts of changing the priority any later will be refused. Consider freeing and allocating a new inotify event source to change the priority at that point.

To destroy an event source object use :ref:`sd_event_source_unref(3)`, but note that the event source is only removed from the event loop when all references to the event source are dropped. To make sure an event source does not fire anymore, even when there's still a reference to it kept, consider disabling it with :ref:`sd_event_source_set_enabled(3)`.

If the second parameter of :code:`sd_event_add_inotify()` is passed as :code:`NULL` no reference to the event source object is returned. In this case, the event source is considered "floating", and will be destroyed implicitly when the event loop itself is destroyed.

If the :code:`handler` parameter to :code:`sd_event_add_inotify()` is :code:`NULL`, and the event source fires, this will be considered a request to exit the event loop. In this case, the :code:`userdata` parameter, cast to an integer, is passed as the exit code parameter to :ref:`sd_event_exit(3)`.

:code:`sd_event_source_get_inotify_mask()` retrieves the configured inotify watch mask of an event source created previously with :code:`sd_event_add_inotify()`. It takes the event source object as the :code:`source` parameter and a pointer to a uint32_t variable to return the mask in.

:code:`sd_event_source_get_inotify_path()` retrieves the target path of the configured inotify watch of an event source created previously with :code:`sd_event_add_inotify()`. It takes the event source object as the :code:`source` parameter and a pointer to a const char \** variable to return the path in. The caller must not free the returned path.

Return Value
############

On success, these functions return 0 or a positive integer. On failure, they return a negative errno-style error code.

Errors
######

Returned errors may indicate the following problems:

.. systemd:option:: -ENOMEM

   Not enough memory to allocate an object.

.. systemd:option:: -EINVAL

   An invalid argument has been passed. This includes specifying a mask with :code:`IN_MASK_ADD` set.

.. systemd:option:: -ESTALE

   Returned by :code:`sd_event_source_add_inotify()` or :code:`sd_event_source_add_inotify_fd()` when the event loop is already terminated. Returned by :code:`sd_event_source_get_inotify_path()` when no active inode data is assigned to the event source, e.g. when the event source is disabled.

.. systemd:option:: -ECHILD

   The event loop has been created in a different process, library or module instance.

.. systemd:option:: -EDOM

   The passed event source is not an inotify process event source.

.. systemd:option:: -EBADF

   The passed file descriptor is not valid.

.. systemd:option:: -ENOSYS

   :code:`sd_event_add_inotify_fd()` or :code:`sd_event_source_get_inotify_path()` was called without :code:`/proc/` mounted.
