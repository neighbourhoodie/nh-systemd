===============
systemd.link(5)
===============

Name
####

systemd.link — Network device configuration

Synopsis
########

:code:`link.link`

Description
###########

A plain ini-style text file that encodes configuration for matching network devices, used by :ref:`systemd-udevd(8)` and in particular its :code:`net_setup_link` builtin. See :ref:`systemd.syntax(7)` for a general description of the syntax.

Note that some distributions may incorporate :code:`.link` files in their early boot facilities (e.g. by including copies of the :code:`.link` files in initramfs). As such it may be necessary to take manual steps to ensure that any local changes are consistent with early-boot storage facilities. The relevant distribution-specific documentation should be consulted.

The :code:`.link` files are read from the files located in the system network directory :code:`/usr/lib/systemd/network` and :code:`/usr/local/lib/systemd/network` [#usrlocalfootnote]_, the volatile runtime network directory :code:`/run/systemd/network`, and the local administration network directory :code:`/etc/systemd/network`. All configuration files are collectively sorted and processed in alphanumeric order, regardless of the directories in which they live. However, files with identical filenames replace each other. It is recommended that each filename is prefixed with a number smaller than "70" (e.g. :code:`10-eth0.link`). Otherwise, the default :code:`.link` files or those generated by :ref:`systemd-network-generator.service(8)` may take precedence over user configured files. Files in :code:`/etc/` have the highest priority, files in :code:`/run/` take precedence over files with the same name in :code:`/usr/lib/`. This can be used to override a system-supplied link file with a local file if needed. As a special case, an empty file (file size 0) or symlink with the same name pointing to :code:`/dev/null` disables the configuration file entirely (it is "masked").

Along with the link file :code:`foo.link`, a "drop-in" directory :code:`foo.link.d/` may exist. All files with the suffix ".conf" from this directory will be merged in the alphanumeric order and parsed after the main file itself has been parsed. This is useful to alter or add configuration settings, without having to modify the main configuration file. Each drop-in file must have appropriate section headers.

In addition to :code:`/etc/systemd/network`, drop-in ".d" directories can be placed in :code:`/usr/lib/systemd/network` or :code:`/run/systemd/network` directories. Drop-in files in :code:`/etc/` take precedence over those in :code:`/run/` which in turn take precedence over those in :code:`/usr/lib/`. Drop-in files under any of these directories take precedence over the main link file wherever located.

The link file contains a \[Match] section, which determines if a given link file may be applied to a given device, as well as a \[Link] section specifying how the device should be configured. The first (in lexicographic order) of the link files that matches a given device is applied. Note that a default file :code:`99-default.link` is shipped by the system. Any user-supplied :code:`.link` should hence have a lexicographically earlier name to be considered at all.

See :man-pages:`udevadm(8)` for diagnosing problems with :code:`.link` files.

[Match] Section Options
#######################

A link file is said to match an interface if all matches specified by the \[Match] section are satisfied. When a link file does not contain valid settings in \[Match] section, then the file will match all interfaces and :code:`systemd-udevd` warns about that. Hint: to avoid the warning and to make it clear that all interfaces shall be matched, add the following:

.. code-block:: sh

   OriginalName=*

The first (in alphanumeric order) of the link files that matches a given interface is applied, all later files are ignored, even if they match as well. The following keys are accepted:

.. systemd:option:: MACAddress=
   :group: network-directives

   A whitespace-separated list of hardware addresses. The acceptable formats are:

   .. systemd:option:: colon-delimited hexadecimal
      :group: network-directives

         Each field must be one byte. E.g. "12:34:56:78:90:ab" or "AA:BB:CC:DD:EE:FF".

         .. versionadded:: 250

   .. systemd:option:: hyphen-delimited hexadecimal
      :group: network-directives

         Each field must be one byte. E.g. "12-34-56-78-90-ab" or "AA-BB-CC-DD-EE-FF".

         .. versionadded:: 250

   .. systemd:option:: dot-delimited hexadecimal
      :group: network-directives

         Each field must be two bytes. E.g. "1234.5678.90ab" or "AABB.CCDD.EEFF".

         .. versionadded:: 250

   .. systemd:option:: IPv4 address format
      :group: network-directives

         E.g. "127.0.0.1" or "192.168.0.1".

         .. versionadded:: 250

   .. systemd:option:: IPv6 address format
      :group: network-directives

         E.g. "2001:0db8:85a3::8a2e:0370:7334" or "::1".

         .. versionadded:: 250

   The total length of each MAC address must be 4 (for IPv4 tunnel), 6 (for Ethernet), 16 (for IPv6 tunnel), or 20 (for InfiniBand). This option may appear more than once, in which case the lists are merged. If the empty string is assigned to this option, the list of hardware addresses defined prior to this is reset. Defaults to unset.

   .. versionadded:: 211

If the empty string is assigned to this option, the list of hardware addresses defined prior to this is reset. Defaults to unset.

.. inclusion-marker-do-not-remove property|

.. systemd:option:: Property=
   :group: network-directives

   A whitespace-separated list of udev property names with their values after equals sign ("="). If multiple properties are specified, the test results are ANDed. If the list is prefixed with a "!", the test is inverted. If a value contains white spaces, then please quote whole key and value pair. If a value contains quotation, then please escape the quotation with "\\".

   Example: if a .link file has the following:

     .. code-block:: sh

        Property=ID_MODEL_ID=9999 "ID_VENDOR_FROM_DATABASE=vendor name" "KEY=with \"quotation\""

   then, the .link file matches only when an interface has all the above three properties.

[Link] Section Options
######################

The \[Link] section accepts the following keys:

.. systemd:option:: Description=
   :group: network-directives

   A description of the device.

   .. versionadded:: 211

.. systemd:option:: Property=
   :group: network-directives

   Set specified udev properties. This takes space separated list of key-value pairs concatenated with equal sign ("="). Example:

     .. code-block:: sh

        Property=HOGE=foo BAR=baz

   This option supports simple specifier expansion, see the Specifiers section below. This option can be specified multiple times. If an empty string is assigned, then the all previous assignments are cleared.

   This setting is useful to configure the "ID_NET_MANAGED_BY=" property which declares which network management service shall manage the interface, which is respected by :ref:`systemd-networkd(8)` and others. Use

     .. code-block:: sh

        Property=ID_NET_MANAGED_BY=io.systemd.Network

   to declare explicitly that :code:`systemd-networkd` shall manage the interface, or set the property to something else to declare explicitly it shall not do so. See :ref:`systemd.network(5)` for details how this property is used to match interface names.

   .. versionadded:: 256

.. systemd:option:: ImportProperty=
   :group: network-directives

   Import specified udev properties from the saved database. This takes space separated list of property names. Example:

     .. code-block:: sh

        ImportProperty=HOGE BAR

   This option supports simple specifier expansion, see the Specifiers section below. This option can be specified multiple times. If an empty string is assigned, then the all previous assignments are cleared.

   If the same property is also set in :systemd:var:`Property=` in the above, then the imported property value will be overridden by the value specified in :systemd:var:`Property=`.

   .. versionadded:: 256

.. systemd:option:: UnsetProperty=
   :group: network-directives

   Unset specified udev properties. This takes space separated list of property names. Example:

     .. code-block:: sh

        UnsetProperty=HOGE BAR

   This option supports simple specifier expansion, see the Specifiers section below. This option can be specified multiple times. If an empty string is assigned, then the all previous assignments are cleared.

   This setting is applied after :systemd:var:`ImportProperty=` and :systemd:var:`Property=` are applied. Hence, if the same property is specified in :systemd:var:`ImportProperty=` or :systemd:var:`Property=`, then the imported or specified property value will be ignored, and the property will be unset.

   .. versionadded:: 256

.. systemd:option:: Alias=
   :group: network-directives

   The :systemd:var:`ifalias` interface property is set to this value.

   .. versionadded:: 211

.. systemd:option:: MACAddressPolicy=
   :group: network-directives

   The policy by which the MAC address should be set. The available policies are:

   .. systemd:option:: persistent
      :group: network-directives

         If the hardware has a persistent MAC address, as most hardware should, and if it is used by the kernel, nothing is done. Otherwise, a new MAC address is generated which is guaranteed to be the same on every boot for the given machine and the given device, but which is otherwise random. This feature depends on ID_NET_NAME_* properties to exist for the link. On hardware where these properties are not set, the generation of a persistent MAC address will fail.

         .. versionadded:: 211

   .. systemd:option:: random
      :group: network-directives

         If the kernel is using a random MAC address, nothing is done. Otherwise, a new address is randomly generated each time the device appears, typically at boot. Either way, the random address will have the "unicast" and "locally administered" bits set.

         .. versionadded:: 211

   .. systemd:option:: none
      :group: network-directives

         Keeps the MAC address assigned by the kernel. Or use the MAC address specified in :systemd:var:`MACAddress=`.

         .. versionadded:: 227

   An empty string assignment is equivalent to setting "none".

   .. versionadded:: 211

.. systemd:option:: MACAddress=
   :group: network-directives

   The interface MAC address to use. For this setting to take effect, :systemd:var:`MACAddressPolicy=` must either be unset, empty, or "none".

   .. versionadded:: 211

.. systemd:option:: NamePolicy=
   :group: network-directives

   An ordered, space-separated list of policies by which the interface name should be set. :systemd:var:`NamePolicy=` may be disabled by specifying :systemd:option:`net.ifnames=0` on the kernel command line. Each of the policies may fail, and the first successful one is used. The name is not set directly, but is exported to udev as the property :systemd:option:`ID_NET_NAME`, which is, by default, used by a :man-pages:`udev(7)`, rule to set :systemd:var:`NAME`. The available policies are:

   .. systemd:option:: kernel
      :group: network-directives

         If the kernel claims that the name it has set for a device is predictable, then no renaming is performed.

         .. versionadded:: 216

   .. systemd:option:: database
      :group: network-directives

         The name is set based on entries in the udev's Hardware Database with the key :systemd:var:`ID_NET_NAME_FROM_DATABASE`.

         .. versionadded:: 211

   .. systemd:option:: onboard
      :group: network-directives

         The name is set based on information given by the firmware for on-board devices, as exported by the udev property :systemd:var:`ID_NET_NAME_ONBOARD`. See :ref:`systemd.net-naming-scheme(7)`.

         .. versionadded:: 211

   .. systemd:option:: slot
      :group: network-directives

         The name is set based on information given by the firmware for hot-plug devices, as exported by the udev property :systemd:var:`ID_NET_NAME_SLOT`. See :ref:`systemd.net-naming-scheme(7)`.

         .. versionadded:: 211

   .. systemd:option:: path
      :group: network-directives

         The name is set based on the device's physical location, as exported by the udev property :systemd:var:`ID_NET_NAME_PATH`. See :ref:`systemd.net-naming-scheme(7)`.

         .. versionadded:: 211

   .. systemd:option:: mac
      :group: network-directives

         The name is set based on the device's persistent MAC address, as exported by the udev property :systemd:var:`ID_NET_NAME_MAC`. See :ref:`systemd.net-naming-scheme(7)`.

         .. versionadded:: 211

   .. systemd:option:: keep
      :group: network-directives

         If the device already had a name given by userspace (as part of creation of the device or a rename), keep it.

         .. versionadded:: 241

   .. versionadded:: 211

.. systemd:option:: Name=
   :group: network-directives

   The interface name to use. This option has lower precedence than :systemd:var:`NamePolicy=`, so for this setting to take effect, :systemd:var:`NamePolicy=` must either be unset, empty, disabled, or all policies configured there must fail. Also see the example below with "Name=dmz0".

   Note that specifying a name that the kernel might use for another interface (for example "eth0") is dangerous because the name assignment done by udev will race with the assignment done by the kernel, and only one interface may use the name. Depending on the order of operations, either udev or the kernel will win, making the naming unpredictable. It is best to use some different prefix, for example "internal0"/"external0" or "lan0"/"lan1"/"lan3".

   Interface names must have a minimum length of 1 character and a maximum length of 15 characters, and may contain any 7bit ASCII character, with the exception of control characters, ":", "/" and "%". While "." is an allowed character, it is recommended to avoid it when naming interfaces as various tools (such as :man-pages:`resolvconf(1)`) use it as separator character. Also, fully numeric interface names are not allowed (in order to avoid ambiguity with interface specification by numeric indexes), nor are the special strings ".", "..", "all" and "default".

   .. versionadded:: 211

.. systemd:option:: AlternativeNamesPolicy=
   :group: network-directives

   A space-separated list of policies by which the interface's alternative names should be set. Each of the policies may fail, and all successful policies are used. The available policies are "database", "onboard", "slot", "path", and "mac". If the kernel does not support the alternative names, then this setting will be ignored.

   .. versionadded:: 245

.. systemd:option:: AlternativeName=
   :group: network-directives

   The alternative interface name to use. This option can be specified multiple times. If the empty string is assigned to this option, the list is reset, and all prior assignments have no effect. If the kernel does not support the alternative names, then this setting will be ignored.

   Alternative interface names may be used to identify interfaces in various tools. In contrast to the primary name (as configured with :systemd:var:`Name=` above) there may be multiple alternative names referring to the same interface. Alternative names may have a maximum length of 127 characters, in contrast to the 15 allowed for the primary interface name, but otherwise are subject to the same naming constraints.

   .. versionadded:: 245

.. systemd:option:: TransmitQueues=
   :group: network-directives

   Specifies the device's number of transmit queues. An integer in the range 1…4096. When unset, the kernel's default will be used.

   .. versionadded:: 248

.. systemd:option:: ReceiveQueues=
   :group: network-directives

   Specifies the device's number of receive queues. An integer in the range 1…4096. When unset, the kernel's default will be used.

   .. versionadded:: 248

.. systemd:option:: TransmitQueueLength=
   :group: network-directives

   Specifies the transmit queue length of the device in number of packets. An unsigned integer in the range 0…4294967294. When unset, the kernel's default will be used.

   .. versionadded:: 248

.. systemd:option:: MTUBytes=
   :group: network-directives

   The maximum transmission unit in bytes to set for the device. The usual suffixes K, M, G are supported and are understood to the base of 1024.

   .. versionadded:: 211

.. systemd:option:: BitsPerSecond=
   :group: network-directives

   The speed to set for the device, the value is rounded down to the nearest Mbps. The usual suffixes K, M, G are supported and are understood to the base of 1000.

   .. versionadded:: 211

.. systemd:option:: Duplex=
   :group: network-directives

   The duplex mode to set for the device. The accepted values are :systemd:option:`half` and :systemd:option:`full`.

   .. versionadded:: 211

.. systemd:option:: AutoNegotiation=
   :group: network-directives

   Takes a boolean. If set to yes, automatic negotiation of transmission parameters is enabled. Autonegotiation is a procedure by which two connected ethernet devices choose common transmission parameters, such as speed, duplex mode, and flow control. When unset, the kernel's default will be used.

   Note that if autonegotiation is enabled, speed and duplex settings are read-only. If autonegotiation is disabled, speed and duplex settings are writable if the driver supports multiple link modes.

   .. versionadded:: 233

.. systemd:option:: WakeOnLan=
   :group: network-directives

   The Wake-on-LAN policy to set for the device. Takes the special value "off" which disables Wake-on-LAN, or space separated list of the following words:

   .. systemd:option:: phy
      :group: network-directives

         Wake on PHY activity.

         .. versionadded:: 211

   .. systemd:option:: unicast
      :group: network-directives

         Wake on unicast messages.

         .. versionadded:: 235

   .. systemd:option:: multicast
      :group: network-directives

         Wake on multicast messages.

         .. versionadded:: 235

   .. systemd:option:: broadcast
      :group: network-directives

         Wake on broadcast messages.

         .. versionadded:: 235

   .. systemd:option:: arp
      :group: network-directives

         Wake on ARP.

         .. versionadded:: 235

   .. systemd:option:: magic
      :group: network-directives

         Wake on receipt of a magic packet.

         .. versionadded:: 211

   .. systemd:option:: secureon
      :group: network-directives

         Enable SecureOn password for MagicPacket. Implied when :systemd:var:`WakeOnLanPassword=` is specified. If specified without :systemd:var:`WakeOnLanPassword=` option, then the password is read from the credential ":emphasis:`LINK`.link.wol.password" (e.g., "60-foo.link.wol.password"), and if the credential not found, then read from "wol.password". See :systemd:var:`ImportCredential=`/:systemd:var:`LoadCredential=`/:systemd:var:`SetCredential=` in :ref:`systemd.exec(5)` for details. The password in the credential, must be 6 bytes in hex format with each byte separated by a colon (":") like an Ethernet MAC address, e.g., "aa:bb:cc:dd:ee:ff".

         .. versionadded:: 235

   Defaults to unset, and the device's default will be used. This setting can be specified multiple times. If an empty string is assigned, then the all previous assignments are cleared.

   .. versionadded:: 211

.. systemd:option:: WakeOnLanPassword=
   :group: network-directives

   Specifies the SecureOn password for MagicPacket. Takes an absolute path to a regular file or an :systemd:constant:`AF_UNIX` stream socket, or the plain password. When a path to a regular file is specified, the password is read from it. When an :systemd:constant:`AF_UNIX` stream socket is specified, a connection is made to it and the password is read from it. The password must be 6 bytes in hex format with each byte separated by a colon (":") like an Ethernet MAC address, e.g., "aa:bb:cc:dd:ee:ff". This implies :systemd:var:`WakeOnLan=secureon`. Defaults to unset, and the current value will not be changed.

   .. versionadded:: 250

.. systemd:option:: Port=
   :group: network-directives

   The port option is used to select the device port. The supported values are:

   .. systemd:option:: tp
      :group: network-directives

         An Ethernet interface using Twisted-Pair cable as the medium.

         .. versionadded:: 234

   .. systemd:option:: aui
      :group: network-directives

         Attachment Unit Interface (AUI). Normally used with hubs.

         .. versionadded:: 234

   .. systemd:option:: bnc
      :group: network-directives

         An Ethernet interface using BNC connectors and co-axial cable.

         .. versionadded:: 234

   .. systemd:option:: mii
      :group: network-directives

         An Ethernet interface using a Media Independent Interface (MII).

         .. versionadded:: 234

   .. systemd:option:: fibre
      :group: network-directives

         An Ethernet interface using Optical Fibre as the medium.

         .. versionadded:: 234

   .. versionadded:: 234

.. systemd:option:: Advertise=
   :group: network-directives

   This sets what speeds and duplex modes of operation are advertised for auto-negotiation. This implies "AutoNegotiation=yes". The supported values are: .. list-table:: Supported advertise values
      :header-rows: 1

      * - Advertise
        - Speed (Mbps)
        - Duplex Mode

   By default, this is unset, i.e. all possible modes will be advertised. This option may be specified more than once, in which case all specified speeds and modes are advertised. If the empty string is assigned to this option, the list is reset, and all prior assignments have no effect.

   .. versionadded:: 240

.. systemd:option:: ReceiveChecksumOffload=
   :group: network-directives

   Takes a boolean. If set to true, hardware offload for checksumming of ingress network packets is enabled. When unset, the kernel's default will be used.

   .. versionadded:: 245

.. systemd:option:: TransmitChecksumOffload=
   :group: network-directives

[SR-IOV] Section Options
########################

SR-IOV provides the ability to partition a single physical PCI resource into virtual PCI functions which can then be e.g. injected into a VM. In the case of network VFs, SR-IOV reduces latency and CPU utilisation for north-south network traffic (that is, traffic with endpoints outside the host machine), by allowing traffic to bypass the host machine’s network stack.

The presence of an \[SR-IOV] section in a .link file will cause the creation and configuration of the specified virtual function. Within a .network file, the specified virtual function will be configured, but must already exist. Specify several \[SR-IOV] sections to configure several SR-IOVs.

The \[SR-IOV] section accepts the following keys.

.. systemd:option:: VirtualFunction=
   :group: network-directives

   Specifies a Virtual Function (VF), lightweight PCIe function designed solely to move data in and out. Takes an integer in the range 0…2147483646. This option is compulsory.

   .. versionadded:: 251

.. systemd:option:: VLANId=
   :group: network-directives

   Specifies VLAN ID of the virtual function. Takes an integer in the range 1…4095.

   .. versionadded:: 251

.. systemd:option:: QualityOfService=
   :group: network-directives

   Specifies quality of service of the virtual function. Takes an integer in the range 1…4294967294.

   .. versionadded:: 251

.. systemd:option:: VLANProtocol=
   :group: network-directives

   Specifies VLAN protocol of the virtual function. Takes "802.1Q" or "802.1ad".

   .. versionadded:: 251

.. systemd:option:: MACSpoofCheck=
   :group: network-directives

   Takes a boolean. Controls the MAC spoof checking. When unset, the kernel's default will be used.

   .. versionadded:: 251

.. systemd:option:: QueryReceiveSideScaling=
   :group: network-directives

   Takes a boolean. Toggle the ability of querying the receive side scaling (RSS) configuration of the virtual function (VF). The VF RSS information like RSS hash key may be considered sensitive on some devices where this information is shared between VF and the physical function (PF). When unset, the kernel's default will be used.

   .. versionadded:: 251

.. systemd:option:: Trust=
   :group: network-directives

   Takes a boolean. Allows one to set trust mode of the virtual function (VF). When set, VF users can set a specific feature which may impact security and/or performance. When unset, the kernel's default will be used.

   .. versionadded:: 251

.. systemd:option:: LinkState=
   :group: network-directives

   Allows one to set the link state of the virtual function (VF). Takes a boolean or a special value "auto". Setting to "auto" means a reflection of the physical function (PF) link state, "yes" lets the VF to communicate with other VFs on this host even if the PF link state is down, "no" causes the hardware to drop any packets sent by the VF. When unset, the kernel's default will be used.

   .. versionadded:: 251

.. systemd:option:: MACAddress=
   :group: network-directives

   Specifies the MAC address for the virtual function.

   .. versionadded:: 251

.. inclusion-end-marker-do-not-remove sr-iov|

[EnergyEfficientEthernet] Section Options
#########################################

The \[EnergyEfficientEthernet] section controls the Energy Efficient Ethernet (EEE) feature of the interface, and accepts the following keys.

.. systemd:option:: Enable=
   :group: network-directives

   Takes a boolean argument. When true, the Energy Efficient Ethernet (EEE) feature will be enabled on the interface. Defaults to unset, and the enablement of EEE will be unchanged.

   .. versionadded:: 258

.. systemd:option:: TxLowPowerIdle=
   :group: network-directives

   Takes a boolean argument. When true, the transmit Low Power Idle (Tx-LPI) mode of the Energy Efficient Ethernet feature will be enabled on the interface. Defaults to unset, and the enablement of the mode will be unchanged.

   .. versionadded:: 258

.. systemd:option:: TxLowPowerIdleSec=
   :group: network-directives

   Takes a timespan. This configures how long the interface should not enter the Low Power Idle mode after transmission. If it is too short, may decrease performance. If it is too long, may not gain energy saving. Defaults to unset, and the timespan will be unchanged.

   .. versionadded:: 258

.. systemd:option:: LinkMode=
   :group: network-directives

   Takes a list of link modes, e.g. "1000baset-full". See the table for :systemd:var:`Advertise=` setting in \[Link] section in the above for possible values. This configures the Energy Efficient Ethernet capable connection modes to be advertised. Defaults to unset, and the advertised modes will be unchanged.

   .. versionadded:: 258

Examples
########

/usr/lib/systemd/network/99-default.link
----------------------------------------

The link file :code:`99-default.link` that is shipped with systemd defines the default policies for the interface name, alternative names, and MAC address of links.

.. code-block:: sh

   [Match]
   OriginalName=*
   [Link]
   NamePolicy=keep kernel database onboard slot path
   AlternativeNamesPolicy=database onboard slot path
   MACAddressPolicy=persistent

/etc/systemd/network/10-dmz.link
--------------------------------

This example assigns the fixed name "dmz0" to the interface with the MAC address 00:a0:de:63:7a:e6:

.. code-block:: sh

   [Match]
   MACAddress=00:a0:de:63:7a:e6
   [Link]
   Name=dmz0

:code:`NamePolicy=` is not set, so :code:`Name=` takes effect. We use the "10-" prefix to order this file early in the list. Note that it needs to be before :code:`99-default.link`, i.e. it needs a numerical prefix, to have any effect at all.

(Re-)applying a .link file to an interface
------------------------------------------

After a new .link file has been created, or an existing .link file modified, the new settings may be applied to the matching interface with the following commands:

.. code-block:: sh

   $ sudo udevadm control --reload
   $ sudo ip link set eth0 down
   $ sudo udevadm trigger --verbose --settle --action add /sys/class/net/eth0

You may also need to stop the service that manages the network interface, e.g. :ref:`systemd-networkd.service(8)` or :code:`NetworkManager.service` before the above operation, and then restart the service after that. For more details about :code:`udevadm` command, see :man-pages:`udevadm(8)`.

Debugging :code:`NamePolicy=` assignments
-----------------------------------------

.. code-block:: sh

   $ sudo SYSTEMD_LOG_LEVEL=debug udevadm test-builtin net_setup_link /sys/class/net/hub0
   …
   Parsed configuration file /usr/lib/systemd/network/99-default.link
   Parsed configuration file /etc/systemd/network/10-eth0.link
   ID_NET_DRIVER=cdc_ether
   Config file /etc/systemd/network/10-eth0.link applies to device hub0
   link_config: autonegotiation is unset or enabled, the speed and duplex are not writable.
   hub0: Device has name_assign_type=4
   Using default interface naming scheme 'v240'.
   hub0: Policies did not yield a name, using specified Name=hub0.
   ID_NET_LINK_FILE=/etc/systemd/network/10-eth0.link
   ID_NET_NAME=hub0
   …

Explicit :code:`Name=` configuration wins in this case.

.. code-block:: sh

   sudo SYSTEMD_LOG_LEVEL=debug udevadm test-builtin net_setup_link /sys/class/net/enp0s31f6
   …
   Parsed configuration file /usr/lib/systemd/network/99-default.link
   Parsed configuration file /etc/systemd/network/10-eth0.link
   Created link configuration context.
   ID_NET_DRIVER=e1000e
   Config file /usr/lib/systemd/network/99-default.link applies to device enp0s31f6
   link_config: autonegotiation is unset or enabled, the speed and duplex are not writable.
   enp0s31f6: Device has name_assign_type=4
   Using default interface naming scheme 'v240'.
   enp0s31f6: Policy *keep*: keeping existing userspace name
   enp0s31f6: Device has addr_assign_type=0
   enp0s31f6: MAC on the device already matches policy *persistent*
   ID_NET_LINK_FILE=/usr/lib/systemd/network/99-default.link
   …

In this case, the interface was already renamed, so the :code:`keep` policy specified as the first option in :code:`99-default.link` means that the existing name is preserved. If :code:`keep` was removed, or if were in boot before the renaming has happened, we might get the following instead:

.. code-block:: sh

   enp0s31f6: Policy *path* yields "enp0s31f6".
   enp0s31f6: Device has addr_assign_type=0
   enp0s31f6: MAC on the device already matches policy *persistent*
   ID_NET_LINK_FILE=/usr/lib/systemd/network/99-default.link
   ID_NET_NAME=enp0s31f6
   …

Please note that the details of output are subject to change.

/etc/systemd/network/10-internet.link
-------------------------------------

This example assigns the fixed name "internet0" to the interface with the device path "pci-0000:00:1a.0-*":

.. code-block:: sh

   [Match]
   Path=pci-0000:00:1a.0-*
   [Link]
   Name=internet0
