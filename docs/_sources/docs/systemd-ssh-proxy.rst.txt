====================
systemd-ssh-proxy(1)
====================

Name
####

systemd-ssh-proxy — SSH client plugin for connecting to

Synopsis
########

.. code-block:: sh

   Host unix/* unix%* vsock/* vsock%* vsock-mux/* vsock-mux%*
       ProxyCommand /usr/lib/systemd/systemd-ssh-proxy %h %p
       ProxyUseFdpass yes

:code:`/usr/lib/systemd/systemd-ssh-proxy [ADDRESS] [PORT]`

Description
###########

:code:`systemd-ssh-proxy` is a small "proxy" plugin for the :man-pages:`ssh(1)` tool that allows connecting to :code:`AF_UNIX` and :code:`AF_VSOCK` sockets. It implements the interface defined by :code:`ssh`'s :code:`ProxyCommand` configuration option. It's supposed to be used with an :man-pages:`ssh_config(5)` configuration fragment like the following:

.. code-block:: sh

   Host unix/* unix%* vsock/* vsock%* vsock-mux/* vsock-mux%*
       ProxyCommand /usr/lib/systemd/systemd-ssh-proxy %h %p
       ProxyUseFdpass yes
       CheckHostIP no
   Host .host
       ProxyCommand /usr/lib/systemd/systemd-ssh-proxy unix/run/ssh-unix-local/socket %p
       ProxyUseFdpass yes
       CheckHostIP no

A configuration fragment along these lines is by default installed into :code:`/etc/ssh/ssh_config.d/20-systemd-ssh-proxy.conf`.

With this in place, SSH connections to host string "unix/" followed by an absolute :code:`AF_UNIX` file system path to a socket will be directed to the specified socket, which must be of type :code:`SOCK_STREAM`. Similar, SSH connections to "vsock/" followed by an :code:`AF_VSOCK` CID will result in an SSH connection made to that CID. "vsock-mux/" followed by an absolute :code:`AF_UNIX` file system path to a socket is similar but for cloud-hypervisor/firecracker which do not allow direct :code:`AF_VSOCK` communication between the host and guests, and provide their own multiplexer over :code:`AF_UNIX` sockets. See `cloud-hypervisor VSOCK support <https://github.com/cloud-hypervisor/cloud-hypervisor/blob/main/docs/vsock.md>`_ and `Using the Firecracker Virtio-vsock Device <https://github.com/firecracker-microvm/firecracker/blob/main/docs/vsock.md>`_. Note that "%" can be used as a separator instead of "/" to be compatible with tools like "scp" and "rsync".

Moreover, connecting to ".host" will connect to the local host via SSH, without involving networking.

This tool is supposed to be used together with :ref:`systemd-ssh-generator(8)` which when run inside a VM or container will bind SSH to suitable addresses. :code:`systemd-ssh-generator` is supposed to run in the container or VM guest, and :code:`systemd-ssh-proxy` is run on the host, in order to connect to the container or VM guest.

Exit status
###########

On success, 0 is returned, a non-zero failure code otherwise.

Examples
########

Talk to a local VM with CID 4711
--------------------------------

.. code-block:: sh

   ssh vsock/4711

Talk to a VM guest hosted with cloud-hypervisor/firecracker
-----------------------------------------------------------

.. code-block:: sh

   ssh vsock-mux/run/vm-1234.sock

Talk to the local host via ssh
------------------------------

.. code-block:: sh

   ssh .host

or equivalent:

.. code-block:: sh

   ssh unix/run/ssh-unix-local/socket

Copy local 'foo' file to a local VM with CID 1348
-------------------------------------------------

.. code-block:: sh

   scp foo vsock%1348:
