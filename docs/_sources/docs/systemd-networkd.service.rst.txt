===========================
systemd-networkd.service(8)
===========================

Name
####

systemd-networkd.service, systemd-networkd — Network manager

Synopsis
########

:code:`systemd-networkd.service`

:code:`/usr/lib/systemd/systemd-networkd`

Description
###########

:code:`systemd-networkd` is a system service that manages networks. It detects and configures network devices as they appear, as well as creating virtual network devices.

Certain low-level settings of physical network devices (e.g. device names and altnames) as well as the creation of SR-IOV virtual functions on physical network interfaces may be managed by :ref:`systemd-udevd(8)` according to the contents of :ref:`systemd.link(5)` files.

:code:`systemd-networkd` will create "virtual" network devices (e.g. bridges and tunnels) based on the configuration in :ref:`systemd.netdev(5)` files, respecting the \[Match] sections in those files.

:code:`systemd-networkd` will manage network addresses and routes for any link for which it finds a :code:`.network` file with an appropriate \[Match] section, see :ref:`systemd.network(5)`. For those links, it will flush existing network addresses and routes when bringing up the device (except when directed not to). Any links not matched by one of the :code:`.network` files will be ignored. It is also possible to explicitly tell :code:`systemd-networkd` to ignore a link by using the :code:`Unmanaged=yes` option, see :ref:`systemd.network(5)`.

When :code:`systemd-networkd` exits, it generally leaves existing network devices and configuration intact. This makes it possible to transition from the initrd and to restart the service without breaking connectivity. This also means that when configuration is updated and :code:`systemd-networkd` is restarted, netdev interfaces for which configuration was removed will not be dropped, and may need to be cleaned up manually.

:code:`systemd-networkd` may be introspected and controlled at runtime using :man-pages:`networkctl(1)`.

See :man-pages:`org.freedesktop.network1(5)` and :man-pages:`org.freedesktop.LogControl1(5)` for a description of the D-Bus API.

Configuration Files
###################

The configuration files are read from the files located in the system network directory :code:`/usr/lib/systemd/network`, the volatile runtime network directory :code:`/run/systemd/network` and the local administration network directory :code:`/etc/systemd/network`.

Networks are configured in :code:`.network` files, see :ref:`systemd.network(5)`, and virtual network devices are configured in :code:`.netdev` files, see :ref:`systemd.netdev(5)`.
