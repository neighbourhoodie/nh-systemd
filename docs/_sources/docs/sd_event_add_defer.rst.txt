=====================
sd_event_add_defer(3)
=====================

Name
####

sd_event_add_defer, sd_event_add_post, sd_event_add_exit, sd_event_handler_t — Add static event sources to an event loop

Synopsis
########

:code:`#include <systemd/sd-event.h>` :code:`:code:`typedef` struct sd_event_source sd_event_source;` .. code-block::

   typedef int (*sd_event_handler_t)(sd_event_source *s,
	void *userdata); .. code-block::

   int sd_event_add_defer(sd_event *event,
	sd_event_source **source,
	sd_event_handler_t handler,
	void *userdata); .. code-block::

   int sd_event_add_post(sd_event *event,
	sd_event_source **source,
	sd_event_handler_t handler,
	void *userdata); .. code-block::

   int sd_event_add_exit(sd_event *event,
	sd_event_source **source,
	sd_event_handler_t handler,
	void *userdata);

Description
###########

These three functions add new static event sources to an event loop. The event loop object is specified in the :code:`event` parameter, the event source object is returned in the :code:`source` parameter. The event sources are enabled statically and will "fire" when the event loop is run and the conditions described below are met.

The :code:`handler` is a function to call or :code:`NULL`. The handler function will be passed the :code:`userdata` pointer, which may be chosen freely by the caller. The handler may return negative to signal an error (see below), other return values are ignored. If :code:`handler` is :code:`NULL`, a default handler that calls :ref:`sd_event_exit(3)` will be used.

:code:`sd_event_add_defer()` adds a new event source that will be dispatched instantly, before the event loop goes to sleep again and waits for new events. By default, the handler will be called once (:code:`SD_EVENT_ONESHOT`). Note that if the event source is set to :code:`SD_EVENT_ON` the event loop will never go to sleep again, but continuously call the handler, possibly interleaved with other event sources.

:code:`sd_event_add_post()` adds a new event source that is run before the event loop will sleep and wait for new events, but only after at least one other non-post event source was dispatched. By default, the source is enabled permanently (:code:`SD_EVENT_ON`). Note that this event source type will still allow the event loop to go to sleep again, even if set to :code:`SD_EVENT_ON`, as long as no other event source is ever triggered.

:code:`sd_event_add_exit()` adds a new event source that will be dispatched when the event loop is terminated with :ref:`sd_event_exit(3)`.

The :ref:`sd_event_source_set_enabled(3)` function may be used to enable the event source permanently (:code:`SD_EVENT_ON`) or to make it fire just once (:code:`SD_EVENT_ONESHOT`).

If the handler function returns a negative error code, it will either be disabled after the invocation, even if the :code:`SD_EVENT_ON` mode was requested before, or it will cause the loop to terminate, see :ref:`sd_event_source_set_exit_on_failure(3)`.

To destroy an event source object use :ref:`sd_event_source_unref(3)`, but note that the event source is only removed from the event loop when all references to the event source are dropped. To make sure an event source does not fire anymore, even when there's still a reference to it kept, consider setting the event source to :code:`SD_EVENT_OFF` with :ref:`sd_event_source_set_enabled(3)`.

If the second parameter of these functions is passed as :code:`NULL` no reference to the event source object is returned. In this case, the event source is considered "floating", and will be destroyed implicitly when the event loop itself is destroyed.

If the :code:`handler` parameter to :code:`sd_event_add_defer()` or :code:`sd_event_add_post()` is :code:`NULL`, and the event source fires, this will be considered a request to exit the event loop. In this case, the :code:`userdata` parameter, cast to an integer, is passed as the exit code parameter to :ref:`sd_event_exit(3)`. Similar functionality is not available for :code:`sd_event_add_exit()`, as these types of event sources are only dispatched when exiting anyway.

Return Value
############

On success, these functions return 0 or a positive integer. On failure, they return a negative errno-style error code.

Errors
######

Returned errors may indicate the following problems:

.. systemd:option:: -ENOMEM

   Not enough memory to allocate an object.

.. systemd:option:: -EINVAL

   An invalid argument has been passed.

.. systemd:option:: -ESTALE

   The event loop is already terminated.

.. systemd:option:: -ECHILD

   The event loop has been created in a different process, library or module instance.
