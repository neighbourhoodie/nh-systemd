================
environment.d(5)
================

Name
####

environment.d — Definition of user service environment

Synopsis
########

| :code:`~/.config/environment.d/\*.conf`
| :code:`/etc/environment.d/\*.conf`
| :code:`/run/environment.d/\*.conf`
| :code:`/usr/local/lib/environment.d/\*.conf`
| :code:`/usr/lib/environment.d/\*.conf`
| :code:`/etc/environment`

Description
###########

Configuration files in the :code:`environment.d/` directories contain lists of environment variable assignments passed to services started by the systemd user instance. :ref:`systemd-environment-d-generator(8)` parses them and updates the environment exported by the systemd user instance. See below for an discussion of which processes inherit those variables.

It is recommended to use numerical prefixes for file names to simplify ordering.

For backwards compatibility, a symlink to :code:`/etc/environment` is installed, so this file is also parsed.

%% include="standard-conf.rst" id="confd|" %%

Configuration Format
####################

The configuration files contain a list of ":emphasis:`KEY`\=:emphasis:`VALUE`" environment variable assignments, separated by newlines. The right hand side of these assignments may reference previously defined environment variables, using the "${OTHER_KEY}" and "$OTHER_KEY" format. It is also possible to use "${:emphasis:`FOO`:-:emphasis:`DEFAULT_VALUE`}" to expand in the same way as "${:emphasis:`FOO`}" unless the expansion would be empty, in which case it expands to :emphasis:`DEFAULT_VALUE`, and use "${:emphasis:`FOO`:+:emphasis:`ALTERNATE_VALUE`}" to expand to :emphasis:`ALTERNATE_VALUE` as long as "${:emphasis:`FOO`}" would have expanded to a non-empty value. No other elements of shell syntax are supported.

Each :emphasis:`KEY` must be a valid variable name. Empty lines and lines beginning with the comment character "#" are ignored.

Example
#######

Setup environment to allow access to a program installed in :code:`/opt/foo`
----------------------------------------------------------------------------

:code:`/etc/environment.d/60-foo.conf`:

.. code-block:: sh

           FOO_DEBUG=force-software-gl,log-verbose
           PATH=/opt/foo/bin:$PATH
           LD_LIBRARY_PATH=/opt/foo/lib${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH}
           XDG_DATA_DIRS=/opt/foo/share:${XDG_DATA_DIRS:-/usr/local/share/:/usr/share/}

Applicability
#############

Environment variables exported by the user service manager (:code:`systemd --user` instance started in the :code:`user@uid.service` system service) are passed to any services started by that service manager. In particular, this may include services which run user shells. For example in the GNOME environment, the graphical terminal emulator runs as the :code:`gnome-terminal-server.service` user unit, which in turn runs the user shell, so that shell will inherit environment variables exported by the user manager. For other instances of the shell, not launched by the user service manager, the environment they inherit is defined by the program that starts them. Hint: in general, :ref:`systemd.service(5)` units contain programs launched by systemd, and :ref:`systemd.scope(5)` units contain programs launched by something else.

Note that these files do not affect the environment block of the service manager itself, but exclusively the environment blocks passed to the services it manages. Environment variables set that way thus cannot be used to influence behaviour of the service manager. In order to make changes to the service manager's environment block the environment must be modified before the user's service manager is invoked, for example from the system service manager or via a PAM module.

Specifically, for ssh logins, the :man-pages:`sshd(8)` service builds an environment that is a combination of variables forwarded from the remote system and defined by :code:`sshd`, see the discussion in :man-pages:`ssh(1)`. A graphical display session will have an analogous mechanism to define the environment. Note that some managers query the systemd user instance for the exported environment and inject this configuration into programs they start, using :code:`systemctl show-environment` or the underlying D-Bus call.
