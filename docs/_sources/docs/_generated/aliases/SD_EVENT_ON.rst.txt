sd_event_source_set_enabled(3)
==============================

Name
####

sd_event_source_set_enabled, sd_event_source_get_enabled, SD_EVENT_ON, SD_EVENT_OFF, SD_EVENT_ONESHOT — Enable or disable event sources

Synopsis
########

:code:`#include <systemd/sd-event.h>` :code:`:code:`enum` { :code:`SD_EVENT_OFF` = 0, :code:`SD_EVENT_ON` = 1, :code:`SD_EVENT_ONESHOT` = -1, };` .. code-block::

   int sd_event_source_set_enabled(sd_event_source *source,
	int enabled); .. code-block::

   int sd_event_source_get_enabled(sd_event_source *source,
	int *ret);

Description
###########

:code:`sd_event_source_set_enabled()` may be used to enable or disable the event source object specified as :code:`source`. The :code:`enabled` parameter takes one of :code:`SD_EVENT_ON` (to enable), :code:`SD_EVENT_OFF` (to disable) or :code:`SD_EVENT_ONESHOT`. If invoked with :code:`SD_EVENT_ONESHOT` the event source will be enabled but automatically reset to :code:`SD_EVENT_OFF` after one dispatch. For :code:`SD_EVENT_OFF`, the event source :code:`source` may be :code:`NULL`, in which case the function does nothing. Otherwise, :code:`source` must be a valid pointer to an sd_event_source object.

Event sources that are disabled will not result in event loop wakeups and will not be dispatched, until they are enabled again.

:code:`sd_event_source_get_enabled()` may be used to query whether the event source object :code:`source` is currently enabled or not. If both the :code:`source` and the output parameter :code:`ret` are :code:`NULL`, this function returns false. Otherwise, :code:`source` must be a valid pointer to an sd_event_source object. If the output parameter :code:`ret` is not :code:`NULL`, it is set to the enablement state (one of :code:`SD_EVENT_ON`, :code:`SD_EVENT_OFF`, :code:`SD_EVENT_ONESHOT`). The function also returns true if the event source is not disabled.

Event source objects are enabled when they are first created with calls such as :man-pages:`sd_event_add_io(3)`, :man-pages:`sd_event_add_time(3)`. However, depending on the event source type they are enabled continuously (:code:`SD_EVENT_ON`) or only for a single invocation of the event source handler (:code:`SD_EVENT_ONESHOT`). For details see the respective manual pages.

As event source objects stay active and may be dispatched as long as there is at least one reference to them, in many cases it is a good idea to combine a call to :man-pages:`sd_event_source_unref(3)` with a prior call to :code:`sd_event_source_set_enabled()` with :code:`SD_EVENT_OFF`, to ensure the event source is not dispatched again until all other remaining references are dropped.

Return Value
############

On success, :code:`sd_event_source_set_enabled()` returns a non-negative integer. :code:`sd_event_source_get_enabled()` returns zero if the source is disabled (:code:`SD_EVENT_OFF`) and a positive integer otherwise. On failure, they return a negative errno-style error code.

Errors
######

Returned errors may indicate the following problems:

.. systemd:option:: -EINVAL

   :code:`source` is not a valid pointer to an sd_event_source object.

.. systemd:option:: -ENOMEM

   Not enough memory.

.. systemd:option:: -ECHILD

   The event loop has been created in a different process, library or module instance.
