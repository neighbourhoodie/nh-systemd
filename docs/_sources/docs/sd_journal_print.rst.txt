Description
###########

:code:`sd_journal_print()` may be used to submit simple, plain text log entries to the system journal. The first argument is a priority value. This is followed by a format string and its parameters, similar to :man-pages:`printf(3)` or :man-pages:`syslog(3)`. Note that currently the resulting message will be truncated to :code:`LINE_MAX - 8`. The priority value is one of :code:`LOG_EMERG`, :code:`LOG_ALERT`, :code:`LOG_CRIT`, :code:`LOG_ERR`, :code:`LOG_WARNING`, :code:`LOG_NOTICE`, :code:`LOG_INFO`, :code:`LOG_DEBUG`, as defined in :code:`syslog.h`, see :man-pages:`syslog(3)` for details. It is recommended to use this call to submit log messages in the application locale or system locale and in UTF-8 format, but no such restrictions are enforced. Note that log messages written using this function are generally not expected to end in a new-line character. However, as all trailing whitespace (including spaces, new-lines, tabulators and carriage returns) are automatically stripped from the logged string, it is acceptable to specify one (or more). Empty lines (after trailing whitespace removal) are suppressed. On non-empty lines, leading whitespace (as well as inner whitespace) is left unmodified.

:code:`sd_journal_printv()` is similar to :code:`sd_journal_print()` but takes a variable argument list encapsulated in an object of type :code:`va_list` (see :man-pages:`stdarg(3)` for more information) instead of the format string. It is otherwise equivalent in behavior.

:code:`sd_journal_send()` may be used to submit structured log entries to the system journal. It takes a series of format strings, each immediately followed by their associated parameters, terminated by :code:`NULL`. The strings passed should be of the format "VARIABLE=value". The variable name must be in uppercase and consist only of characters, numbers and underscores, and may not begin with an underscore. (All assignments that do not follow this syntax will be ignored.) The value can be of any size and format. It is highly recommended to submit text strings formatted in the UTF-8 character encoding only, and submit binary fields only when formatting in UTF-8 strings is not sensible. A number of well-known fields are defined, see :ref:`systemd.journal-fields(7)` for details, but additional application defined fields may be used. A variable may be assigned more than one value per entry. If this function is used, trailing whitespace is automatically removed from each formatted field.

:code:`sd_journal_sendv()` is similar to :code:`sd_journal_send()` but takes an array of :code:`struct iovec` (as defined in :code:`uio.h`, see :man-pages:`readv(3)` for details) instead of the format string. Each structure should reference one field of the entry to submit. The second argument specifies the number of structures in the array. :code:`sd_journal_sendv()` is particularly useful to submit binary objects to the journal where that is necessary. Note that this function will not strip trailing whitespace of the passed fields, but passes the specified data along unmodified. This is different from both :code:`sd_journal_print()` and :code:`sd_journal_send()` described above, which are based on format strings, and do strip trailing whitespace.

:code:`sd_journal_perror()` is a similar to :die-net:`perror(3)` and writes a message to the journal that consists of the passed string, suffixed with ": " and a human-readable representation of the current error code stored in :man-pages:`errno(3)`. If the message string is passed as :code:`NULL` or empty string, only the error string representation will be written, prefixed with nothing. An additional journal field ERRNO= is included in the entry containing the numeric error code formatted as decimal string. The log priority used is :code:`LOG_ERR` (3).

Note that :code:`sd_journal_send()` is a wrapper around :code:`sd_journal_sendv()` to make it easier to use when only text strings shall be submitted. Also, the following two calls are mostly equivalent:

.. code-block:: sh

   sd_journal_print(LOG_INFO, "Hello World, this is PID %lu!", (unsigned long) getpid());
   sd_journal_send("MESSAGE=Hello World, this is PID %lu!", (unsigned long) getpid(),
                   "PRIORITY=%i", LOG_INFO,
                   NULL);

Note that these calls implicitly add fields for the source file, function name and code line where invoked. This is implemented with macros. If this is not desired, it can be turned off by defining :code:`SD_JOURNAL_SUPPRESS_LOCATION` before including :code:`sd-journal.h`.

:code:`sd_journal_print_with_location()`, :code:`sd_journal_printv_with_location()`, :code:`sd_journal_send_with_location()`, :code:`sd_journal_sendv_with_location()`, and :code:`sd_journal_perror_with_location()` are similar to their counterparts without "_with_location", but accept additional parameters to explicitly set the source file name, function, and line. The arguments "file" and "line" must contain valid journal entries including the variable name, e.g. "CODE_FILE=src/foo.c" and "CODE_LINE=666", while "func" must only contain the function name, i.e. the value without "CODE_FUNC=". These variants are primarily useful when writing custom wrappers, for example in bindings for a different language.

:man-pages:`syslog(3)` and :code:`sd_journal_print()` may largely be used interchangeably functionality-wise. However, note that log messages logged via the former take a different path to the journal server than the later, and hence global chronological ordering between the two streams cannot be guaranteed. Using :code:`sd_journal_print()` has the benefit of logging source code line, filenames, and functions as metadata along all entries, and guaranteeing chronological ordering with structured log entries that are generated via :code:`sd_journal_send()`. Using :code:`syslog()` has the benefit of being more portable.

These functions implement a client to the `Native Journal Protocol <https://systemd.io/JOURNAL_NATIVE_PROTOCOL>`_.

Return Value
############

The ten functions return 0 on success or a negative errno-style error code. The :man-pages:`errno(3)` variable itself is not altered.

If :ref:`systemd-journald(8)` is not running (the socket is not present), those functions do nothing, and also return 0.

Thread safety
#############

.. include:: threads-aware.rst
    :start-after: .. inclusion-marker-do-not-remove safe|
    :end-before: .. inclusion-end-marker-do-not-remove safe|

:code:`sd_journal_sendv()` and :code:`sd_journal_sendv_with_location()` are "async signal safe" in the meaning of :man-pages:`signal-safety(7)`.

:code:`sd_journal_print()`, :code:`sd_journal_printv()`, :code:`sd_journal_send()`, :code:`sd_journal_perror()`, and their counterparts with "_with_location" are not async signal safe.
